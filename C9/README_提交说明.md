## 1. 一句话

> 把「买了什么、放在哪、还能放几天」变成一句人话就能问出来的答案——**用一句话存进去，用一句模糊的话问出来，快浪费时提前说一句**。

打开就能看到的东西：今天该先吃哪三样、忘了名字也能搜到、现在能做什么菜、以及一个诚实的浪费账本。

## 4. 这个项目和其他「冰箱 App」不一样的地方

1. **不要求你全量建档。** 19 种常备品只记水位，不记到期日。理由是竞品用户的真实原话：*"别全录入，只录入最娇气的几样"*。全量建档的系统第二周就变成 fiction。
2. **简报只有一句话。** 逐条推送是被静音最快的方式，所以默认只给「今天先吃：X、Y、Z」。
3. **猜的地方必须可见。** 每次入库都打印：词命中了吗、数量哪来的、位置哪来的、保质期是你说的还是我按常识猜的、置信度多少。猜错了你能当场看见并改。
4. **混乱输入是默认情况，不是异常。** 「一两花椒」不是 12 个、「一碗剩菜」不能掉字、「2盒牛奶和一袋面粉」要拆两条——这些都被写成回归测试。
5. **浪费要记账。** 扔掉时记录「差几天过期」，否则「浪费率」永远只是感觉。

## 5. 已知限制（不藏）

- **没有照片识别。** 这是所有人对这类产品的第一期待；V1 在零依赖 / 零预算约束下没做。W5 计划以小票 OCR + **草稿态人工确认** 的方式有限接入，永不静默写入。
- **词典只有 78 种食材**，覆盖我家常买的，不是全中国家庭。未收录词会记录并标记待确认，不硬猜。
- **保质期是常识区间**，只用于排序提醒，不能用来判断「还能不能吃」。
- **真实用户目前只有我**（符合 W1 预期）。「只有我一个人在用」被写成了 W6 的红色失败信号。
- **GitHub 尚未公开**：本地仓库已就绪（`main` 分支、首次提交 `e4da2c8`、31 个文件、`.gitignore` 已排除数据库与缓存、根目录有陌生人可读的 `README.md`），**只差远程地址**。所以 W1 仍不把它算作已公开渠道。
