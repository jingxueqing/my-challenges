# 家里有什么 · HomePantry

> 把「买了什么、放在哪、还能放几天」变成一句人话就能问出来的答案。
> 零第三方依赖 · 单机 SQLite · 离线可用 · CLI 与网页双入口

一个给中文家庭用的食材记忆体。设计上只赌一件事：**录入成本决定这个工具能不能活过第二周**。
所以它不做「全量建档」，只做三件事——一句话存进去、一句模糊的话问出来、快浪费时提前说一句。

---

## 1. 30 秒跑起来

要求：Python 3.10+（开发环境 3.13.12），**不需要 pip install 任何东西**。

```bash
cd homepantry

# 灌一份 33 条演示数据（全部是自然语言原句，播种本身就是一次端到端自检）
python3 -m pantry.cli seed

# 今天先吃什么（这就是产品的主输出）
python3 -m pantry.cli brief -v

# 打开网页界面（默认 http://127.0.0.1:8765）
python3 -m pantry.cli serve
```

数据库默认落在 `~/.homepantry/pantry.db`，可以用 `--db` 或环境变量 `PANTRY_DB` 换位置：

```bash
PANTRY_DB=/tmp/try.db python3 -m pantry.cli seed
```

## 2. 常用命令

| 命令 | 作用 | 例子 |
|---|---|---|
| `add` | 一句话入库，打印全部解析依据 | `add "2盒牛奶 冷藏 7天"` |
| `ls` | 按「该先吃」排序，不按录入时间 | `ls` |
| `find` | 模糊检索，忘了名字也能找 | `find 白色的粉` / `find nn` / `find 冻的半月形` |
| `brief` | 一句话简报：今天先吃哪几样 | `brief -v` |
| `cook` | 用现有食材推菜谱，标出缺料 | `cook --top 5` |
| `shop` | 购物清单（缺料 + 常备跌破水位） | `shop --sync` |
| `eat` | 用掉，进事件流 | `eat 12 --qty 1` / `eat 12 --all` |
| `trash` | 扔掉，记浪费并记录「差几天过期」 | `trash 12` |
| `stats` | 账本：用过 / 扔掉 / 浪费率 | `stats` |
| `export` | 导出 Markdown 库存表，贴群里 | `export --out 库存.md` |
| `serve` | 启动本地 Web 界面 | `serve --port 8765` |
| `seed` | 重置并灌入演示数据 | `seed` |

全局参数：`--db <path>`、`--no-color`。

### 输入能写成什么样

```text
2盒牛奶 冷藏 7天          → 牛奶 2盒 @冷藏，7 天后到期
半颗白菜                  → 白菜 0.5颗 @冷藏，按常识给 5 天
一碗剩菜 冷藏 2天          → 剩菜 1碗 @冷藏，2 天后到期
200g猪肉 冷藏 2天          → 猪肉 200g @冷藏
一两花椒 橱柜              → 花椒 1两 @橱柜（常备品，不设到期日）
一袋面粉 放橱柜            → 面粉 1袋 @橱柜（常备品，只记水位）
2盒牛奶和一袋面粉 冷藏      → 拆成两条
牛奶 2盒 到11月20日        → 日期优先于保质期常识
```

每次 `add` 都会逐条打印：命中了哪个词典词、数量从哪来、位置从哪来、保质期是「你说了」还是「我按常识猜的」、置信度多少。**猜的部分必须可见，否则用户没法纠错。**

## 3. 网页界面

`serve` 起的是一个单文件 HTML（无构建、无 CDN、无字体外链），首屏在局域网内几乎瞬时。

| 区域 | 做的事 |
|---|---|
| 今日先吃 | 一句话 + 12 条以内的细节。刻意不逐条推送 |
| 说一句入库 | 支持一次输入多行、多品类 |
| 我记得有… | 模糊检索，结果带「为什么匹配」 |
| 库存 | 按 过期 → 今天 → 3 天 → 7 天 → 更久 → 常备 排序 |
| 现在能做什么 | 覆盖率排序的菜谱，标出会用到哪些临期食材 |
| 购物清单 | 只由「缺料」和「常备水位」生成，可一键重算 |
| 账本 | 近 30 天用过 / 扔掉 / 浪费率 / 常备待补 |

截图见仓库外层 `screenshots/`（桌面 880px、移动端 390px 真实视口）。

### HTTP 接口

界面用的就是这套 JSON 接口，也可以直接给别的 Agent / 脚本调用：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state` | 库存 + 简报 + 统计（首屏一次拉完） |
| GET | `/api/search?q=` | 模糊检索 |
| GET | `/api/recipes?top=` | 菜谱推荐 |
| GET | `/api/shopping` | 购物清单 |
| GET | `/api/stats` | 账本 |
| GET | `/api/export` | Markdown 导出 |
| POST | `/api/add` | `{"text": "2盒牛奶 冷藏 7天"}` |
| POST | `/api/consume` | `{"id": 12, "qty": 1}` |
| POST | `/api/waste` | `{"id": 12}` |
| POST | `/api/shopping/sync` | 重算购物清单 |
| POST | `/api/shopping/toggle` | 勾选已买 |
| POST | `/api/seed` | 重置演示数据 |

## 4. 目录结构

```text

│   ├── lexicon.py    食材词典：别名、品类、存放位置、保质期常识、常备品水位
│   ├── nlparse.py    自然语言解析：数量/单位/位置/日期/多品类切分 + 置信度
│   ├── fuzzy.py      模糊检索：别名、拼音首字母、字形、特征标签、子串
│   ├── recipe.py     菜谱匹配：覆盖率、临期食材加权、缺料清单
│   ├── expire.py     预警分组与常备品水位告警
│   ├── shopping.py   购物清单生成（缺料 + 水位）
│   ├── store.py      SQLite 持久化：items / events / shopping 三张表
│   ├── seed.py       33 条自然语言演示数据
│   ├── cli.py        命令行入口（12 个子命令）
│   ├── ui.py         单文件网页界面
│   ├── server.py     HTTP 服务（12 个端点 + 静态页）
│   └── data/
│       ├── lexicon.json   78 种食材 / 115 个别名 / 19 种常备品
│       └── recipes.json   22 道家常菜
└── tests/test_pantry.py   54 个测试
```

规模：`pantry/*.py` 约 2,000 行，测试约 390 行。

## 5. 设计上的几个硬选择

**① 不做全量建档。** 常备品（米面油盐等 19 种）只记「水位」，不记到期日。理由来自竞品用户的原话：*"别全录入，只录入最娇气的几样"*。全量建档的系统，第二周就会变成 fiction。

**② 简报只有一句话。** 行业里被静音最多的就是逐条推送。所以默认只给「今天先吃：X、Y、Z」，细节折叠在 `-v` 后面。

**③ 排序即动作顺序。** 库存列表按「过期 → 今天 → 3 天内 → 7 天内 → 更早 → 常备」排，而不是按录入时间。用户打开就想知道「先动哪个」。

**④ 猜的地方必须可见。** 保质期是猜的就标「按常识取 N 天」，名称没收录就标「未收录词，建议补词典」并置 `needs_review`。宁可不填，不可装作知道。

**⑤ 浪费要记账。** `trash` 会记下「差几天过期」。没有这个数字，浪费率永远是感觉，不是事实。

## 6. 测试

```bash
python3 -m unittest discover -s tests -t .        # 54 passed, ~0.7s
```

测试原则是**每条对应用户真会说的一句话或真会做的一个动作**，不测实现细节。覆盖：12 种口语写法、多品类切分、拼音/字形/特征模糊检索、状态边界（今天到期 / 已过期）、菜谱覆盖率与过期食材不吃、购物清单去重、水位告警、HTTP 端点、日期可注入。

其中 9 条是**已修 bug 的回归用例**，包括：
- 「一两花椒」被连读成 12（`一两` 是单位，不是数量 1+2）
- 「一碗剩菜」的「剩」被当填充词删掉，导致名称掉字
- 「2盒牛奶和一袋面粉」里的「和」把「和牛」这类词切开
- 常备品跟着行级位置「冷藏」走，导致面粉进了冷藏
- 测试用固定日期、实现用真实当天，隔一天跑就红（日期必须可注入）

## 7. 已知限制（诚实清单）

- **没有照片识别。** 这是所有人对这类产品的第一期待，但 V1 零依赖 / 零预算的约束下没做。计划 W5 以小票 OCR + **草稿态人工确认**的方式有限接入，永不静默写入。
- **词典只有 78 种食材。** 覆盖我家常买的，不是全中国人常买的。未收录词会记录 + 标记待确认，不会硬猜。
- **保质期是常识区间，不是精确值。** 它只用来排序提醒，不能用来判断「还能不能吃」。
- **只有中文口语输入。** 不处理方言、不做语音（W3 计划）。
- **单机单用户。** 无账号、无同步；数据在 `~/.homepantry/pantry.db`，不上云。
- **没有移动端原生壳。** 手机通过局域网访问网页，W2 加主屏图标。

## 8. 数据与隐私

所有数据存在本机 SQLite，不发任何网络请求，不接任何第三方分析。删掉 `~/.homepantry/` 就等于彻底删除。
