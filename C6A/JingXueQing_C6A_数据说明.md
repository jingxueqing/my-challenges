## 1. 采集对象

不是造数据，是把我自己历史挑战的**真实交付目录**扫了一遍：

| 项 | 数量 | 说明 |
|---|---|---|
| 学生 | 3 | 本机存在的交付署名（`Elite20TA` 等） |
| 挑战 | 20 | C1、C2、C2A、C2G、C3、C3C、C4、C4A、C4B、C4C、C4D、C5、C5A、C6、C6A、C7、C8、C9、C10、C10H |
| 提交包 | 19 | 一个「包」= 一个挑战的一次交付目录 |
| 交付记录 | 16 | 学生 × 挑战 的去重记录（同一包多次覆盖算一条） |
| 文件与目录条目 | 264 | 递归统计（含子目录、截图、数据文件） |

采集范围是本机的历史交付目录（`~/Desktop` 与挑战工作区下的 `C*` 交付包）。**没有联网抓取**，没有第三方 API，没有手工编造行。

## 2. 每个文件是什么

### `records.csv` — 记录级主表（16 行）

一行 = 一个「学生 × 挑战」。字段：

| 字段 | 含义 | 怎么来的 |
|---|---|---|
| 学生 / 挑战 / 挑战名 | 标识 | 目录名与挑战元数据 |
| 状态 | `complete` / `partial` | 必填项是否全部命中 |
| 完整度 | 0~1 | 已交必填项 ÷ 必填项总数 |
| 必填项数 / 已交必填项 / 缺失项 | 明细 | 与平台 `required_deliverables` 逐项比对 |
| 文件数 | 整数 | 该包内文件条目数 |
| 提交时间(近似) | ISO 8601 | **取目录内最新文件的 mtime**，不是平台提交时间 |
| 提交包数 | 整数 | 该记录下覆盖了几个交付目录 |
| 命名合规率 | 0~1 | 命中必填模式的条目数 ÷ 必填项数 |
| AI日志可用 | 是 / 否 | 是否存在可读的 `*AI日志*` |
| 评审分 | 0~1 或空 | 仅 C4A 有质量分，见第 4 节 |

### `files.csv` — 文件级明细（264 行）

一行 = 一个文件或目录。字段：`学生,挑战,文件名,相对路径,类型,大小(字节),修改时间,归类,命中的交付项`。
`归类` 是我自己定的粗分类（技能包/代码、截图、数据、文档…），`命中的交付项` 记录这个文件命中了哪条必填模式。

### `matrix.csv` — 学生 × 挑战 矩阵（3 行 × 20 挑战列）

单元格取值 `✅` 完整 / `⚠️` 部分 / `❌` 缺失，末尾三列是行汇总（已提交数、完整条数、平均完整度）。
这张表是仪表盘热力图的直接数据源。

### `challenge_stats.csv` — 挑战级汇总（20 行）

每个挑战的必填项数、提交人数、完整条数、平均完整度、`规格来源`。
`规格来源 = auto_extracted` 表示必填项是从平台 challenge 内容里自动抽取的，不是我手填的。

### `specs.json` / `specs_extracted.json`

平台规格缓存：每个挑战的 `required_deliverables` 原始模式串，以及抽出来的结构化必填项。
保留它俩是为了**可复算**——改判定逻辑时不用回平台重新拉。

### `submissions.json`

仪表盘直接消费的结构化数据（记录级 + 派生统计），字段比 CSV 更全，`JingXueQing_C6A_仪表盘/data.json` 与它同源。

### `报告/`

按运行日期留档的每日摘要与群通知稿。11-01 是首次采样（17 包），11-02 补进 C6/C7 后变 19 包。
**两份数字不同不是错**，是同一套管线在不同时点的快照，故意保留。

## 3. 口径与判定规则

1. **完整度** = 已命中的必填项 ÷ 必填项总数。必填项本身不存在 → 记为 1.0 并在 `缺失项` 写「无指定」。
2. **模式匹配**：必填项里带 `*` 的按通配匹配（如 `*AI日志*` 可跨子目录命中），不带 `*` 的必须**文件名精确相等**。
3. **目录也算条目**：`*仪表盘*` 这类模式命中一个同名目录即算交付，不要求目录里有 index.html——但仪表盘目录里确实有。
4. **时间**：用文件 mtime 近似提交时间。这是**已知偏差**：重跑管线会刷新 mtime，所以时间线看的是「最后编辑」而不是「首次提交」。
5. **去重**：同一挑战在同一目录下多次覆盖，按一个包计；跨目录同名挑战按多个包计。

---

## 4. 已知局限（不藏）

- **样本小**：只有 3 个学生、19 个包。它不是统计样本，是自我审计。
- **提交时间不精确**：见上，mtime 近似。
- **评审分只有一处**：`评审分` 仅 C4A 有真实值（复用 C4A 技能产出的 `评审结果.json`，rubric `c4a-rubric-v1.1`），其余为空**不是漏采，是没有这个数据**。
- **必填项靠自动抽取**：`auto_extracted` 的规格若平台改过措辞，历史包会显示「缺失」但其实是命名变了。重算时请先重拉 `specs.json`。
- **没有跨设备数据**：只扫了本机，别的机器上的交付不在表里。

## 5. 怎么重算

```bash
cd JingXueQing_C6A_pipeline
python3 run.py          # 采集 → 规格抽取 → 汇总 → Excel → 网站，一条命令跑完
```

单步：`specs.py`（拉规格）→ `spec_extract.py`（抽必填项）→ `pipeline.py`（采集与判定）→
`make_excel.py`（生成 `JingXueQing_C6A_report.xlsx`）→ `make_site.py`（生成 `JingXueQing_C6A_仪表盘/`）→ `digest.py`（每日摘要）。

全程只用 Python 标准库，不联网、不装包、不需要 Node。原始 CSV 可直接用 Excel 打开复核。
