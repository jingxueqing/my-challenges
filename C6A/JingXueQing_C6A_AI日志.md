# C6A AI 日志：一次真实的人机协作记录

> 作者：JingXueQing（人）｜ 执行：WorkBuddy 内置 Agent（AI）
> 记录方式：按**执行轮次**顺序记录，每轮写「目标 / 动作 / 失败 / 修复 / 证据」。
> 证据来源标注规则：`【终端】`= 本机命令真实输出；`【文件】`= 交付目录里可打开的文件与行号；`【时间戳】`= 文件修改时间。**没有一条是事后编的。**

## 0. 这次的人机分工（先说清楚，避免误会）

| 角色 | 做了什么 |
|---|---|
| **人（我）** | ① 把挑战资料包（CHALLENGE.md / rubric / 完整资料）交给 AI；② 划定底线：**只许用本机真实提交数据，不许编造同学姓名和提交记录**；③ 验收产物：能不能双击打开、数字对不对得上、缺件提醒是否指向真人真事 |

一句需求（"完成挑战"）之后的所有迭代都发生在执行侧：AI 跑出结果 → 数值不合理 → 回查代码 → 修 → 重跑。**这正是 C6A 想考的东西：不是把 prompt 写得漂亮，而是把「结果不对」揪出来。**

原始需求（一字未改）：`@挑战_C6A 提交数据仪表盘_w43gy7_完整资料 完成挑战`

## 1. 第 0 轮：先查数据，别急着写代码

**动作**：读 `README.md / CHALLENGE.md / rubric.json / challenge.json`；然后盘本机有哪些**真实**提交数据。

**发现**：

- 桌面 `我的挑战/` 下有 20 个挑战的官方文档（含必填项表格）——这是「规格」的权威源。
- 桌面 `挑战的产物/` 下有 16 个交付目录（本人 C1/C2/C2A/C2G/C4/C4A×2/C4B/C4C/C4D/C5/C5A/C6/C7）——这是「提交」的真实数据（C6A 本包后来移到了桌面根，见第 11 轮）。
- `C4A-…另版含真实评审输入/真实评审输入/` 下有 **3 位提交者**的真实 C4 包（JingXueQing / WeChatGroup / Elite20TA）——这是唯一一份「别人」的数据。

**关键决策（人拍的）**：不造假。全班 20 人拿不到，就老老实实写「本机可核验 3 位提交者」，并在界面上把「❌ 无记录」和「未提交」区分开。
**证据**：`【文件】JingXueQing_C6A_数据/submissions.json → provenance.caveats`

## 2. 第 1 轮：规格抽取，第一版只抽到 13/20

**目标**：把 20 份 CHALLENGE.md 变成机器可执行的「必填项清单」。

**动作**：写 `spec_extract.py`，用正则抓「交付物表格行」和「`姓名_xxx.md` 代码块行」。

**失败**：

```
【终端】抽取到 13 个挑战的规格
【终端】未能自动抽取（需要人工补丁）： C1, C2, C3, C3C, C4D, C5A, C6A
```

**根因分析**：

1. C1/C2/C3 的表格里写的是 `README.md`、`*AI日志*`、`paper.tex`，**没有「姓名」占位符**，被我的 `NAME_TOKENS` 过滤掉了；
2. C4D/C5A/C6A 是**代码块清单**（`姓名_C6A_方案设计.md   ← 说明`），我要求「两个下划线」的正则匹配不上；
3. 通配符 `*AI日志*` 因为「不像文件名」被 `FILE_LIKE` 拒绝。

**修复**：放宽 pattern 识别（允许通配符、允许单下划线）、代码块行只要出现姓名占位符就收。
**证据**：`【文件】JingXueQing_C6A_pipeline/specs.py` 的 `pick_pattern()`

## 3. 第 2 轮：抽到 19/20，但抽出来的东西「串味」了

**现象（比抽不到更危险）**：

```
【终端】C1  1 项 / 必填 1        ← 应该有 4 项
【终端】C4 12 项 / 必填 12       ← 应该有 5 项
【终端】C6A label = "data" / "dashboard" / "report"   ← 标签取成了文件名
```

**根因**：

1. **章节串味**：C4 文档第十章「附件：两个示例 .skill」的表格被当成交付物（多出 7 项）；
2. **挑战串味**：`挑战_C2A` 文档里嵌了 C9 的交付清单，抽成 C2A 的必填项（后续导致 C2A 误判「缺任务说明文档」）；
3. **标签取错列**：`←` 后面的说明被当标签，或者反引号里的文件名直接当标签。

**修复**：

- 只解析标题含 `交付物 / 需要提交 / 必须提交` 的章节（`deliverable_sections()`）；
- 抽到的 pattern 里若含 `_C9_` 而当前挑战是 C2A → 丢弃（跨挑战串味过滤）；
- 标签清洗：文件名当标签的去掉扩展名，`姓名A/姓名B` 占位符去掉，泛词（"必须"/"文件"）用槽位中文名兜底。

**结果**：`【终端】20 个挑战 / C1 4 项 / C4 5 项 / C6A 9 项`

## 4. 第 3 轮：一个字母级别的 bug，把 Excel 报表判错了

**现象**：C6A 的 `姓名_C6A_report.xlsx` 被归到「文章/链接」槽位。

**根因**：槽位匹配先看「标签」，而标签是 `report`；`article` 槽位的正则里含 `repo`——`report` 里恰好有 `repo` 四个字母。
**修复**：槽位优先级改成 **slug（按文件名正则）> 标签 > pattern**，`report.xlsx` 走 `\.xlsx$` 命中 `excel` 槽位。
**证据**：`【文件】specs.py → build_item()` 中 `slot = norm_slot(slug,"file") or norm_slot(label,"label")`

## 5. 第 4 轮：数据管线第一版，17 个包 / 14 条记录，三处算错

**第一版输出**：

```
【终端】[scan] 提交包 17 个
【终端】[data] 记录 14 条 / 学生 3 位 / 挑战 20 个 / 文件 239 个
```

**人工核对发现三处错**（都是"数字看起来合理，但其实是错的"）：

| # | 错误 | 怎么发现 | 根因 |
|---|---|---|---|
| ① | 别人的文件算到本人头上 | `JingXueQing/C4` 记录了 3 个提交包，其中一个是 C4A 包里的 `真实评审输入/` | 嵌套提交包没被排除，深度 2 层时把别人包里的文件抓进来了 |
| ② | C2A 被判「缺任务说明文档、测试结果」 | C2A 明明有完整的提案 + 日志 | 第 3 轮遗留的跨挑战串味 |
| ③ | C2G 被判「缺 16MB artifact」 | 文件 `JingXueQing_C2G_submission.tar.gz` 就在目录里 | `config.json` 的 `ignore_file_globs` 里写了 `*.tar.gz/*.zip/*.skill`——把**最关键的交付物**当垃圾过滤了 |

**修复**：① 把 `真实评审输入` 加进 `ignore_dirs`，由独立根目录单独扫描；② 跨挑战过滤；③ 忽略列表只留 `*.pyc / .DS_Store / *.tmp`。

**教训（写进 AAR）**：**"忽略规则"和"交付物"经常长得一样**。为了少扫一点垃圾文件而设的过滤，差点把整个挑战的核心产物判成缺失。

## 6. 第 5 轮：修一个 bug，撞出另一个 bug（回归）

**现象**：修完嵌套包过滤后，C4D 和 C5A 从「完整」变成「缺件」。

```
【终端】JingXueQing C4D partial 0.75 miss=['你的 Agent 技能代码', '运行截图']
【终端】JingXueQing C5A partial 0.80 miss=['截图证明']
```

**根因**：我把「名字形如 `Xxx_C4D_yyy` 的目录」一律当成嵌套提交包跳过——但 `JingXueQing_C4D_agent-skill/`、`JingXueQing_C4D_output_screenshots/`、`JingXueQing_C5A_screenshots/` **本身就是交付物**。

**修复**：撤掉这条规则，改用「显式忽略目录名」的方式（`真实评审输入 / 评审输入 / review_input`）。
**教训**：**用模式识别来处理特例，很容易误伤正常数据**；特例就该写成白名单，并写清理由。

## 7. 第 6 轮：口径本身也要被质疑一次

**现象**：「命名规范符合率」C1 = 0%、C2 = 0%、C5 = 25%，看起来很糟。

**第一反应**是「指标算错了」，于是把分母从「所有候选文件」改成「真正命中交付项的文件」（工程内部文件不该拖累命名分）。

**改完还是 0%** —— 查文档才发现：**C1/C2 的官方规格本身就不要求姓名前缀**（写的是 `README.md`、`*AI日志*`、`paper.tex`）。也就是说 0% 是**真话**，但读法要变：**低估的不是学生的纪律，而是这两个挑战的命名规范与统一规范不一致。**

**处理**：不改数字，改**解读**——把这条写进「洞察」卡片，并在 AAR 里作为「指标要配口径，否则就是甩锅工具」的例子。
**证据**：`【文件】submissions.json → records[JingXueQing/C1].quality.naming_compliance = 0.0`

## 8. 第 7～8 轮：Excel 与网站，靠"看图"发现的问题

**Excel**：`【终端】KeyError: 'specs_origin'` —— provenance 里我把 `specs_origin` 嵌错了层级（放进 `scan_rules` 里）。改结构 + 重跑，6 个 Sheet 正常。

**网站**：无头 Chrome 截图逐页看，发现 5 个视觉/交互问题：

| 问题 | 表现 | 修法 |
|---|---|---|
| 学生卡片等高 | 只有 1 条记录的同学卡片被撑到 500px，大片空白 | `.stu-grid{align-items:start}` |
| 记录行溢出 | 右侧「完整/缺件」胶囊被裁掉一半 | `grid-template-columns:46px minmax(0,1fr) auto` + `min-width:0` |
| 零数据挑战全红 | C3/C6/C8 等 8 个挑战的必填项标签全显示"缺失红" | 无提交人数时不着色（无数据 ≠ 缺失） |

| 深链打不开 | `#record=JingXueQing%7CC4B` 没解码，正则匹配不到 `\|` | 先 `decodeURIComponent` 再匹配 |

**证据**：`【文件】JingXueQing_C6A_screenshots/*.png`（修前修后都在截图里可比对）

## 9. 第 9 轮：写自检脚本，让机器替我验收

**动作**：`run.py check` 反向验算——状态 vs 缺失项、完整度 vs 命中数、文件命中的交付项是否在规格里、数据根是否还在。

**第一次跑就抓到一个"假 bug"**：

```
【终端】发现 1 个问题：
  - JingXueQing/C6A：完整度与必填项命中数不一致
```

**排查**：完整度存的是 3 位小数（`round(x,3)`），自检阈值写的 `1e-6`，4/9 = 0.4444 与 0.444 差 4e-4 → 误报。阈值改 `1e-3` 后通过。

**这是本次最值钱的一条经验**：**自检脚本自己也会错，而且错得更隐蔽**（它会让人以为数据有问题）。

## 11. 第 11 轮：交付目录挪到桌面，指标跟着变了

**触发**：人一句「把这个挑战的产物挪到桌面」。听起来是纯文件操作，`mv` 一条命令就完，但数据看板跟别的东西不一样——**它的数据是用路径换来的**。

**动作**：`mv` 整个 `C6A-交付_JingXueQing_提交数据仪表盘/` 到桌面根。

**连带撞出三个问题（都是搬完才发现）**：

| # | 问题 | 根因 | 处理 |
|---|---|---|---|
| 1 | C6A 自己那行记录会消失 | 数据根是 `挑战的产物/`，扫描逻辑取「子目录当提交包」；本包搬出去后就不在任何根下了 | 配置加了三级数据根 `/Users/jingxueqing/Desktop`，并用新字段 `include_only` **只认 C6A 这一个子目录**——否则桌面上 `我的挑战/` 等文件夹会被误当提交包 |
| 2 | 冒出两个从没进过看板的包 | `C6-交付_…公众号创作台`（134 文件）、`C7-交付_…内容传播`（21 文件）是上次采样之后才出现的 | 不特殊处理，重扫自动纳入：17 包 → 19 包 |
| 3 | 文档里 6 处数字全部过期 | 217 文件 / 14 记录 / 12 完整 / 89% / 覆盖率 23% 是上一轮的快照 | 逐处按新输出重算；**但本文第 4～9 轮里的历史数字保持原样**，那是当时的真实输出，改了就是伪造证据 |

**新输出（终端原文）**：

```
[scan] 提交包 19 个
[data] 记录 16 条 / 学生 3 位 / 挑战 20 个 / 文件 264 个
[data] 状态：完整 14 / 缺件 2 / 平均完整度 90%
[site]  index.html 生成完成（147 KB，内嵌 16 条记录）
自检通过：状态、完整度、文件-规格映射三者一致。
```

**证据**：`【终端】run.py all / run.py check`；`【文件】config.json → roots[2].include_only`；`【文件】pipeline.py → discover_packages() 的 only 白名单分支`。

**教训**：凡是「把路径当输入」的系统，搬家不是搬文件，是改数据源。迁移完必须重跑 + 重算，光看 `ls` 通过不算通过。

## 13. 我（人）最想留下的三句话

1. **AI 一次就能跑通的代码，往往"看起来对"**。C6A 里三个最致命的错误（别人的文件算到我头上、核心产物被忽略规则吃掉、缺件误判）都是**跑通了、数字也合理**的情况下出现的。
2. **口径比代码难**。「❌ 无记录」和「未提交」混为一谈，就会在群里冤枉同学——这不是技术问题。
3. **让 AI 自己验收自己**。`run.py check` 和截图回看，是这次真正把质量兜住的两件事。
