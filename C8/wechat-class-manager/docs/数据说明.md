# 数据说明：哪些是真的，哪些是合成的

> 这份文档存在的唯一目的：让别人能判断"这个系统的数字能不能信"。
> 所以它把每一类数据的来源、边界、不可信的地方都写清楚。

---

## 1. 三类数据，边界分明

| 数据 | 来源 | 真实性 | 用在哪 |
|---|---|---|---|
| **挑战定义**（20 个挑战、必备件、截止日） | 课程官方 `CHALLENGE.md` / `challenge.json`（桌面《我的挑战》下 20 份原始资料） | **真实** | `config/challenges.yaml` |
| **真实提交包**（14 个挑战、235 个文件） | 本机磁盘 `~/Desktop/挑战的产物/` 实扫 | **真实** | 提交矩阵中 `sources=["disk"]` 的 14 项 |
| **群消息流**（268 条 / 14 天 / 21 人） | `data/make_fixtures.py` 生成 | **合成脱敏** | 分类、关联、Q&A、画像、预警 |

一句话：**结构是真的，人不是真的，聊天内容是照着真实场景手写的。**

## 2. 为什么群消息是合成的

### 2.1 本机微信库确实读不了（附证据）

```bash
$ head -c 16 ~/Library/Containers/com.tencent.xinWeChat/Data/Documents/\
xwechat_files/wxid_x80d3qnl4bd112_2d6c/db_storage/message/message_0.db | xxd
00000000: bc00 2ab8 2acc ebf5 cfdd f9ea f369 1720  ..*.*........i.
```

正常 SQLite 文件头应该是 `SQLite format 3\0`（`53 51 4c 69 74 65 20 66 6f 72 6d 61 74 20 33 00`）。
这里是 `bc00 2ab8…` —— **SQLCipher 加密**。会话库 `session.db`、联系人库 `contact.db` 同样加密。

WeChat 4.x 的密钥只在微信进程内存里。取出它需要 attach 到运行中的进程（root + `task_for_pid`），
属于侵入式操作，而且会碰到别人的聊天记录。**我没有做，也不建议做。**

`python3 -m wcm.cli doctor` 会把这条检测结果打印出来，任何人都能自己复核。

### 2.2 为什么不用"随便编几百条"了事

随便编的消息分类准确率一定虚高（因为没有真实语言噪声）。
所以这份回放集的写法是：**每一条都对应真实课程里真实会发生的事**——

- 文件名不规范的提交（`C4A评审器.zip`、`郭雅琪_C4A评审器_最终版.zip`）
- 群里问过一百遍的问题（公众号封面尺寸、latex 参考文献格式、8G 内存跑不跑得动 ollama）
- 老师真的会发的通知（`@所有人 提醒：C5 仓库必须在本周五 24:00 前公开`）
- 真的会有人消失（罗欣然、谢梦琪设置为沉默样例）

而且**每条都有人工标注的 intent**（`data/fixtures/labels.jsonl`），
这是分类准确率的分母，不是模型自己编的答案。

## 3. 学生名单的构成

| 类型 | 人数 | 说明 |
|---|---|---|
| 真实 | 1（景雪晴 / JingXueQing） | 提交数据来自本机 14 个真实提交包；群消息里的发言是合成的 |
| 合成 | 19 | 姓名、专业均为虚构，用于撑起班级规模与活跃度分布 |

给合成学生分配了不同的行为模式，让看板有真实的形状：

- **高活跃贡献者**：林一舟、何承翰（提问多 + 回答多 + 提交齐）
- **高质量沉默型**：景雪晴（发言少但提交最全，14 个挑战——这是真实情况）
- **只问不答型**：孙乐、彭心语
- **递减型**：邱志伟（前两周活跃，后两周明显下降 → 触发 engagement_drop）
- **沉默型**：罗欣然、谢梦琪（7 天以上零发言 → 触发 silent_student）
- **缺件型**：马嘉乐、徐方雨（只交了主文件，缺 AI 日志/拿来说明）

## 5. 换成你自己的数据（3 步）

```bash
# 1. 用 chatlog 或任一工具导出你的群，字段对齐 data/fixtures/messages_raw.jsonl
#    time / talker / talkerName / sender / senderName / type / content / contents / msgId

# 2. 改名单（config/group_config.yaml 的 roster）和挑战（config/challenges.yaml）

# 3. 跑
python3 wechat_bridge.py --source replay --fixture <你的导出.jsonl> --days 30 -o out/messages.jsonl
python3 -m wcm.cli run --days 30
```

注意：分类器是按本课程群的说话风格调的，换群之后**一定要先看混淆矩阵再调规则**，
不要直接相信 91.8% 这个数字。

## 6. 隐私处理

- 真实提交包只记录**文件名、大小、修改时间**，不读取文件内容，不上传任何地方。
- 群消息里不含任何真实学生姓名（除本人）。
- 全链路无网络调用（除非你手动开 chatlog 或配 LLM key）。
- `out/` 目录可整体删除重建，不包含不可再生的数据。
