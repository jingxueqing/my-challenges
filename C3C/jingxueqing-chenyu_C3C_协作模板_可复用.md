# 跨专业协作模板（下一对搭档可以直接套用）

> 来源：`jingxueqing-chenyu` 做 C3C 的实操沉淀。凡标注 **⚠️坑** 的地方，都是我们真实踩过的。
> 用法：复制本文件 → 按顺序填 → 填不下去的地方就是你们还没想清楚的地方。

---

## 第 0 步：组队前先自检（10 分钟）

两个人各自回答，然后对照：

| 问题 | A 的答案 | B 的答案 |
|---|---|---|
| 我的专业是 | | |
| 我**能独立交付**的东西（举个具体例子） | | |
| 我**完全不会、且不是一周能学会**的东西 | | |
| 我最怕对方说"这很简单啊"的时刻是 | | |

**合格标准：** 你们各自的"完全不会"里，至少有一项是对方"能独立交付"的。
如果做不到，换人或者换项目——**技能差异不够，C3C 的价值就不成立。**

⚠️坑：只对比"我会 Python 你会 Excel"是不够的。要对比"我能交付什么"和"我交付不了什么"。

## 第 1 步：技能画像（各自 30 分钟）

复制 `技能画像模板` 到你们各自的文件，**重点填第三节和第五节**（想学什么 / 我明确做不到什么）。

```markdown
# 技能画像 ｜ 姓名

## 一、专业与背景
- 学校/专业/年级：
- 相关经历（2 段，带时间）：
- 求职/研究方向：

## 二、我已经会的（5–10 项）
| # | 技能 | 熟练度 | 我怎么证明（要具体到产出物） |
|---|---|---|---|
（熟练度只用三档：能独立交付 / 能用 / 入门。"熟练"这个词不许用，说不清）

## 三、我想学的（3–5 项）
| # | 想学的 | 为什么想学（写具体的卡点，不写"想提升自己"） | 期望学到什么程度（可验证） |
|---|---|---|---|

## 四、我能教的（3–5 项）
| # | 能教的 | 为什么这项值得教（不写"我会 Excel"这种简历式内容） | 教学形式 |
|---|---|---|---|

## 五、我明确做不到的事（至少 3 条）
（这一节最重要。写不出来说明你还没想清楚自己的边界）
1.
2.
3.

## 六、项目结束时，我希望我能做到的一件事（一句可验证的话）
> 例：我能独立往项目里加一个新的能力标签并让它通过全部测试。
（不许写"我学会了编程"这种无法验证的句子）
```

⚠️坑：技能画像写成简历。检验方法——**如果你的画像可以直接投简历，那它就是简历，不是画像。**

## 第 2 步：定项目 + 写"为什么单独做不了"（1 小时，两人一起）

用这个表，**必须各写一栏，不许合并**：

| 如果没有对方，我会缺什么（写 3 条，要具体到"卡在哪一步"） |
|---|
| A 缺： |
| 1. |
| 2. |
| 3. |
| B 缺： |
| 1. |
| 2. |
| 3. |

**合格标准：** 每一条都能举出一个真实卡住的场景。
❌ "我缺一个人帮我写代码" —— 太笼统
✅ "我卡在第一个报错就动不了：报 ModuleNotFoundError 时我不知道是我写错了还是站错目录了"

⚠️坑：写"我们互相补充"这种话，等于没写。

## 第 3 步：写验收标准（这是整个项目最关键的一步）

在**动手写任何东西之前**写。模板：

```markdown
## 验收标准

### AC-1 [名称]
[一句可判定的话]

> 判定方式：[怎么测]
> 为什么需要这条：[不满足会怎样]

### AC-2 ...
```

**把形容词翻译成可判定句的三条公式：**

| 模糊说法 | 翻译公式 | 例子 |
|---|---|---|
| "要稳定" | "重复 N 次，结果 ____" | "同一输入跑 100 次，结果完全一致" |
| "要给理由" | "任何 ____ 都必须能定位到 ____" | "任何缺失判定都必须能定位到原文的某一句" |
| "要合理" | "做 X，结果不许 ____"（写成**下限**，不写目标） | "多加一条相关经历，分数不许下降" |

**为什么写成下限而不是目标：** 目标会限制实现方式（"必须上升"排除了"不变"），
下限只排除错误（"不许下降"允许不变）。**给实现留空间，是需求方的修养。**

⚠️坑：AC 超过 8 条就该砍。我们最后留下 7 条，砍掉了 3 条"想到但没法判定"的。

## 第 4 步：定"谁有资格判断"（30 分钟，最容易漏）

填这张表，**每行必须填满，不许留空**：

| 判断事项 | 只有谁能拍板 | 另一个人能做什么 |
|---|---|---|
| 代码质量 / 结构好不好 | | 提需求 |
| 结果在业务上是否合理 | | 提供数据与实现 |
| 某个中文词算不算同义 | | 提候选，等对方确认 |
| 参数取多少 | 分两半：口径由业务方定，实现细节由工程方定 | |
| 什么算"做完了" | | |

⚠️坑：**不填这张表，就会出现"两个人都以为对方会判断"的空窗期。**
我们的 bug 因此多活了两周。

## 第 5 步：教学会话设计（每次 2 小时）

**固定结构（别改）：**

| 时段 | 内容 | 硬要求 |
|---|---|---|
| 0–5 min | 教学方说一件"我在这件事上也不确定"的事 | **不许跳过**。跳过就会变成装懂 |
| 5–45 min | 讲，一次只讲一个概念 | 用对方熟悉的类比开场（"字典就是 VLOOKUP"） |
| 45–50 min | 学习方复述一遍 | 复述不出来说明没讲清 |
| 50–110 min | 学习方动手，教学方只看不动手 | 教学方不许碰键盘 |
| 最后 10 min | 定课后作业 + 记下一个可进仓库的产物 | **不留下产物的教学等于聊天** |

**每次会话必须产出一个能提交的东西**（代码/文档/测试/标注），否则下次不许开始。

⚠️坑：教学方说"这很简单啊"。这句话会让人三天不敢提问。**说一次就够了。**

---

## 第 6 步：协作机制（四条硬规则）

1. **规格先行**：任何影响对方工作的改动，先在 `docs/` 改文档，对方确认影响范围，才动手。
2. **改规则必须补回归用例**：防止"为了让结果好看而改标准"。
3. **谁的地盘谁签字**：见第 4 步的表。越界要给出理由，理由要能被反驳。
4. **不做纯听课**：见第 5 步。

---

## 第 7 步：能力验证（各做一个独立任务）

| 谁 | 任务类型 | 验收方式 |
|---|---|---|
| 非 CS 方 | 独立写一段代码 / 独立跑通一个工具 / 独立完成一次 Git 提交 | 有真实提交记录 + 测试全绿 |
| CS 方 | 独立完成一个领域分析 / 独立产出一份专业内容 | 由非 CS 方批注，**允许不通过** |

**关键要求：CS 方的任务必须允许失败，并且失败要保留在交付物里。**
我们那次是 3 条过 1 条。**把失败删掉，这份验证就没有说服力了。**

⚠️坑：能力验证任务做成"表演"（挑一个对方肯定会的做）。
要挑**对方领域里最基础、但自己真的不会**的那一件事。

---

## 第 8 步：验证"你写的检查真的会检查"

任何自动化检查（测试、脚本、断言）都要做一次**破坏性验证**：

1. 先让它通过
2. **故意改坏一处**
3. 确认它**变红**
4. 改回来，确认变绿

**如果第 3 步不红，说明这个检查是假绿——它不保护任何东西。**

⚠️坑（我们踩过两次）：**遍历"被检查对象自己报出来的清单"去验证这个清单，
永远验不出清单被改。** 必须拿一份外部写死的预期去比。

```python
# ❌ 假绿：删掉列表里的一项，遍历的还是删后的列表
for kw in tag.all_keywords():
    assert hit(kw)

# ✅ 真红：集合不等就红
assert sorted(tag.all_keywords()) == sorted(["词1", "词2", "词3"])
```

## 第 9 步：AAR（各自先写 15 分钟，再交换）

结构固定：

```markdown
## 一、做了什么（事实层，只写可复核的）
## 二、学到了什么（分人，每条要能指到具体事件）
## 三、失败经验（至少 3 条，每条写：事实 / 代价 / 根因 / 改进方案）
## 四、怎么验证的（每条结论 → 验证方式 → 复核命令）
## 五、可复制的经验
## 六、如果只记住一件事
```

**两条硬要求：**

1. **失败至少写 3 条。** 写不出来的 AAR 一定是假的。
2. **"学到了什么"必须能指到一个具体事件**，不能是"我提升了协作能力"。

⚠️坑：交换后强行把分歧写成一致。
**保留分歧更有价值**——分歧点往往就是两个人认知差异最大的地方。

---

## 第 10 步：交付前检查表

- [ ] 每一份文档里的**数字**都有复算命令
- [ ] 代码能在**没装任何第三方库**的机器上跑（或用 `requirements.txt` 写清）
- [ ] README 里有「已知局限」章节，至少 3 条，**包括自曝短板的**
- [ ] 所有"变好了"的结论都有**对照组**
- [ ] `git log` 里每个提交都解释了**为什么**，不只是"改了什么"
- [ ] 能力验证的**失败记录**保留在交付物里
- [ ] AI 日志区分了「实测」和「回溯」，标注了证据来源
- [ ] 明确写了「不做的事」以及**为什么不做**

---

## 最后一页：三句话

1. **1+1>2 不会自动发生。** 它只发生在两个人都愿意说"这个我不会"的时候。
2. **技术能力不能替代领域判断。** 一个能跑的、结论错误的工具，比没有工具更危险。
3. **任何"我觉得不对"，都能改写成"如果……就说明不对"。** 改写得出来，它就成了工程问题；
   改不出来，它永远只是情绪。
