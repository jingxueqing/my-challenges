## 二、教学大纲（实际执行的版本，不是计划版）

### 2.1 为什么不用讲语法（10 分钟）

陈屿先给景雪晴看一段真实代码：

```python
Tag("DAT02", "SQL 查询", "数据分析", 0.70,
    ["SQL", "查询语句", "多表关联", "Hive", "取数"],
    "能独立取数，不用求人"),
```

**陈屿：** 这段你读得懂吗？

**景雪晴：** 读得懂。这是一个"标签"，编号 DAT02，名字叫 SQL 查询，属于数据分析类，
权重 0.7，关键词是这几个，后面一句是解释。

**陈屿：** 那如果我要加一个标签呢？

**景雪晴：** 照着写一行就行……但我不知道加在哪、要不要改别的地方。

**这就是 S1 真正的起点：她不需要学语法，她需要知道"改一个地方会不会弄坏别的地方"。**

### 2.2 三件事（25 分钟）

**第一件：什么是"字典"，为什么标签要用字典存**

对比两种写法。用列表：

```python
tags = [Tag("DAT01",...), Tag("DAT02",...)]
# 想找 DAT02：得从头翻到尾
```

用字典：

```python
TAG_INDEX = {t.id: t for t in _TAGS}
# 想找 DAT02：TAG_INDEX["DAT02"] 直接拿到
```

**景雪晴的反应：** "这个我知道，就是 Excel 里的 VLOOKUP。"
**陈屿：** "……对，就是 VLOOKUP，但快得多。"

> 📌 这是整个项目里最重要的一次类比。陈屿后来在 AAR 里写：
> "我一直以为要解释哈希表，后来发现一句 VLOOKUP 就讲完了。
> 我讲不清楚，是因为我只会用术语讲。"

**第二件：只读（frozen）是什么意思**

```python
@dataclass(frozen=True)
class Tag: ...
```

**陈屿：** 加了 frozen，这个对象建好之后就不能改。你试试 `tag.weight_default = 0.9`。

**景雪晴试了，报错：** `FrozenInstanceError: cannot assign to field 'weight_default'`

**景雪晴：** 那我以后要改权重怎么办？

**陈屿：** 改源码里那个数字，重新跑。不能运行时改。

**景雪晴：** 为什么不让改？

**陈屿：** 因为如果代码里某个地方悄悄把权重改了，你看到的报告和标签表就对不上了。
你要的 AC-2 是"能溯源"——如果权重会变，溯源就断了。

**景雪晴：** 那这条要写进规格里。

> ✅ **这是她第一次主动提出要改规格。** 当天补进 `需求规格_v1.md`：
> 「标签的权重在运行期不可变，只能通过改源码调整，否则报告不可复算。」

**第三件：Git 不是备份**

陈屿演示了 5 条命令，然后让她把自己改的 `taxonomy.py` 提交。

她第一反应："这个和存一个'最终版2'有什么区别？"

陈屿用 `git log` 给她看了仓库历史，让她自己找"哪一次改了权重"。

她翻了 3 分钟，找不到——**因为当时只有 1 次提交。**

**陈屿：** 现在找不到，是因为还没历史。等有 10 次提交的时候，你就能一眼看到
"哦，10 月 16 号那次把 Excel 权重从 0.7 降到 0.6 了"。

**景雪晴：** 那提交信息是不是得写清楚为什么改？

**陈屿：** 对，而且要写"为什么"，不是写"改了什么"。

> ✅ 这条后来变成了整个项目的提交规范。看 `git log` 会发现所有提交信息都在解释原因，
> 而不是描述改动。

## 三、动手环节（65 分钟）

### 任务：独立加一个标签，并让它出现在 `taxonomy` 命令的输出里

**给定的脚手架（陈屿先写好的）：**

```python
Tag("XXX01", "标签名", "业务与行业", 0.60,
    ["关键词1", "关键词2", "关键词3"],
    "一句话解释这个能力是什么")
```

**她加的第一个标签（原始版，未修改）：**

```python
Tag("BIZ09", "行业认知", "业务与行业", 0.75,
    ["行业研究", "行业分析"],
    "懂行业")
```

### 卡点 1：关键词少于 3 个，测试没红（18 分钟）

她加完，跑 `python3 -m jd_insight.cli taxonomy`，正常输出。她认为做完了。

陈屿让她跑测试。她跑：

```
$ python3 -m unittest discover -s tests -t .
...
OK
```

**全绿。**

**陈屿：** 全绿，说明你做对了。

**景雪晴：** 等等，我这个词条只写了 2 个关键词，你之前说过每个至少 3 个。

陈屿检查——**当时还没有"每个标签至少 3 个关键词"这条测试。**
是她在 S1 之后自己提出"这条应该能被检查"，陈屿才补的
（现在是 `test_every_tag_has_at_least_three_keywords`）。

**这是本项目最重要的一次"反向教学"：学习方发现教学方的测试有漏洞。**

> 📌 陈屿在 AAR 里写："我以为我在教她，结果她第一次动手就指出我的测试缺了一条约束。
> 我写测试的习惯是'测我写的逻辑'，她的是'测我以为的规则'。这是两种东西。"

### 卡点 2：`ModuleNotFoundError`（22 分钟）

她自己回家重跑，报错：

```
ModuleNotFoundError: No module named 'jd_insight'
```

她的处理：**把 `jd_insight` 文件夹删了，重新从微信里下载了一份。** 还是报错。

微信上求助。陈屿问了一句："你在哪个目录下跑的？"

她发了截图，路径是 `/Users/jingxueqing`。

**陈屿：** 你不在项目目录里。命令行只在你"站"的目录里找东西。

**景雪晴：** 那我怎么知道我站在哪？

**陈屿：** `pwd`。

**她后来在笔记里写：** "原来报错不一定是代码错，可能是我站错地方了。
这个认知花了我两天，但改变了之后我所有的操作习惯——现在我每次开终端先 `pwd`。"

> ✅ 这条经验进入了 S3 的教学内容，也进入了 `cli.py` 的错误处理设计：
> 文件不存在时输出"文件不存在：xxx"，而不是抛原始 traceback。

### 卡点 3：不知道该把标签加在哪儿（15 分钟）

她加在文件最末尾，结果 `taxonomy` 命令输出里，这个标签出现在最后一个域的末尾，
而不是"业务与行业"那一段。

**陈屿：** 为什么输出顺序不对？

**景雪晴：** 因为我把代码加在最后了。但列表的顺序不就是展示顺序吗？

**陈屿：** 对。所以你应该加在"业务与行业"那一段的末尾。

**她改成插在 `BIZ08` 之后，输出顺序就对了。**

**她的总结：** "原来代码里的**顺序**是有意义的信息，不只是给机器看的。"
