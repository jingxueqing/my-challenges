## 二、教学大纲

### 2.1 读报错：从最后一行往上读（15 分钟）

陈屿给了 3 个报错，让她判断"是谁的错"。

**报错 1：**

```
FileNotFoundError: [Errno 2] No such file or directory: 'data/jd_J01.txt'
```

**景雪晴：** 我的错，路径不对。

**报错 2：**

```
ModuleNotFoundError: No module named 'pandas'
```

**景雪晴：** 环境的问题，没装东西。

**报错 3：**

```
TypeError: match() missing 1 required positional argument: 'resume_text'
```

**景雪晴：** ……这个是我少传了一个参数？

**陈屿：** 对。三个都答对了。**判断"是谁的错"比"看懂错在哪"更重要**，
因为只有前者决定你下一步该干什么。

**于是有了这张她后来贴在显示器边上的表：**

| 报错里出现 | 大概率是谁的问题 | 下一步 |
|---|---|---|
| `ModuleNotFoundError` | 环境 | 先确认装的包里有没有它 |
| `FileNotFoundError` | 路径 | `pwd` + `ls` |
| `TypeError` / `AttributeError` | 代码 | 参数名、拼写、类型 |
| `SyntaxError` | 代码 | 看它指的行号，问题常在上一行 |
| 一屏红字但最后一行是 `AssertionError` | **测试真的没过** | 这是唯一一种"红得有用"的 |

### 2.2 断言是什么（20 分钟）

陈屿的讲法：**断言 = 一句"我认为应该是这样"，机器帮你核对。**

```python
self.assertEqual(len(tx.all_tags()), 44)
```

**景雪晴：** 那如果以后加了标签，这个测试就会红？

**陈屿：** 对。而且**这是故意的**。

**景雪晴：** 为什么故意让它红？

**陈屿：** 因为标签数从 44 变成 45 是一件需要有人负责的事。
如果测试自动跟着变，那就没人知道标签体系什么时候变了。

**景雪晴的反应（当场记在笔记里）：**

> "我一直以为测试是'检查代码有没有 bug'。原来是'锁定我已经决定的事，
> 谁想改就得先跟我打招呼'。这个理解完全不一样。
> 那我是不是可以写一条'权重不能低于 0.4'的测试，防止以后有人乱调？"

**当场就写了这条：**

```python
def test_weight_in_range(self):
    for t in tx.all_tags():
        self.assertGreaterEqual(t.weight_default, 0.4)
        self.assertLessEqual(t.weight_default, 1.0)
```

> 📌 这是她独立写的第二个测试，也是她第一次理解"测试是给未来的自己立的规矩"。

### 2.3 什么叫"假绿"（20 分钟）—— 本次会话的核心

陈屿讲了三种"测试通过了但其实没测"的情况：

| 类型 | 例子 | 为什么假 |
|---|---|---|
| 恒真断言 | `assertEqual(1, 1)` | 永远不会红 |
| 空集合遍历 | `for t in []: assert...` | 循环体一次都没执行 |
| 测了个不存在的东西 | 断言一个根本不存在的关键词 | 断言永远空转 |

**景雪晴：** 第三种怎么发现？

**陈屿：** 很难发现。**唯一的办法是把断言改到"故意让它失败"，看它会不会红。**

**这就是"红-绿-红"方法：**

1. 先写断言，跑一次，**必须红**（证明它真的在检查）
2. 再让它变绿
3. 再故意改坏一处，确认它**又红了**

## 三、动手环节（65 分钟）

### 任务：独立写 3 个用例，并证明它们不是假绿

她选了：
1. 标签 id 不重复
2. 每个标签至少 3 个关键词
3. 权重在 0.4–1.0 之间

前两个一次通过。第三个出现了本节最重要的事件。

### 事件：假绿暴露（第 41 分钟）

她写的第三版：

```python
def test_weight_in_range(self):
    for t in tx.tags_in_domain("数据分析"):
        self.assertGreaterEqual(t.weight_default, 0.4)
```

跑，绿了。她准备提交。

陈屿问了一句：**"如果我把某个权重改成 0.1，这条会红吗？"**

她试了：把 `TOL02` 协作工具改成 0.1。跑测试。**还是绿的。**

原因：她只遍历了"数据分析"这一个域，而 `TOL02` 在"工具与平台"域。

**景雪晴：** 那我把三个域都列上？

**陈屿：** 你有 6 个域，为什么只列 3 个？

**景雪晴：** ……因为我刚才想到的是这 3 个。

**陈屿：** 这就是"假绿"的典型来源：**你测的是你想得到的部分，不是全部。**

**改成遍历 `all_tags()` 之后，她再试，红了。** 然后她改回 0.4，绿了。

**她的笔记原文：**

> "陈屿问我'会红吗'的时候我很自信，结果没红。
> 我那一刻的感受不是'我写错了'，是'我刚才差点把一个没用的测试交上去，
> 而且我会以为它在保护我'。
> 从那以后我写完任何检查都会先故意弄坏一处，看它红不红。"

### 她反过来提出的一个改进

做完 3 个用例后她问：**"如果不用测试框架，就我一个人在本机跑，怎么知道是不是全对？"**

陈屿：跑 `python3 -m unittest` 就行。

**景雪晴：** 但我不想记这么长的命令，而且我想让它顺便检查一下别的
（比如"能不能真的提取出标签"）。

于是有了 `selfcheck` 子命令：

```bash
python3 -m jd_insight.cli selfcheck
# → selfcheck 通过：标签体系完整、解析器有召回、打分单调。
```

**这个想法完全来自她。** 陈屿的原话（AAR 里）：

> "我从来没想过给不会用测试框架的人做一个一键检查。
> 因为在我的世界里，'跑测试'是个正常操作。
> 她让我意识到：**工具的使用者不等于工具的开发者，他们需要不同的入口。**"
