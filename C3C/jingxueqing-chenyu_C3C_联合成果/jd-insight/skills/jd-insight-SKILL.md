# JobLens · 岗位镜（技能名 jd-insight）

> 品牌名 JobLens，技能标识沿用 `jd-insight`，避免已装用户重装。

把 JD 拆成 44 项能力标签向量，把简历映射上去，输出可解释的匹配度报告。

## 什么时候用

- 用户贴了一段 JD，问「我能投吗 / 差在哪」
- 用户贴了简历，问「我适合什么岗」
- 用户有一批 JD，想排序
- 用户想知道「接下来补哪个技能性价比最高」

## 什么时候不要用

- 用户想让你**替他决定**要不要投 → 工具只给分与缺口，决定权在人。
- 用户想自动筛掉别人 → 本工具明确不支持（不处理否定语义，会误杀）。
- 用户问的是简历**怎么写**而不是**够不够** → 直接给写作建议，不必跑工具。

## 执行步骤

1. 确认输入齐全：
   - 单岗位模式：需要 `JD 文本` + `简历文本`
   - 排序模式：需要 `JD 列表 csv/json（含 title, jd_text 列）` + `简历文本`
   缺简历时先问用户要，不要凭空生成简历。

2. 把文本落到临时文件（避免超长文本塞进命令行参数）：

```bash
mkdir -p /tmp/jd-insight && cd <技能目录>
# 写入 /tmp/jd-insight/jd.txt 与 /tmp/jd-insight/resume.txt 后再跑
python3 -m jd_insight.cli match \
  --jd /tmp/jd-insight/jd.txt \
  --resume /tmp/jd-insight/resume.txt \
  -o /tmp/jd-insight/report.html \
  --json /tmp/jd-insight/result.json
```

3. 读 `result.json` 而不是解析 HTML。关键字段：
   - `total` 总分、`grade` 结论、`role_type` 岗位类型
   - `hard_gaps` 硬缺口 tag_id 列表 → 用 `taxonomy` 映射成中文名
   - `advise` 改进建议（已按业务口径生成，可直接采用）

4. 回复用户时必须包含三件事，缺一不可：
   - **分数 + 结论**（不要只给分数不给判断）
   - **Top 3 缺口 + 每个缺口的一条具体动作**（不要写「建议加强数据分析能力」这种空话）
   - **证据引用**：缺口要引 JD 原句，已具备项要引简历原句。这是本工具的核心价值，不许省略。

5. 若用户要求，用 `present_files` 打开 HTML 报告。

## 输出风格要求

- 分数只作为索引，不作为结论。要说清「这个分数意味着什么」。
- 缺口按「能不能在一个月内补上」排序，而不是按权重排序——权重高的往往最难补。
- 严禁为了让用户高兴而调高分数。若用户质疑分数，先核对 alias 表是否覆盖了他的同义表达，再决定是否改标签体系（改完必须补回归用例）。

## 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 分数极低但用户确实会这项技能 | 简历用词与关键词表不同义（如「财报」vs「财务报表」） | 先查 `python3 -m jd_insight.cli taxonomy`，再补 alias + 回归用例 |
| 技术岗被判成非技术岗 | 工程基础命中 < 3 个标签 | 看 JD 是否用中文描述技术栈（如「用 Java 做后端」） |
| 报告打不开 | 输出路径目录不存在 | 先 `mkdir -p` |

## 依赖

Python ≥ 3.9，**无第三方依赖**。首次使用先跑 `python3 -m jd_insight.cli selfcheck` 确认环境正常。
