# jd-insight 需求规格 v1.0

> 撰写：JingXueQing ｜ 2026-09-18
> 写给谁：陈屿。我看不懂代码，所以我只写清楚**输入是什么、输出长什么样、什么算对**。
> 具体怎么实现是你的部分，但如果你实现出来的东西不符合下面任何一条，我会打回去。

---

## 0. 为什么做这个东西（我自己的问题）

我投了 37 个岗位，收到了 4 个面试。我不知道问题出在哪：

- 我以为自己"数据分析还行"，但有些 JD 我看完觉得"这不就是我做的吗"，还是没回应。
- 有些 JD 我一眼就知道自己不行（比如要求 Java 的）。
- 我不知道该先补哪个技能。所有人都说"补数据分析"，但我缺的到底是 SQL 还是指标体系？

我需要一个东西，能告诉我：**这份 JD 要什么、我有什么、差什么、先补哪个。**

我试过让 AI 直接读 JD 和简历然后给判断。三个问题：

1. **每次结论不一样**。同一份 JD 问两次，一次说我去投没问题，一次说我不够格。
2. **说不清为什么**。它说"你缺乏数据分析能力"，我说"我实习就在做数据分析"，它就改口了。
   这说明它不是真的在判断，是在顺着我说。
3. **不能批量**。我有 30 多个想投的岗位，一个一个问太慢，而且无法横向比较。

结论：需要一个**能重复、能给理由、能批量**的判断方法。这就是这个项目。

## 1. 输入

| 输入 | 格式 | 必需 | 说明 |
|---|---|---|---|
| JD 文本 | 纯文本 | 是 | 从招聘网站复制的原文，允许有"岗位职责""任职要求"等小标题 |
| 简历文本 | 纯文本 | 是 | 我自己的简历，允许有分节标题和列表符号 |
| JD 列表 | CSV | 否 | 多岗位排序时用。至少要有 `title` 和 `jd_text` 两列 |

硬约束：**不能要求用户预先清洗文本**。真实 JD 里全是「；」「·」「1.」「【】」这些符号，
要求用户先清洗就等于没有工具。

## 2. 输出

### 2.1 一个总分（0–100）

必须配一句人话结论，不能只给数字。分档：

| 分数 | 结论 | 含义 |
|---|---|---|
| ≥ 80 | 强匹配 | 可以投，重点是把已有证据写得更硬 |
| 65–79 | 可投 | 值得投，但要先补 1–2 个缺口 |
| 45–64 | 需补短板 | 补完再投，现在投大概率浪费机会 |
| < 45 | 不建议投 | 方向不对，别把时间花在这里 |

### 2.2 六个能力域的得分

业务与行业 / 数据分析 / 产品与需求 / 沟通协作 / 工程基础 / 工具与平台

为什么是这 6 个：我把自己见过的 JD 要求逐条归类，归到第 7 类的时候发现
新类别里只剩 2 条，说明粒度太细没有意义。6 个是我人工归纳的收敛点。

### 2.3 缺口清单

每条缺口必须包含三样东西，**缺一不可**：

1. 缺的是哪个能力（用中文名，不要只给 ID）
2. **JD 的原句**（我要能自己回去核对，不接受"系统认为你缺"）
3. 一条可以明天就开始做的具体动作

"建议加强数据分析能力"这种话不算建议，属于废话。

### 2.4 岗位排序

同一份简历对 N 条 JD 的分数排序。这个功能对我最重要——
因为我真正要做的决定不是"这家我行不行"，而是"这 30 个里我该先投哪 10 个"。

## 3. 什么算对（验收标准）

我按"如果这条不满足，我就不敢用"的思路写。

### AC-1 可重复

同一份 JD + 同一份简历，跑 100 次结果必须完全一致。

> 理由：如果结果会变，我就无法判断"分数变高"是因为我补了技能，还是因为系统随机。

### AC-2 能溯源

任何一个"缺失"判定，都必须能定位到 JD 里的某一句原话。
任何一个"已具备"判定，都必须能定位到简历里的某一句原话。

> 理由：我不能接受一个我说不清理由的分数。面试官问我"你凭什么觉得自己匹配"，
> 我需要答案。

### AC-3 单调性

我在简历里多加一条**相关**经历，分数不许下降。

> 理由：这条是我用来检验"它是不是真的在看内容"的。如果加内容反而降分，说明算法有 bug。
> （后来陈屿告诉我这条在数学上叫单调性，还写成了测试。我原本只是觉得"这不合理"。）

### AC-4 不能一票否决

某一项完全不会，不能直接判 0 分。

> 理由：我不会 Java，但我投的是商业分析岗，JD 里提一句 Java 不该让我总分归零。
> 反过来，一个岗位也不会因为我某项满分就要我。
> **权重应该决定影响大小，而不是决定生死。**

### AC-5 加分项要降权

JD 里"有 XX 者优先""加分项"这类段落里的要求，权重必须明显低于"任职要求"段。

> 理由：我统计过自己投的 20 条 JD，"优先"那一段的要求平均只覆盖真实工作内容的
> 一小部分。如果加分项和硬要求同权，会把"加分项齐全但硬门槛不达标"的人排到前面。

### AC-6 不许编造

如果我的简历里没有证据，就输出"缺失"，不许用"可能具备""相关经验丰富"这种模糊话。

> 理由：这个工具的价值就是敢说"你没有"。说不出口就没用了。

### AC-7 报告能单独发出去

生成的报告要是一个文件，双击能看，能直接发给我导员或者贴在群里。

> 理由：我不想为了展示一个结果，要求别人去装 Python。
> （陈屿说这条他一开始没想到，他本来打算做一个网页服务。）

## 4. 明确不做的事

写清楚不做什么，比写清楚做什么更重要。

| 不做 | 原因 |
|---|---|
| 不用它自动筛别人的简历 | 它不处理"未使用过 Python"这种否定句，会误杀。只能用于自己投递前自查 |
| 不做语义相似度（如「经营分析」≈「商业洞察」） | 需要 embedding 模型，会引入不可解释性，与 AC-2 冲突 |
| 不抓取招聘网站数据 | 合规风险，且我不想让项目依赖外部接口的稳定性 |
| 不做 Web 服务 / 登录 / 数据库 | 我的使用场景是本地跑一次，不需要 |
| 不给"改简历"建议 | 那是另一个问题（怎么写），不是这个工具的问题（够不够） |

## 5. 我和陈屿怎么分工（写在这里是为了后面吵架时有依据）

| 事项 | 谁定 | 谁做 |
|---|---|---|
| 6 个域、44 个标签、每个标签的关键词 | 我 | 我写内容，陈屿把它变成代码里的数据结构 |
| 每个标签的默认权重 | 我 | 我 |
| 打分公式的形态（乘法/加权/阈值） | 陈屿 | 陈屿 |
| 覆盖系数取 0/1 还是分档 | 我坚持分档 | 陈屿实现 |
| 加分项降权系数具体取多少 | 我（0.5） | 陈屿实现 |
| 代码结构、测试、打包 | 陈屿 | 陈屿 |
| 样例 JD 的标注 | 我 | 我 |
| 分数是否合理（业务判断） | **只能是我** | — |

最后一行是重点。陈屿能验证代码有没有 bug，但**他无法判断一个分数对工商管理背景的人
是否合理**——他不知道"读财报"对我是基本功，也不知道"竞品分析"和"行业研究"在实际
工作里是不是一回事。

反之我也无法判断"为什么 Python 会被两个标签同时命中"。

这就是为什么这件事一个人做不成。
