# 权重校准口径

> 撰写：JingXueQing ｜ 审定：ChenYu（只审"能不能实现"，不改业务判断）
> 这份文件的用途：任何人质疑"为什么某个标签权重是 0.65 而不是 0.8"，答案在这里。

---

## 一、weight_default 是什么，不是什么

**是**：这个能力在"校园招聘"这个特定语境下的**普遍重要性**。
测量方式是：我把手上的 24 条样例 JD 逐条读一遍，对每个标签问
"如果候选人这项完全空白，我还会给他面试机会吗？"

- 一定会给 → 0.80–1.00
- 大概率会给 → 0.65–0.80
- 看岗位而定 → 0.50–0.65
- 基本不影响 → 0.40–0.50

**不是**：某个具体岗位的重要性。岗位专属强度由程序按"出现次数 × 段落位置"动态计算，
不写在权重表里。这一点很关键——如果给每个岗位单独调权重，44 个标签 × 24 个岗位
就是 1000 多个数字，没人维护得住，也无法解释。

## 二、为什么最高只到 0.85，没有 1.00

代码里最重的是 `ENG01 Python 编程` 0.85 和 `PRD01 需求分析` 0.80。

没有设 1.00 的理由：**AC-4 要求不能一票否决**。
一旦出现 1.00，在归一化之后它就会占据过大份额，实质上变成"这项不会就别投了"。
而我见过的真实情况是：不会 Python 的人照样能做商业分析，不会需求分析的人
照样能做好数据岗。所以留出上限，让"多项齐备"永远能赢过"单项满分"。

## 三、几个需要单独解释的权重

### BIZ03 财务与报表 = 0.65（而不是 0.80）

直觉上财务很重要，但这 24 条 JD 里真正要求"能读财报"的只有 6 条（财务/审计/投后），
占 25%。给到 0.80 会让所有非财务岗的分数被无关项拖低。

**这条权重是我最后悔给低了的一条**：改 alias 的时候发现，分数偏低不是权重的问题，
是关键词没覆盖到。教训是"分数不对时先怀疑词表，再怀疑权重"。

### ENG05 算法与数据结构 = 0.70

只对技术岗有意义，但我没有把它的权重压到 0.50，理由是：
在 3 条技术岗 JD 里它出现了 3 次，按次数增益算上去之后自然会被放大。
**用动态增益处理岗位差异，比用手调权重更可维护。**

### COM05 抗压与节奏 = 0.45

给的是最低档。原因不是"抗压不重要"，而是：**JD 里写"抗压"的信息量几乎为零**。
凡是写这句话的岗位都累，不写的人也累。它对区分岗位没有作用，
但完全删掉又不合适（有些岗位确实会明确写"高强度出差"），所以留一个低权重。

### TOL01 办公套件 = 0.45 / TOL02 协作工具 = 0.40

这两类是所有岗位的入场券，不构成区分度。给低权重是为了避免
"Excel 熟练"这四个字把整份简历的分数抬起来。

**但 TOL01 有一个副作用我没预料到**：PPT 被算作"办公套件"，
导致"能写方案、能做汇报"这类能力被归到了工具域而不是沟通域。
这是当前体系的一个真实缺陷，记录在此，不在这一版修（见 AAR 的"已知问题"）。

## 四、覆盖系数为什么是 0 / 0.85 / 1.0

这是我坚持的，陈屿原本建议用 0 / 1（二值）。

我的理由：校园简历里，"上过一门课"和"做过一个项目"在文本上都只出现一次，
二值化会把二者等同。而"做过项目"的人通常会在这份简历里**反复提到**相关的事
（比如我的简历里"数据透视"出现了两次、"SQL 取数"出现了两次）。

所以：

- 出现 1 次 = 0.85：他提到了，但只有一处佐证
- 出现 ≥2 次 = 1.00：多处出现，说明这是他真正做过的事

**为什么不干脆 0 / 0.5 / 1.0**：0.5 太重了。一个只写了一次 SQL 的人，
可能只是在课程作业里碰过，直接砍一半对他不公平。而 0.85 保留了"我认你，
但我不完全信"的态度，这是我想要的语气。

## 五、加分项系数为什么是 0.5

我人工核对了 24 条 JD 的"加分/优先"段落，做了个粗略统计：

| JD 类型 | 加分项条数 | 加分项中"任职要求"里没提过的 | 占比 |
|---|---|---|---|
| 技术岗（3 条） | 3 | 3 | 100% |
| 数据/分析岗（6 条） | 8 | 5 | 63% |
| 运营/产品岗（8 条） | 11 | 6 | 55% |
| 财务/HR 岗（7 条） | 7 | 3 | 43% |

加分项里有 40–60% 是"额外的东西"。如果给 1.0，一个"加分项全中但硬门槛缺两项"的人
会排到"硬门槛全中但没有加分项"的人前面——这在真实招聘里是反的。

0.5 是折中：让加分项能拉开差距，但不能翻盘。

## 六、硬缺口阈值为什么是 0.08

硬缺口 = 归一化权重 ≥ 8% 且必需项完全未命中。

8% 这个数的来源：一条 JD 平均命中 8–12 个标签，均分权重约 8–12%。
所以阈值设在均值附近，意思是"**这条要求的权重高于平均，而你没有**"。

设成 0.15 会只报最狠的一两条，漏掉真正的问题；设成 0.03 会报出七八条，
用户会觉得"我怎么什么都不行"，然后关掉工具。

## 七、我没法校准的部分（诚实记录）

1. **没有真实标注集**。我没有 200 份"已知是否通过简历关"的样本，
   所以所有阈值都是基于 24 条 JD 的人工判断，不是统计最优。
   这意味着：**这套权重的可信度上限，就是我的判断力上限。**
2. **无法验证预测准确率**。工具说的是"文本匹配度"，不是"录取概率"。
   我没法证明匹配度高的人更容易过简历关——那是另一个需要长期跟踪的实验。
3. **行业偏差**。24 条 JD 全都来自我关注的消费品 / 互联网 / 财务方向。
   制造业、国企、医疗的岗位用词我没覆盖，分数可能系统性偏低。
