### 轮次 6 —— 定主方向 + 提原创点（22:02）
**我的判断（人）**：主方向选**评估侧滑窗**，不是题目建议的 tokenizer。理由：收益最大、成本为零、风险最低，且成本低到"失败也赔得起"。
**我的创意（人）**：读到 SOTA 用"17 虚拟层 / 11 物理层"时想到——**参数共享意味着"展开几次"是零字节代价的旋钮**，而固定深度训练把这个旋钮焊死了。于是提出：
- **SRD**：训练时随机采样展开次数，降低深度敏感度；
- **TTDS**：评估时加深展开，只花评估预算。
**AI 补的**：合法性论证（训练/评估是两个独立 600s 预算）、风险 R3（train/test 失配）、以及"两者必须成对、SRD 是保险费"的表述。
**AI 提的反对意见（我采纳了）**：TTDS 的 train/test 失配是最高风险，历史上这类做法几乎都失败 → 我在先验登记里把 H3 写成"预期明显变差"，而不是乐观。

### 轮次 7 —— 写训练脚本第一版（22:05）

包含：SP8192/byte 双 tokenizer、ShuffledSequenceLoader、11L×512d GQA + Partial RoPE + QK-Gain + 并行残差 + U-Net skip gate、深度递归 + SRD/TTDS、MuonEq-R + AdamW、EMA、GPTQ(SDClip)、字节重排 + Brotli、滑窗评估 + Legal TTT、artifact 断言、smoke mode。

### 轮次 8 —— 自查（22:12）★ 最有价值的一轮
**我要求**：不要只说"写完了"，把你自己能找出的 bug 列出来。
**AI 自查出的 6 个问题**（全部真实修复，可 `git diff` 核对）：

| # | 问题 | 严重度 | 修复 |
|---|---|---|---|
| 1 | `MLP.forward` 依赖外部注入的 `self._cfg`，模块无法独立构造 | 中 | `cfg` 移进 `__init__` |
| 2 | 并行残差分支写成 `self.mlp(self.norm2(x) if False else h)` —— 死代码，且语义错误（MLP 读的是 attention 的 norm） | 高 | 改成 `x + attn(norm1(x)) + mlp(norm2(x))` |
| 3 | `_dequantize` 的 1D 分支表达式错误 | 中 | 统一为 `q * scale.unsqueeze(-1)` |
| 4 | **`eval_sliding` 里取 NLL 的那行是乱码**：`-lp[sel[0],sel[1], tgt[1:][sel[0],sel[1]]*0 + tgt[sel]]` | **致命** | 改为 `nll_all = -lp.gather(-1, tgt.clamp_min(0).unsqueeze(-1))` 再用 mask 取 |
| 5 | `_windows` 的尾部处理会让部分 token 未被打分，且打分区间不连续 | 高 | 重写为"按 end 枚举窗口 + 尾部补丁窗口"，并在 docstring 里写 correctness contract（**每个 token 恰好打一次分**） |
| 6 | **TTT 的分子用"已打分 token 的 nats"，分母却用"整个 chunk 的字节数"** | **致命** | 让 `eval_sliding` 返回 `scored_bytes`，分子分母覆盖同一批 token |

**为什么这轮最有价值**：第 4 条会让代码直接崩；第 6 条正是我在文档里警告别人的那个 bug——**分子分母覆盖不同 token 集合，会凭空产生虚假增益**。我自己写的第一版就踩了。这条我原样写进了日志和消融报告，作为"为什么必须写独立校验器"的实证。

### 轮次 10 —— 尝试本机验证（22:50 起，反复失败）
**失败链（全部真实）**：
1. `cd ~/Desktop/... && python ...` → **SIGTERM**。反复测试发现：**只要在该目录下执行任何命令（连 `echo` 都被杀）** → 判定沙箱禁止在个人目录执行程序。
2. 换到工作区目录重跑 → 仍 SIGTERM。
3. 后台任务返回：`cd: no such file or directory` → 之前的 `mkdir` 因被杀根本没建成。
4. 系统体检（后台，耗时 4m55s 才返回一条 `echo`）：`Pages free: 3059`（×16KB ≈ **仅约 50 MB 空闲内存**），load 1.74 → **机器处于严重内存压力 / 大量换页**，前台命令全部超时被杀。
5. `mkdir` 后台任务返回：`Brokered host mkdir requires an available runtime file rulemade` → 沙箱不允许创建目录。

**结论**：**本机执行路径被环境彻底堵死**（沙箱 + 内存双重限制）。
**我的决定**：**停止尝试，不伪造日志。** 转而在所有文档里明确标注"未执行"，并把"验证步骤"写成拿到算力后的第一步。

### 轮次 12 —— ★ 真机跑通，又抓出 3 个 bug（23:26 → 23:38）

**第一次跑（3 seed 全部同一处崩溃）**：
```
RuntimeError: The size of tensor a (4) must match the size of tensor b (2)
  at F.scaled_dot_product_attention
```
**根因**：`_repeat_kv`（GQA 的 KV 头复制）被我放在 `transpose(1,2)` **之后**调用。它在 `(b,n_kv,T,d)` 上做 `reshape` 成 `(b,n_kv,T*reps,d)`，静默产出错误形状。**这是 `py_compile` 永远抓不到、只有真跑才暴露的类型错误。**

**第二次跑（3 seed 全部同一处崩溃）**：
```
IndexError: list index out of range   at h = h + g * acts[j]
```
**根因**：U-Net 跳跃连接写成了"第 i 层去读第 n−1−i 层的激活"，而那个激活**还没算出来**。语义也错了——U-Net 应该是**后半段读前半段**。改成 `j = n-1-i; if j < i` 才对。

**第三次跑（23:35–23:38）：3 个 seed 全部成功，拿到真实数据。**

| seed | pre-quant BPB | post-quant BPB | ΔTTDS | artifact |
|---:|---:|---:|---:|---:|
| 42 | 3.713073 | 3.719371 | **+0.055072** | 397,253 B |
| 0 | 3.821949 | 3.837830 | **+0.067168** | 397,967 B |
| 1234 | 3.788499 | 3.799250 | **+0.097174** | 396,919 B |

**第 3 个 bug（不崩但危险）**：原先用 `step / 20000` 判断递归启用时机，在 600 s 上限下步数是不确定的（本跑只有 40 步），导致 `recur_start_frac` 形同虚设。已改成用**已用 wallclock 比例**判断——10 分钟约束下 wallclock 才是真正的稀缺资源，用它当时钟才诚实。

**这轮给我的教训**：`py_compile` 只能证明"语法对"，证明不了"能对"。**3 个 bug 全部是运行期才暴露的，而且两个是静默的形状/语义错误。** 我在交付里写了 700 行训练代码却只做过语法检查，如果就这样交出去，拿到算力券的第一跑必然崩溃 —— 那就烧掉了 1/7 预算。

| F7 | **只做 `py_compile` 就以为代码能跑** | 语法检查抓不到形状/语义错误 | **差点把 700 行没跑过的代码交上去** —— 拿到券的第一跑必崩，烧掉 1/7 预算 | **训练脚本必须至少跑通一次 tiny smoke**，哪怕只有 40 步 |
| F8 | GQA 的 `_repeat_kv` 在 transpose 之后调用 | 我把布局顺序搞反了 | 3 seed 全崩 | 已在函数 docstring 里写死"必须在 (b,T,H,D) 布局下、transpose 之前调用" |

## 4. 我对这次 AI 协作的诚实评价

**AI 真正帮到我的地方（不可替代）：**
1. **把 33 条记录变成可计算的数据**——我自己不会去做这个解析，而它直接决定了主方向的选择。这是本轮最大杠杆。
2. **从 5 份 README 里抽出可引用的原句和数字**——尤其是发现"pre-quant BPB 几乎不变"这个决定性证据。
3. **自查出 6 个 bug**，其中两个是致命的。

**AI 没做到 / 我不敢信的地方：**
1. **它给不出 BPB 的实际数字**——因为它也跑不了。所有"预期值"都是推理，不是事实。我一律标 `[未测]`。
2. **它倾向于乐观**。在讨论 TTDS 时，AI 最初的措辞是"应该能带来改善"。是我要求它给出反对意见，它才列出 train/test 失配的风险。→ **教训：必须显式要求 AI 给反对意见，否则它会顺着你的思路走。**

**我做的最重要的两个决定，都不是 AI 给的：**
1. 主方向选评估侧（AI 给了数据，选它是我的判断）；
2. **不填未实测的 BPB**（AI 不会主动坚持这个，是我在每份文档里强制的口径）。

第 2 条我认为是本次交付的核心。在一个"分数就是一切"的排行榜挑战里，**主动交白卷需要理由**——我的理由是：一个编出来的 1.08 能骗过评审一天，但骗不过任何人重跑一次；而这套方案本身的价值不受影响。
