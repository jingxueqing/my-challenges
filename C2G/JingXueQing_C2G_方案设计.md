## 1. 技术选型

### 1.1 底座：为什么直接站在 PR #1394 而不是从 nanoGPT 起步

官方把 Parameter Golf 定义成一个 **L(N) 优化问题**（固定参数量 N，最小化 loss）。这意味着「架构 + 量化 + 评估」是一个整体，**任何一环落后都会拖垮全局**。从 nanoGPT 裸起步，等于要自己重新走完 33 条记录里别人已经验证过的 22 步。

所以我选 **PR #1394（@clarkkev，1.08563）作为底座**，理由：

1. 它的 README 是全部记录里**理论最完整**的一份，把「量化 bitwidth / clip 范围 / 压缩后熵」的关系写成了可推导的公式（`H(q) ≈ b − log₂k + const`），让我能预判改动后果，而不是盲调；
2. 它之后的 4 条 SOTA（1.0835 / 1.0828 / 1.0822 / 1.0810）**全部是在它之上的增量**，说明它是稳定的公共地基；
3. 它把量化 clip 从「搜索重构误差」改成 `c = k·std(row)`，使 artifact 大小**单调可控**（k 越大越小），这对 16MB 硬约束是决定性的工程优势。

## 2. 我的两个原创点

### 2.1 观察：现有深度递归有一个结构性浪费

PR #1437 的 3 层递归把 11 个物理层展开成 17 个虚拟层。参数是共享的，**所以"展开几次"其实是一个免费的旋钮**——多展开一次不增加任何一个字节的 artifact。

但现有做法把训练时的展开次数写死成 2。这带来两个后果：

- 模型只被优化到"深度 = 2 次展开"这一个工作点，**在其他深度上不一定好用**；
- 于是"评估时多展开几次"这条路被堵死了——因为训练没见过，直接加深大概率崩。

换句话说：**一个免费的旋钮，被训练方式焊死了。**

### 2.2 [1] SRD —— Stochastic Recurrence Depth

**改动**：训练时每一步随机采样展开次数 `extra ∈ {1, 2}`（在第 35% 训练进度后启用；前 35% 用 `extra=0` 先让 11 层基础栈稳定）。

**为什么可行**：这不是新发明，是把 **stochastic depth / LayerDrop** 的思路从"随机丢层"搬到"随机加深"。递归块的参数本来就在多个深度上被共享，随机化展开次数等价于对这个共享块做深度上的期望优化：

$$\mathcal{L} = \mathbb{E}_{d \sim \mathcal{U}\{1,2\}}\big[\mathcal{L}_d(\theta)\big]$$

结果是同一个 θ 在 d=1 和 d=2 下都被优化过，**对深度的敏感度下降**。

**代价**：几乎为零。不增加参数、不增加 artifact 字节、单步计算量期望只增加约 1.5/2 → 约 +25% 的递归块计算（递归块只占 3/11 层，整体 step time 预计 +5~8%）。10 分钟预算下这需要用 `MAX_WALLCLOCK_SECONDS` 实测兜住。

**风险**：平均深度下降可能损害最终 BPB（因为一半的步数只用了 14 虚拟层而非 17）。**这是我设计的第一个要验的负风险**，消融 C1 vs D0 就是专门测它的。

### 2.3 [2] TTDS —— Test-Time Depth Scaling

**改动**：评估时把展开次数从 2 提到 3（虚拟层 17 → 20），**只改评估，不改权重、不改 artifact**。

**为什么这是合法的**：
- 参数完全不变 → artifact 字节数不变，不触碰 16MB；
- 不吃训练预算 → 训练仍是 600s；
- 只花**评估预算** → 官方 README 明确训练 10 分钟和评估 10 分钟是**两个独立上限**。当前 SOTA 评估只用约 500s / 600s，还有余量；
- 满足 Issue #1017 全部四条：因果（严格前缀）、归一化分布（标准 softmax）、先打分后更新、单遍（每个 token 只打一次分）。

**为什么我觉得它可能有用**：OpenAI 在 README 里明确把这个挑战的期望方向包含 "test-time compute"。TTT 已经在**横向**（用更多 token 做适应）上验证了收益（−0.002 ~ −0.0021）。TTDS 是在**纵向**（用更多深度）上做同样的事。递归块的存在让纵向扩展的参数代价为 0——这是 TTT 没有的结构优势。

**SRD 和 TTDS 是成对设计的**：单独上 TTDS（训练固定 d=2、评估 d=3）会 train/test 深度失配，大概率变差；SRD 的存在就是为了让 d=3 落在模型"见过的深度分布的外推区"而不是"完全陌生区"。

**所以我的核心假设是**：

> H1：SRD 单独会让 BPB **略微变差**（−0.001 ~ +0.003）；
> H2：SRD + TTDS 组合会**净变好**，且幅度大于单独 TTDS；
> H3：单独 TTDS（无 SRD）会**明显变差**。

三条假设里 H1 是"我愿意付出代价"的预测。**如果 H1 不成立而 H2 成立，那更好；如果 H1 成立而 H2 不成立，我的原创点就算失败，我会照实写。**

### 2.4 备选原创点（如果 SRD/TTDS 失败）

- **TTDS + 深度感知的 logit softcap**：展开变深后 logits 尺度会漂，softcap 可以随虚拟深度调整。零参数代价。
- **TTDS 分层调度**：只对"高熵 token"（模型不确定的位置）用深展开，其余用浅展开，把评估预算花在刀刃上。需要一次额外的 no-grad 打分来确定熵——但那会破坏单遍原则，**需要先确认合规性**，若不确定就不做。

## 4. 统计口径

- 每个正式配置 **3 个独立 seed**：0 / 42 / 1234（与 PR #1413 一致，便于横向对照）。
- 报告 **mean ± std**。
- 申报新纪录需满足官方两条：**Δ ≥ 0.005 nats** 且 **p < 0.01**（配对 t 检验，3 seed）。
- **3 seed 的 std 参考量级**：SOTA 记录报的是 **std ≈ 0.0002** `[引用: 2026-04-09...README.md]`。如果我的 std 明显大于 0.001，说明我的实验有非受控变量（比如数据顺序没固定、EMA 未收敛），先修再报。
- **禁止用验证集调超参。** 超参在 Stage A/B 用 train loss + 固定的 1/10 held-out 训练分片决定；val 只在 Stage C/D 的最终确认时看。

## 7. 作者对本文的自评

我最不确定的是 **R3（TTDS 的 train/test 深度失配）**。历史上"训练一个条件、推理另一个条件"几乎总是失败的，我唯一的对冲是 SRD，而 SRD 本身也有可能损害 BPB（R2）。

**所以 D3 这一格有相当概率是负结果。** 我提前说清楚：如果 D3 是负的，我会把 D1/D2/D3 三条曲线原样交出来，作为"深度递归在评估时不可扩展"的一条证据。这条负结果本身就是有价值的——它告诉后来者"这个免费旋钮焊死是有原因的"，能省下别人几十小时的 GPU。

反过来，我最有信心的是 **Stage A**。它有公开实测、机制清晰、成本为零、失败也可控。Level 2 是我在现有信息下能给出的最可靠的承诺。
