# 公众号发布 SOP：从一个 Markdown 文件到一篇已发布的文章

> 本 SOP 是 C4B Level 4 的交付内容。假设你已安装 `wechat-publisher-pro` 技能。

---

## 阶段 0：准备（3 分钟）

确认环境：

```bash
python -c "import markdown, bs4, docx, lxml, pygments; print('deps ok')"
# 若报错
python -m pip install markdown beautifulsoup4 python-docx lxml pygments
```

建议用虚拟环境，避免污染系统 Python：

```bash
python -m venv .venv && source .venv/bin/activate
```

---

## 阶段 1：写稿（AI 辅助，10–30 分钟）

在 Markdown 文件**开头**写 frontmatter：

```yaml
---
title: 我把公众号发布做成了一个技能
author: JingXueQing
date: 2026-10-05
tags: AI, 技能开发, 效率工具
abstract: 一句话说清读者能得到什么。写摘要时假设读者只看这一行。
cover: cover.png
---
```

写作要点（针对公众号阅读场景）：

| 要素 | 建议 |
|------|------|
| 标题 | ≤ 30 字，含具体收益或反差；别用"浅谈""初探" |
| 摘要 | 40–80 字，写**读者能得到什么**，不是"本文介绍了…" |
| 开头 | 前 3 行决定是否继续读，直接给结论或冲突 |
| 小标题 | 每 300–500 字一个，用 `##`，读者靠它导航 |
| 段落 | ≤ 4 行/段，手机上 4 行以上会显得压抑 |
| 代码 | 必须标语言，才能语法高亮 |
| 结尾 | 给明确的下一步动作，不要"希望对你有帮助" |

---

## 阶段 2：转换（1 分钟）

```bash
python scripts/wechat_publisher.py article.md out.html \
    --theme ink --toc --footer --preview phone
```

参数怎么选：

| 场景 | 推荐参数 |
|------|----------|
| 技术教程 / 长文（>3000 字） | `--toc --footer` |
| 经验分享 / 故事 | `--theme amber --footer` |
| 学术 / 报告 | `--theme mono --toc` |
| 图文为主、代码少 | `--theme forest --no-number` |
| 交作业/截图留证 | 加 `--preview phone` |

产出两个文件：

- `out.html` —— 预览页，**只复制白框内正文**
- `out.body.html` —— 纯正文，适合直接全选复制

---

## 阶段 3：自查（2 分钟）

```bash
python scripts/wechat_publisher.py article.md --audit
```

必须做到 **0 高危** 才能往下走。中危项（如外链图片）逐条判断：

- `IMG_EXT` 外链图片 → 打开输出 HTML，确认图片能显示；不能显示就换 base64 内嵌
- `LEN` 超长 → 拆成上下篇

**人工检查清单**（自动化查不出来的）：

- [ ] 标题栏字数是否超 30 字（超了微信会截断）
- [ ] 手机预览时表格是否拥挤（≥5 列建议拆表）
- [ ] 代码块横向是否溢出（长行考虑手动折行）
- [ ] 目录里的标题是否都存在（编号有无重复）
- [ ] 全文搜索一遍 `class=` `id=` `position:`，确认没漏网的

## 阶段 4：发布（5 分钟）

1. 登录 <https://mp.weixin.qq.com> → 左侧「内容管理」→「草稿箱」→「新建图文」
2. **标题栏**：粘贴 frontmatter 的 `title`
3. **作者栏**：粘贴 `author`
4. **封面**：上传 `cover` 对应的图（建议 900×383，2.35:1）
5. **正文区**：打开 `out.body.html` → 全选复制 → 粘贴到正文
6. 粘贴后**检查这几处**（粘贴过程可能触发微信的样式重写）：
   - 代码块是否还是等宽底色
   - callout 框的左侧色条是否还在
   - 表格边框是否完整
   - 图片是否显示
7. 填**摘要**栏（粘贴 frontmatter 的 `abstract`）
8. 选择**封面**（可从正文里选一张图裁剪）
9. 「预览」发到自己的微信，在手机上**逐屏翻一遍**
10. 确认无误 → 「群发」或「发布」

:::warn 粘贴后必查
微信粘贴时会重写部分样式。最容易掉的是：`<hr>` 分隔线、表格内边距、
以及 `white-space:pre-wrap` 的代码块缩进。缩进若丢了，微信会按普通段落折叠——
此时需要重新粘贴 `out.body.html`，或把代码改成图片。
:::

## 阶段 5：传播（Level 4 要求）

### 渠道矩阵

| 渠道 | 做法 | 适用 |
|------|------|------|
| 挑战群 | 发链接 + 一句话导语 | 必做 |
| 朋友圈 | 截图卡片 + 钩子文案 | 建议 |
| 微信群/相关技术社区 | 侧重方法论而非成果 | 选做 |
| 知乎/掘金 | 同一 Markdown 改标题重发 | 选做 |

### 数据追踪

发布后 48 小时记录：

| 指标 | 在哪看 | 说明什么 |
|------|--------|----------|
| 阅读量 | 公众号后台「内容分析」 | 标题+封面是否有效 |
| 分享次数 | 同上 | 内容是否有传播价值 |
| 收藏率 | 同上 | 是否有工具价值 |
| 在看/点赞 | 正文底部 | 内容认同度 |
| 新增关注 | 「用户分析」 | 是否建立个人品牌 |

建议记录模板：

```
文章标题：
发布时间：
24h 阅读 / 分享 / 收藏：
48h 阅读 / 分享 / 收藏：
带来的新增关注：
复盘（哪一步有效/无效）：
```

### 互动设计（让读者留言）

在文章里**埋一个具体问题**，比"欢迎留言"有效得多：

- ❌ "欢迎留言讨论"
- ✅ "你用 skill 做过什么？踩过哪些坑？我把踩坑都写进第 3 节了"
- ✅ "第 4 节那个自动体检脚本，需要的话评论区扣 1，我发出来"

## 阶段 6：复用

同一篇 Markdown 可低成本产出多平台版本：

| 平台 | 改法 |
|------|------|
| 知乎 | 去掉 callout 标记，保留标题层级；补参考文献 |
| 掘金 | 同上；代码块加语言标注 |
| 纯文本 | 直接读 `.md` |
| 朋友圈 | 抽 3 句话 + 封面图 |

**一次写作，多次分发**——这是本技能真正的价值所在。

## 附：常见问题

**Q：粘贴后格式全乱？**
A：99% 是复制了 `out.html` 的外壳。请复制 `out.body.html`，或只选预览页白框内内容。

**Q：图片粘贴后不显示？**
A：外链图被微信拒收。改用 base64 内嵌（把图放在 md 同级目录，用相对路径引用）。

**Q：代码块缩进没了？**
A：微信对 `white-space:pre-wrap` 支持不稳定。改用图片，或把代码块缩短。

**Q：表格手机端挤成一团？**
A：列数 ≥5 时按 `---` 拆成两张表，或把表格转成列表。

**Q：目录点不动？**
A：公众号剥离 `id` 锚点，这是平台限制。在微信编辑器里手动给标题加「书签」链接。

**Q：字数超了？**
A：`--audit` 会提示。按主题拆成上下篇，标题做成「上篇/下篇」。
