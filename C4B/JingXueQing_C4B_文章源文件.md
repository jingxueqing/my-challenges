上个月我接了个活：把一份技术文档发到公众号。

文档是 Markdown 写的，我随手搜了个转换工具，三十秒生成 HTML，粘贴进编辑器——

排版全乱。代码块挤成一行，加粗里的链接消失，分隔线没了，本地图片裂成一片碎图。

那天我意识到：**"能跑通"和"能用"之间，隔着一整个测试套件的距离。**

这篇文章讲我做了什么，以及那些坑具体长什么样。

## 一、先说清楚：这不是教程，是一次翻车实录

网上讲"如何做公众号排版工具"的文章很多，思路无非是：解析 Markdown → 套 CSS → 输出。

但真正花时间的从来不是这三步，而是**你不知道输出会在哪里悄悄坏掉**。

官方给了个 starter kit，代码 380 行，注释写得很清楚，能力清单列了 5 条，看起来完备。我照着跑，示例文章转出来确实像模像样。

于是我差点就交了。

:::warn 先说结论
如果我按示例文章交作业，评分会很难看——因为示例文章里根本没有能暴露那些缺陷的内容。
**验证工具，必须用它最擅长的场景去攻击它。**
:::

所以我先干了一件笨事：写一份"什么坑都踩一遍"的探针文档。

它长这样（为便于阅读，标签已转义显示）：

> 段落里有 `inline code` 和 **加粗** 和 *斜体*，还有 一个 div 标签包住内容。
>
> 这段加粗里嵌套了 `代码` 和 [链接](https://example.com)。
>
> 引用块第一段有 `code`。
> 引用块第二段。

外加一个带语言标注的代码块、一个多段引用、一个三列表格、
一张本地图片、一个 SVG、一条分隔线——共 13 种边界情况。

然后我用 starter 跑它。

## 二、12 个缺陷，5 个是致命的

结果比我预想的糟。**12 个缺陷里有 5 个会直接毁掉内容。**

### 致命级：内容直接丢失

**① 代码块的换行被吞成一行**

starter 用 `p.string = code_text` 赋值。BeautifulSoup 认为字符串就是字符串，**换行符在 HTML 语义里等于空格**。结果就是一段 6 行代码，粘过去变成一长条。

缩进也一起没了。这对技术文章是致命的——缩进就是语义。

**② 加粗里的行内代码和链接会凭空消失**

```python
tag.string = tag.get_text()   # ← 这一行是元凶
```

`get_text()` 把子节点全部拍平成纯文本。所以 `**粗体里有 `代码` 和 [链接](url)**` 转出来只剩"粗体里有 代码 和 链接"——链接的 `href` 整个不见了。

我一开始以为是 markdown 库的问题，排查了半天才定位到这一行。**批处理式的"提取文本再赋值"，是 BeautifulSoup 最容易踩的陷阱。**

**③ 多段引用块被合并成一段**

同一个 `get_text()` 病灶。`> 第一段\n>\n> 第二段` 出来变成一段连续文字，段落感全无。

**④ `<hr>` 分隔线被整体丢弃**

starter 的 `ALLOWED_TAGS` 里没有 `hr`，而清理逻辑是"不在白名单就 `unwrap()`"——`hr` 没有子节点，`unwrap()` 等于删除。文章里的章节分隔线全没了。

**⑤ 内联 div 标签把段落从中间劈开**

markdown 库看到内联 div 标签会认为开启了块级元素，于是把段落截断。原文"前文+div标签+内容+div标签+后文"变成三个孤立段落，`。` 被甩到单独一行。

### 严重级：能看，但很难看

| # | 缺陷 | 后果 |
|---|------|------|
| ⑥ | 图片没有 `max-width` | 手机端横向溢出 |
| ⑦ | 本地图片保留相对路径 `assets/x.png` | 粘贴后 100% 裂图 |
| ⑧ | 嵌套列表被拍平成同级 | 层级信息丢失 |
| ⑨ | `<ul>`/`<ol>` 自身无样式 | 缩进完全失控 |
| ⑩ | 中英文之间零间距 | "用了Python开发" 挤成一团 |

第 ⑦ 条值得单独说：starter 的参考文档里明明白白写了"图片必须用 base64"，但**代码里根本没实现**。文档和实现脱节，这在 starter 里不止一处。

第 ⑩ 条不算 bug，算"没人做"。中文排版里中英文间距是排版基本功，starter 完全没有这个概念。

## 三、顺手发现的两个"假合规"

这两个不是内容 bug，但更值得警惕——**它让你以为安全了，实际没有。**

:::danger 假合规一：CSS 白名单是摆设
starter 定义了 `ALLOWED_CSS` 集合，列了 13 个属性。但 `clean_attributes()` 里从来没引用过它。

文档写着"filter non-allowed CSS properties"，代码里根本没这一步。写了不生效，比不写更危险。
:::

:::danger 假合规二：auto-install 会污染系统环境
`install_dependencies()` 在脚本开头自动执行，缺什么就 `pip install --break-system-packages`。

这意味着**你只是想转换一篇文章，它却擅自改动了你的 Python 环境**。在别人的机器上、在公司的开发机上，这是不能接受的行为。
:::

我改成了：检测到缺依赖就打印清晰的安装指引并退出，绝不擅自动手。

## 四、重写：从 380 行到 1200 行，但不是堆功能

改写分两层。

### 第一层：把 12 个缺陷变成 24 个测试用例

这是我做过的**最有价值的一步**。

我先给每个缺陷配一个最小复现样本，再写断言。不是"看起来对"，而是字符串级的硬判断：

```python
def t_code_block_newlines():
    body = _body_of("t02_code.md", [])
    code = _extract_code_block(body)
    return [
        ("代码块用 pre-wrap 保留换行", "white-space:pre-wrap" in body),
        ("保留第 2 行", "line_two" in code),
        ("缩进空格被保留", re.search(r"\n {4,}\S", code) is not None),
    ]
```

改一行代码，跑一次套件，**红灯变绿灯才是修好了**。没有测试的 bug 修复，本质上是在赌。

这套 eval 跑 24 个用例、117 条断言，20 秒跑完，可以直接挂 CI——有高危项时退出码是 1。

### 第二层：补上真正缺失的能力

| 能力 | 价值 | 难度 |
|------|------|------|
| Callout 提示框（5 种） | 公众号排版的性价比之王 | ★★ |
| 多主题（4 套配色） | 一条命令换风格 | ★★ |
| 自动目录卡片 | 长文导航 | ★★ |
| 本地图片 base64 内嵌 | 修 ⑦ 的根治方案 | ★★ |
| 中文排版间距 | 专业感来源 | ★★★ |
| 代码语法高亮 | 技术文章刚需 | ★★ |
| **合规体检器 `--audit`** | 见下 | ★★ |
| 批量转换 | 运营场景 | ★ |

#### 合规体检器是我最满意的设计

公众号的规则会变。与其我把规则写死在代码里，不如**提供一个能告诉你"哪里违规了"的工具**：

```bash
$ python scripts/wechat_publisher.py article.md --audit
  [高] TAG_DIV     残留 <div> ×3
       → 改用 <p>/<span> 承载样式
  [中] IMG_EXT     2 张图片不是 data: 或微信 CDN
       → 本地图用 base64 内嵌，或发布前传素材库
```

这解决了一个真实问题：**规则是知识，会过时；体检器是机制，不会过时。** 微信哪天改了规则，体检器照样能帮你定位。

我甚至给自己上了一道保险：它只扫 `style="..."` 属性内部，不扫全文。最初版本会误报——因为我的测试文章里正好有一句"内联样式 position:absolute 的文字"，纯正文，结果被当成 CSS 违规报出来了。**体检器自己也要被测试。**

## 五、我自己写错了 5 个 bug

这才是我想写出来的部分。

前四个 bug 是修出来的。这五个，是我在重写过程中**亲手造出来又被 eval 逮住的**。

:::danger 我犯的错一：h1 在错误的位置被降级
我把 `h1 → h2` 写在"清理非白名单标签"之后。可 `h1` 不在白名单里，于是它**先被 unwrap 成裸文本**，我那行降级代码根本匹配不到任何东西。

文章标题直接变成一行裸字，测试全绿——因为我的测试只查了"没有 h1 标签残留"，没查"标题还在不在"。

顺序错了：必须**先降级，再清理**。
:::

:::danger 我犯的错二：BeautifulSoup 会吃掉代码缩进
这个最隐蔽。我给代码块加了 `white-space: pre-wrap`，测试显示缩进保留了，就以为没问题了。

直到我把真实输出打印出来逐行看：

```html
<span>...<span>def</span>...\n    <span>return</span> a</span>
```

`line_two` 那行缩进还在，`return` 那行前面 4 个空格**消失了**。

根因很反直觉：BeautifulSoup 解析时，会**丢弃嵌套标签前面的空白**。它认为标签之间的空格是格式噪音。

修法是在解析前把缩进换成私有区字符（`U+E000`）占位，解析完再换回来：

```python
def protect_code_indent(code_html):
    code_html = re.sub(r"(\n)([ \t]+)",
                       lambda m: m.group(1) + m.group(2).replace(" ", "\ue000"),
                       code_html)
    return code_html
```

**如果我只写"输出看起来对"的测试，这个 bug 会一路带到线上。**
:::

:::danger 我犯的错三：lxml 给我塞了 html 和 body 外壳
Callout 我用一个带 class 的 div 占位标记，渲染完再替换。结果测试报"5 个 callout 一个都没生成"。

单独调试时 `select` 选择那个 class 的 div，明明能找到 5 个。差别在于——**单独调试时我用 `html.parser`，而主流程用 `lxml`**。

`lxml` 解析裸片段时会自动补上 html 加 body 的外壳。这段外壳被注入正文，整棵树就错位了。

修法：用 `html.parser` 解析裸片段，或者只取 `holder.contents` 而不是 `str(holder)`。
:::

:::danger 我犯的错四：计数器位置错了
标题编号 `1. / 1.1 / 2.`。我原来在遍历时对 h2 和 h3 都执行 `h2n += 1`，结果三个小节编成了 `1. / 2.1 / 3.`。

第二、三章的子节被算成"第 2 章第 1 节"，"第 3 章"——但全文根本没有第 3 章。
:::

:::danger 我犯的错五：把冒号当成了汉字
中文排版我加了个中英文自动间距。测试发现"整行div："变成了"整行div ："——**多了一个空格**。

原因是我把全角标点区间 `U+3000–U+303F` 也算进了"CJK 字符"。但全角标点本身就自带右侧间距，再加一次就重了。

`CJK = r"\u4e00-\u9fa5"`——只留纯汉字。**一个字符范围的边界，写错了就是排版事故。**
:::

## 六、给你的三条具体建议

:::key 建议一：验证工具，要攻击它
不要用它自带的示例测。写一份"把坑都踩一遍"的文档，比写十篇正常文档有用。
:::

:::key 建议二：先写测试，再修 bug
没有测试的修复是在赌。我有 5 个 bug 是在"看起来通过了"的自信里溜过去的，是 eval 套件把它们逼出来的。
:::

:::key 建议三：把知识变成机制
规则会过时。我把"记住公众号不许用 div"写成了"`--audit` 每次替你检查"。

**能被执行的规则才是活的规则，写在文档里的等着被人忘。**
:::

## 最后

这个技能最终是 1200 行代码 + 24 个测试用例 + 一份发布 SOP。

从 380 行的 starter 到这里，**新增功能其实只占一半工作量，另一半全花在修 bug 和写测试上**。

这个比例大概就是"工具能跑"和"工具能用"之间的距离。

如果你也在做类似的转换工具，欢迎用这份探针文档测一下你的实现——bug 清单我放在技能仓库的 `tests/fixtures/` 里了，直接复制就能跑。

也欢迎在评论区告诉我：你踩过哪些排版坑？我会把它们加进体检规则。
