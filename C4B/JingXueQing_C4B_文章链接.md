### 1.0.5 二次加固：代码块抗 CSS 剥离

首次发布后我扫描了全文的 26 种 CSS 属性，发现 4 个有风险：

| 属性 | 使用次数 | 风险 |
|------|---------|------|
| `word-break` | 107 | 可能剥离（但实测保留） |
| `letter-spacing` | 74 | 可能剥离（但实测保留） |
| `white-space` | 3 | **pre-wrap 支持不稳定** |
| `table-layout` | 2 | 可能剥离 |

`white-space: pre-wrap` 是**代码块换行的唯一依赖**——
一旦被剥离，代码会塌成一行。

因此新增 `--safe-code` 模式：换行改用显式 `<br />`（完全不依赖 CSS），
缩进用 `padding-left` + 不换行空格双保险。
**即使微信把三个相关 CSS 全剥离，代码结构依然完整。**

代价是放弃语法高亮（高亮 span 会被行边界切断）。
交付的 HTML 是 safe 版，另附高亮版供对比。

### 1.2 一个意外发现

线上版本里，文章正文中的 `<div>` 被微信**主动改写成了 `<span>`**。
说明微信编辑器对残留的 `<div>` 有自动降级机制——
但这个机制在我这个场景下反而**掩盖了我的 bug**：

我本该让读者看到"内联 `<div>` 会劈开段落"这个现象，
结果微信把它改成 `<span>`，读者看到的是一个**不存在的标签名**。

**这不是微信的错，是我的文章写得太"危险"**——
在一篇讲 HTML 标签的文章里，直接写 `<div>` 必然被编辑器改写。
正确做法是用 `&lt;div&gt;` 转义，或者放在代码块里（我后来确实这么处理了，但有一处漏了）。
