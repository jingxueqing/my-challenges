## 2. 三个没想到的困难

**困难一：字数红线比想象中硬得多。**
初稿 2170 字，超标 45%。我原本以为"删几段就行"，实际删到第 5 轮才压到 1499。
真正的教训是：**认知科学论证的密度和字数预算是天然冲突的**——每一条设计（feature/conjunction、
2×2 解耦、SDT、vigilance、change blindness）都值得展开，但 1500 字只够放结论。
最后我的取舍原则是：**砍"展开"，保"机制"**；凡是可以移交给《拿来说明》的（灵感来源清单、
局限说明、风险细节）一律移走。回头看，这个拆分其实让两份文件都更清楚了。

**困难二：C2A-guide.pdf 根本读不出来。**
pypdf 返回空、pdfminer 返回 2 个字符、内嵌图片全是几千字节的小图标——说明它是图形化排版而非文本 PDF。
我在这上面浪费了三轮尝试才判断"放弃解析"。**教训：资料包里给了 `challenge_spec.md` 这个等价物，
我应该在第一次解析失败时就转向它，而不是继续换工具。** 这属于典型的"工具层打转、目标层停滞"。

**困难三：原型跑通 ≠ 数字可信。**
首次冒烟时 `feature|sim=0.9` 在 N=32 出现 100% 正确率，而理论值是 77%。
如果我直接把这张表贴进 README，就会污染整个提案的可信度。
我花了额外两轮做无偏性诊断（20000 次采样实测 p=0.7695 vs 理论 0.77），确认是 n=20/格的小样本噪声，
然后把默认样本量提到 50/格。**教训：原型的第一版输出永远要当"可能有 bug"来处理，
尤其是当你本来就期待看到某个趋势的时候——确认偏误在这里最容易发作。**

## 3. 做得不够好的地方

1. **L2 / L3 只做到"生成器 + 评分函数"，没接进 CLI。** 提案里承诺了三条阶梯，代码里只跑通了一条。
   这在评审时是明确的风险点——如果有人照 README 跑，会发现 L2/L3 用不了。我已在 README 第 7 节
   如实列出未完成的 6 项，但**"诚实标注"不能替代"做完"**。

2. **2×2 解耦只实现了主条件（固定长度、变密度），对照条件（固定密度、变长度）没写。**
   而这恰恰是我在提案里宣称的"最核心的方法学创新"。代码层面目前撑不起这个主张。

3. **人类基线完全没做。** 提案里写了预期分布表和招募方案，但那都是**假设**，不是数据。
   DeepMind 三阶段协议的第 2 步（采集人类基线）目前是空头支票。

4. **相似度参数的实现比理论粗糙。** Duncan & Humphreys 讲的是"目标-干扰相似度"的连续维度，
   我实际实现的是"诱饵占比"这一个代理变量。两者相关但不等价，我应该在提案里把这个简化说清楚——
   目前写得有点像我直接实现了相似度连续体。

## 4. AI 在哪儿帮得最大，哪儿帮不上

**帮得最大的三处：**
1. **文献核验。** 5 轮检索让我拿到可引用的具体数值（Treisman 的 29/67 ms/item 斜率）
   和一个真正的对手（CDV 的 45% 掉幅）。靠记忆写几乎必然出现查无实据的引用。
2. **交叉比对结构化文件。** AI 把 `rubric.json` 和 `CHALLENGE.md` 对齐，发现了"还要交 AAR 和 benchmark"
   这个隐藏要求——这份 AAR 和原型就是这么来的。
3. **代码脚手架。** 四个 Python 模块一轮生成即可运行，省下的时间都花在了设计和验证上。

**帮不上、必须我介入的三处：**
1. **赛道选择。** AI 能列利弊，但"把注意力做成 ΔS 入口"这个赌注只能人下。
2. **概念建构。** ΔS 的定义、它与 ΔR 的区分、三类成因到三条阶梯的映射——AI 只能帮我润色，不能替我立论。
3. **判断数字不对。** AI 生成的代码能跑通，但"为什么 100% 而不是 77%"这个疑问必须人提出来。
   AI 倾向于为自己生成的输出辩护，这是我在协作中反复遇到、也反复需要对抗的一点。

## 5. 如果重来一次，我会怎么改

| 现在 | 改成 |
|---|---|
| 三条阶梯都写进提案，只实现一条 | **提案只承诺 L1，把 L2/L3 明确写成 v2 路线图。** 少承诺、多交付，评审反而更信 |
| 先写提案再补原型 | **先跑一个小规模预实验**（比如只测 1 个模型、2 个负荷档），用真实数据反推指标是否合理，再写提案 |
| 人类基线只给预期表 | **先找 5–8 个同学做预测试**，至少拿到"这个任务对人类是否过易"的经验判断，再谈 40–60 人的正式方案 |
| 相似度用"诱饵占比"代理 | 明确写成"诱饵占比（作为目标-干扰相似度的操作化代理）"，把简化讲在前面 |

## 6. 这次经历如何加深了我对 KSTAR 的理解

最大的收获是：**注意力不是一个"低级"的感知能力，而是整个 KSTAR 循环的上游误差源。**

我一开始也觉得 Attention 是五个赛道里最"技术性"、最没有理论纵深的一个——不就是找东西嘛。
但当我试图把它接回 KSTAR 时，发现了这个结构：

- K 是存量知识，ΔR 是**行动后**的偏差——这两者都有被下游纠正的机会；
- 但 S 是**行动前**对情境的采样，ΔS 一旦发生，后面的 T、A、R 全都在一个错误的前提上运转。
- 换句话说：**K 再准、ΔR 再小，也救不了一个采错样的 S。**

这解释了 DeepMind 说的"参差不齐（jagged profile）"——模型的崩溃点往往不在最难的推理步骤，
而在最容易被忽略的入口环节：它压根没看见那一行。

这个洞察也反过来改变了我的设计：L3 里我加的那道"基于变更后情境的执行题"，
不是为了多测一道题，而是为了**把 ΔS→ΔT→ΔA 的传播放大显式地量化出来**。
一个孤立的注意力分数没有意义，有意义的是"这个分数会让下游错多少"。

C9 阶段如果能拿到实测数据，我最想验证的正是这一条。
