> C4A 评分表里"拿来主义质量"占 20%，这份文档就是举证材料。

---

## 一、基座：`wechat-doc-mapper` 提供了什么

我拿到 C4 资料包后第一件事是把 `wechat-doc-mapper.skill` 解压读完
（`SKILL.md` 全文 + `wechat_doc_mapper.py` 557 行 + `challenges.yaml` 237 行）。
它给了我三样东西：

| 拿到的资产 | 具体内容 | 我的复用方式 |
|-----------|---------|------------|
| **命名规范解析** | `^(?P<author>[A-Za-z\-]+)_(?P<challenge>C\d+)_(?P<part>.+)$` | 直接继承概念，但重写了正则（见下） |
| **作者识别回退链** | 文件名 → 父文件夹 → PDF/DOCX 元数据 → 文档头→ Unknown | 继承四级回退思路，砍掉 2 级、加固 2 级 |
| **递归盘点** | `rglob("*")` + 相对路径/大小/修改时间 | **几乎原样复用**，这是它最扎实的部分 |
| **挑战注册表机制** | `challenges.yaml` 声明式定义，改yaml 不改代码 | **升级为 `rubric.py`**，把"挑战定义"扩展为"评审标准" |
| **Excel 输出** | `openpyxl` 五sheet 报告 | 保留 sheet 结构，**换掉实现**（见下） |

**一句话**：它给了我「骨架」——把文件变成结构化数据的流水线。
但它止步于「谁交了什么」，没有「交得好不好」。

## 二、我改了哪里，以及为什么

### 改造 1：正则重写（修一个真实 bug）

**原版**：
```python
NAMING_PATTERN = re.compile(r'^(?P<author>[A-Za-z\-]+)_(?P<challenge>C\d+)_(?P<part>.+)$')
```

**问题**：作者段 `[A-Za-z\-]+` 不含下划线是对的，但我的实测数据里
`Elite20TA_C4_skill-explainer.skill` 会**整条失配**——
因为它先要匹配作者，再要匹配 `_C4_`，而 `Elite20TA` 后面跟的是 `_C4_`，
失配后回溯仍找不到合法切分（`C4` 之后又是 `_skill-explainer`，
`skill-explainer` 里的连字符让作者段无限膨胀）。

**我的版本**：
```python
NAMING_RE = re.compile(
    r"^(?P<author>[A-Za-z](?:[A-Za-z\-.]?[A-Za-z0-9]){0,29}|[\u4e00-\u9fff]{2,8})"
    r"[-_](?P<challenge>C\d{1,2}[A-Z]?)[-_](?P<part>.+)$",
    re.IGNORECASE)
```

改动点：
- 作者段允许**内部连字符**（`Li-Ming` 是合法姓名），但**不含下划线**（下划线是字段分隔符）；
- 加 `C4A` 这类带字母后缀的挑战号支持（`C\d{1,2}[A-Z]?`）；
- 加**中文姓名**支持（`张伟_C4_AI日志.md`）。

**验证**：`Elite20TA_C4_skill-explainer` → `author=Elite20TA, challenge=C4` ✅

---

### 改造 2：作者识别——从"不合并"到"归一化 + 归属推断"

**原版明确写了**：
> Author name variants: Same person may appear as `ZhangWei`, `Zhang-Wei`, `张伟`.
> The skill does **NOT** auto-merge variants — flag potential duplicates for manual review.

这是**对的克制**，我保留了这个原则，但补了原版没有的三件事
（都是第一轮实测踩出来的坑，不是我预想到的）：

| 我加的规则 | 触发的真实 bug |
|-----------|--------------|
| **结构目录排除** | `scripts/` 被当成作者 → 凭空多出 4 位"scripts 同学" |
| **技能名排除** | `.skill` 包内 frontmatter `name: ai-log-forge` 被当作者 → 造出"ai-log-forge 同学" |
| **副本目录排除** | `wechat-doc-mapper_src/` 被当成作者 → 作者名带 `_src` 后缀 |
| **示例人名黑名单** | `samples/Demo_C4_AAR.md` → 造出"demo 同学" |
| **提交目录归属推断** | 同目录带标记文件指向谁，无标记文件就归谁（解决 `ai-log-forge/SKILL.md`） |

**我的取舍**：我不做 `张伟 ↔ ZhangWei` 的自动合并（那需要人名库，
容易错并），但我做**目录归属推断**——因为这类归属有**目录结构这个客观证据**支撑，
不是靠猜。原则是：**有客观证据才自动化，没证据就标"需人工确认"**。

---

### 改造 3：把 `challenges.yaml` 升级为 `rubric.py`

原版的 `challenges.yaml` 声明"这个挑战该交什么文件"（artifact schema），
用于**分类**。我把它升级成完整的**评审标准**：

```
challenges.yaml  →  "C4 应该有哪些文件"        （分类用）
rubric.py        →  "C4 的四条件怎么打分"       （评审用）
```

具体增加了：
- 每条信号带**权重**（文件名 1.0 / 内容 0.5–0.7 / 扩展名 0.35）；
- 每条检查项带 **strong/weak 阈值**和**改进建议模板**；
- 四维度的**判定规则**（负向优先、致命否决、占位符污染）。

**这就是"拿来 → 理解 → 改造 → 超越"里"超越"的部分**：
原版是`schema → 分类`，我做的是 `schema + 判定规则 → 评审`。

---

### 改造 4：Excel 输出——从依赖 openpyxl 到零依赖手写

**原版**用 `openpyxl`，依赖清单里还有 `pandas` / `python-docx` / `python-pptx` / `pypdf`。
问题是：**助教要在一台陌生的机器上跑这个技能**。装依赖失败 = 技能不可用 = 违反"可复用"。

**我的处理**：
- `extract.py` 全部改用标准库：
  - `.docx`/`.pptx` → `zipfile` + 正则抽 `<w:t>` / `<a:t>`（Office 文件就是 zip+XML）；
  - `.pdf` → 可选 `pypdf`，**没装就诚实降级**并在报告里注明"仅按文件名评估"；
- `report.py` **手写 xlsx**：xlsx 本质是 zip + XML，用`zipfile` + SpreadsheetML 直接生成。
  已用 `zipfile.testzip()`（CRC 校验）+ `minidom`（XML 合法性）验证产物有效。

**结果**：`python3 evaluate_c4.py <文件夹>` 即可运行，零安装。

---

### 改造 5：新增"证据层"（原版完全没有）

这是最本质的升级。原版的判定链路是：

```
命中关键词 → 计数 → 映射到挑战
```

我改成：

```
命中 → 定位到文件:行号 → 记为 Evidence(带权重/极性)
     → 按检查项聚合 → 权重收敛为三态档位
     → 报告里每条判定都附证据
```

新增的 `evidence.py` 提供了原版没有的能力：
- **行号级追溯** —— 报告里每个 ✅ 都能点回原文；
- **置信度** —— 证据 <2 条时标"需人工复核"，不硬给结论；
- **申诉机制** —— "凭什么判我❌"可以对照 `文件:行号` 讨论。

## 三、我没有拿的东西（以及为什么）

诚实说明取舍，避免"看起来全拿了"的虚报：

| 原版能力 | 我用了吗 | 原因 |
|---------|---------|------|
| `map_to_challenges()` 关键词打分映射 | ❌ 不用 | C4A 只评C4 一个挑战，跨挑战映射是C4 场景的包袱。**但我保留了它的信号权重思想**（extension+3 / path +4 / keyword +2） |
| `infer_purpose()` 用途推断 | ❌ 不用 | C4A 不需要"这是论文还是课件"。评审关心的是"合不合格"，不是"是什么" |
| Sheet2「Author × Challenge 矩阵」 | ❌ 不用 |同上，单挑战场景下退化成"作者 × 5 槽位" |
| PDF/DOCX 元数据取作者 | ⚠️ 降级 | 原版用 `pypdf`/`python-docx`。我**去掉了元数据取作者**，只保留"文档头显式声明作者"——因为实测发现包内部文档的元数据往往是**上游作者的**，会把提交者判错 |
| 四级作者回退链 | ✅ 保留并加固 | 唯一原样继承的核心链路 |

## 四、改造后的验证方式

"改得好不好"不能靠我说了算。我的验证手段是**金标准测试集**：

- 造 8 份**故意各不相同**的提交（含 3 份专门打规则漏洞的对抗样本）；
- 人工标注金标准；
- 跑评审器算准确率。

**实测结果**：

| 指标 | 数值 |
|------|------|
| 判定点 | 72 个（完整性 40 + 质量 32） |
| 严格准确率 | **90.3%** |
| 误判率（放过真问题） | **0%** |

金标准测试直接抓出了 4 个我自己写出来的 bug（详见 `AI日志.md` 第 4 节），
每个 bug 的修复都改的是 `wechat-doc-mapper` 继承来的那段逻辑。
**这说明"拿来主义"不是复制粘贴，是把别人的代码放进自己的测试里接受检验。**

## 五、一句话总结

> 从 `wechat-doc-mapper` 拿了**递归盘点、命名解析、作者回退链、Excel 报告结构**
> 这四样骨架；改了**正则、作者归一化、依赖策略、判定链路**这四处；
> 拒绝了**跨挑战映射、用途推断**这两块用不上的包袱；
> 新增了原版完全没有的**证据层**——这是从"能分信"到"能阅卷"的临界点。
