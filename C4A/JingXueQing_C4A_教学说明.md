# JingXueQing_C4A_教学说明

> 面向第一次用这个技能的同学和助教。看完这一份你应该能自己跑起来、
> 看懂报告、并且知道**怎么改评审口径**。

---

## 一、30 秒上手

```bash
# 1. 解压
tar -xzf JingXueQing_C4A_skill-evaluator.skill -C ~/c4a-evaluator
cd ~/c4a-evaluator

# 2. 指向你的群文件夹（就是那个装着大家提交文件的目录）
python3 scripts/evaluate_c4.py "/path/to/你的群文件夹" --out ./评审输出

# 3. 打开报告
open ./评审输出/评审仪表盘.html      # 投屏讲评用
cat ./评审输出/评审报告.md            # 逐条讨论用
```

**没有输出？** 说明文件夹里没有含 `_C4_` 的文件。
加 `--scan-only` 看看它到底扫到了什么。

**环境要求**：Python 3.8+，**不需要装任何第三方库**。

## 二、输入要长什么样

技能接受**任何一个本地文件夹路径**——文件怎么来的都行
（手动下载、WeChat 同步、群文件导出），它只管扫描。

### 理想情况：按规范命名

```
你的群文件夹/
├── ZhangWei_C4_skill说明.md
├── ZhangWei_C4_我的技能.skill
├── ZhangWei_C4_demo.mp4
├── ZhangWei_C4_教学说明.md
├── ZhangWei_C4_AI日志.md
└── LiMing_C4_skill说明.md
    ...
```

命名格式：`姓名_C4_内容描述.扩展名`

### 也支持这些情况（实测过）

| 情况 | 举例 | 能否识别 |
|------|------|---------|
| 子文件夹按人分组 | `ZhangWei/C4_skill说明.md` | ✅ 用文件夹名当作者 |
| 大小写混写 | `zhangwei_c4_xxx.md` | ✅ 自动归一化 |
| 带连字符的姓名 | `Li-Ming_C4_xxx.md` | ✅ |
| 中文姓名 | `张伟_C4_AI日志.md` | ✅ |
| 版本迭代 | `WangXiao_C4_技能_v2.md` | ✅ 检出v2 并追踪版本 |
| 提交目录里散着源码 | `JingXueQing_C4_xxx.md` + `ai-log-forge/scripts/*.py` | ✅ 同目录归属同一人 |
| 附带示例文件 | `samples/Demo_C4_AAR.md` | ✅ 标为附件，不算他的产出 |
| 没标`_C4_` | `随便一个文件.md` | ⚠️ 归为「非 C4 文件」单独列出 |

**识别不出来时会怎样**：标为 `Unknown`并进报告，
**不会瞎猜**。你可以把文件重命名成规范格式再跑一次。

## 三、四种用法

### 用法 1：只盘点谁交了什么（最快，秒级）

```bash
python3 scripts/evaluate_c4.py <文件夹> --scan-only
```

输出 JSON：每位作者交了哪些文件、多大、作者是怎么识别出来的。
**适合群里收齐作业后先点一次名。**

### 用法 2：只查完整性（Level 2）

```bash
python3 scripts/evaluate_c4.py <文件夹> --level 2 --print
```

只回答"五件套齐不齐"，不评质量。**适合催交作业。**

### 用法 3：完整评审（Level 4，默认）

```bash
python3 scripts/evaluate_c4.py <文件夹> --out ./评审输出
```

产出 4 个文件：

| 文件 | 用途 |
|------|------|
| `评审报告.md` | 发群 / 逐条讨论，**主要看这个** |
| `评审仪表盘.html` | 投屏，一眼看清排行与四条件分布 |
| `评审详表.xlsx` | 5 个 sheet，助教精细核对 |
| `评审结果.json` | 结构化全量结果，二次开发用 |

### 用法 4：验证评审器本身准不准

```bash
python3 scripts/tests/make_fixtures.py     # 首次：造 8 份测试提交
python3 scripts/evaluate_c4.py --selftest  # 跑金标准，看准确率
```

**这个命令会告诉你评审器的准确率**。加 `--verbose` 看逐条明细。

改动评审规则后**一定要重跑这个**——不然你不知道自己改好了还是改坏了。

## 四、怎么读报告

### 4.1 先看这三张表

1. **班级总览** —— 最常缺失什么、最弱维度是什么。
   缺失项集中说明**该在群公告里强调**，而不是逐个人催。
2. **综合排名** —— 但**别只看排名**，看"待复核"列。
3. **作者详情** —— 每个人为什么要拿这个分。

### 4.2 三个档位的含义

| 档位 | 含义 | 你该做什么 |
|------|------|-----------|
| ✅ | 达到要求 | 不用管 |
| ⚠️ | **证据不足，不确定** | **打开那个文件看一眼再下结论** |
| ❌ | 没达到要求 | 看下面的建议 |

**⚠️ 不是"差一点"，是"我不敢确定"。** 技能主动承认不知道，
比硬给一个错结论有价值。**报告里"需人工复核"的人，就是等你来看的。**

### 4.3 关键：每条判定都能追到原文

报告里每条证据都是这个格式：

```
➕ JingXueQing_C4_skill说明.md:11 | ## 安装
➖ SunLi_C4_skill说明.md:18 | 1. 修改脚本里的 LOG_PATH = "/Users/sunli/logs/app.log"
```

`➕` 是正向证据，`➖` 是问题信号。
**你觉得判错了？打开那个文件看第几行。** 这是这个技能设计的核心——
判定不是黑箱，是可以一起讨论的事实。

### 4.4 排名怎么算的

```
综合分 = 完整性 × 40% + 质量分 × 60%
```

**但别把排名当结论。** 一个IO 明确但没交 demo 的人，
和一个交齐了但 IO 不明确的人，排名可能接近，
但**他们要改的东西完全不同**。看"下一步行动建议"比看排名有用。

## 五、改评审口径（进阶）

**所有规则都在 `scripts/c4a/rubric.py`，改这个文件就行，不用动引擎代码。**

### 场景 A：想加重/减轻某个维度的权重

```bash
# 觉得"可执行"最重要，给它 40%
python3 scripts/evaluate_c4.py <文件夹> --out ./out \
  --weights "reusable=0.2,executable=0.4,verifiable=0.15,clear_io=0.25"
```

权重会自动归一化，不用凑成 1。

### 场景 B：想加一条检查项

编辑 `rubric.py`，往`QUALITY_CHECKS` 里加一条：

```python
Check(
    id="EXEC.logging",                    # 唯一 ID
    criterion="executable",                # 属于哪个维度
    label="有日志输出",                     # 报告里显示的名字
    positive=[(r"logging|logger|print\(", 1.0)],   # 正则 + 权重
    strong=1, weak=1,                               # 几条算 ✅ / ⚠️
    advice="加一句运行日志，方便别人确认跑通了",      # 没通过时给用户的建议
),
```

**改完必须重跑自检**：

```bash
python3 scripts/evaluate_c4.py --selftest
```

准确率掉下来说明新规则误伤了测试集里的样本，得调阈值。

### 场景 C：某检查项是"没犯错就算过"

比如"无硬编码路径"——成功形态是"什么都没找到"。
把 `id` 加进 `rubric.py` 的 `NEGATIVE_ONLY` 集合即可：

```python
NEGATIVE_ONLY = {"REUSE.nopath", "REUSE.nosecret", "EXEC.notemplate",
                 "你的新检查项ID"}
```

### 场景 D：致命项（直接判❌）

明文密钥这种"不是扣分而是不合格"的问题，加进 `quality.py`：

```python
FATAL_CHECKS = {"REUSE.nopath", "REUSE.nosecret", "你的新检查项ID"}
```

## 六、常见问题

### Q1：报告说某人是 `Unknown`，怎么办？

作者没识别出来。**先看 `--scan-only` 的输出**确认文件被扫到了，
然后把文件重命名成 `姓名_C4_xxx.md` 再跑。
如果还不行，可能是文件夹里混了别的挑战（C1/C2）的文件。

### Q2：为什么我的提交被判"可复用 ❌"？

最常见是**代码里有硬编码的绝对路径**（`/Users/你的名字/...`）
或**明文密钥**。这两种是一票否决——
因为 C4 的检验标准是"让一个陌生人按你的说明操作，能成功吗"，
这两种情况陌生人必然失败。

改成 `~/` 相对路径、密钥改成读环境变量就好了。

### Q3：为什么一份写得挺好的文档被判 ⚠️？

⚠️ 通常是**证据不足**，不是内容差。可能因为：
- 写得太简略（"## 安装" 下面就一句话）
- 关键信息在图片里（评审器读不了图片内容）
- 用了很冷僻的说法，规则没匹配上

**这时候请打开文件人工看一眼**——这正是 ⚠️ 的用途。

### Q4：能不能不装pypdf 就跑 PDF？

能。**PDF 内容抽取需要 `pypdf`，不装会自动降级**为
"仅按文件名评估 PDF 的内容维度"，其他格式完全正常。
报告会注明"PDF 仅按文件名评估"。想要完整功能就 `pip install pypdf`。

### Q5：它会不会把我的文件改坏？

**不会。** 这个技能只读文件、只写报告，
输出全部落在 `--out` 指定的目录里。改自己的提交请手动改。

### Q6：40 份提交跑要多久？

**几秒。** 纯规则引擎，没有网络调用，没有 LLM 调用。
瓶颈只在读文件。

### Q7：能评审别的挑战吗？

能。`rubric.py` 里的 `COMPLETENESS_SPEC` 换成别的挑战的必交清单，
`--challenge C2` 改挑战号即可。
但四条件那套（可复用/可执行/可验证/IO 明确）是 C4 专有的，
别的挑战要重写 `QUALITY_CHECKS`。

## 七、把它变成你的技能（给助教）

这个技能的设计核心是**标准与实现分离**。要改成评审别的东西：

| 想评审 | 改哪里 |
|--------|--------|
| 必交文件清单 | `rubric.py` 的 `COMPLETENESS_SPEC` |
| 评分维度与检查项 | `rubric.py` 的 `QUALITY_CHECKS` |
| 维度权重 | 命令行 `--weights`，或 `rubric.py` 的 `DEFAULT_WEIGHTS` |
| 报告长相 | `report.py` 的 `render_markdown` / `render_html` |
| 判定逻辑 | `evidence.py` 的 `grade()` |

**最有价值的其实是三条设计模式**，跟C4 无关也能用：

1. **证据优先** —— 任何自动判定都要能指回原文，否则不可采信；
2. **标准与实现分离** —— 改标准不用改代码；
3. **主动承认不知道** —— 低置信度标"需人工复核"，不硬给结论。

评审代码、评审报告、评审实验、评审论文——换个 `rubric.py` 就是另一个评审器。
