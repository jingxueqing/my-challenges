## 1. 现在的版本：V3 checklist（可直接抄）

发之前逐条过，**任何一条答不上来就别发**：

| # | 自问 | 不合格的样子 | 合格的样子 |
|---|---|---|---|
| 1 | 我在**什么环境**里？（机器/系统/版本/关键软件） | 「我电脑上跑不了」 | 「M1 / 8GB / macOS 14.5 / Ollama 0.3.x」 |
| 2 | 我在**做什么**？（哪个挑战、哪个文件、想达到什么效果） | 「这个技能有问题」 | 「`wechat_publisher.py` 把 A1.md 转 HTML」 |
| 3 | 我走到**哪一步**了？（第几次、之前是否正常） | 不说 | 「第 3 次跑，前两次是好的」 |
| 4 | 我**试过**什么？ | 不说 | 「换了托管解释器，能跑通」 |
| 5 | 我**排除**了什么？ | 不说 | 「`top` 看内存没吃满 → 排除 OOM」 |
| 6 | 有没有一条**能复现的命令**？ | 「就是不行」 | `python3 scripts/xxx.py A1.md A1.html` |
| 7 | **具体现象**是什么？（不是「不行」） | 「报错了」 | 「报 `ModuleNotFoundError`，第一行就崩」 |
| 8 | **我以为会怎样，实际怎样**？ | 不说 | 「以为能出 HTML，实际什么都没生成」 |
| 9 | **证据**在哪？（代码块 / 路径 / 行号 / 截图） | 只发一张糊图 | 代码块 + 文件路径 + 第几行 |
| 10 | 我**想让别人具体帮我什么**？ | 「怎么办」 | 「你们是在哪个目录起的 serve？」 |

**10 条里有 4 条是「不说」型的反面**——因为提问最常见的病不是「说错」，是**「没说」**。

## 2. 这个 checklist 是怎么长出来的（三版，每一版都是被现实打回来的）

### V1（2026-10 中旬，C4D 之后）：只有 3 条

```
1. 说清楚环境
2. 贴报错
3. 说你想干什么
```

**触发事件**：C4D 装 Ollama 那次，我在群里看别人提问，发现一个规律——
凡是只写「ollama 跑不动」的，回复基本都是「重装试试」；凡是贴了 `library=cpu` 那一行的，回复直接就到点上。
〔回溯〕当时我自己也是踩完 6 个坑才想明白：**能被人一句话答上的问题，都是自己已经把范围缩到一句话了。**

**V1 的问题**：第 2 条「贴报错」太容易作弊。贴一行 `Error: something went wrong` 也算贴了，但没人能帮你。

### V2（2026-11 初，做这个挑战时）：加了「排除项」，这是最重要的一次升级

```
+ 4. 你已经排除了什么
+ 5. 你以为会怎样，实际怎样
```

**触发事件**：我在写 `ask_checker.py` 第一版规则时，把「真实报错」这一格写成「只要出现『报错』两个字就给分」。
然后跑样本：

```
bad_01「这个报错了怎么办」   → 8 分（拿到了「真实报错」的分）
good_01（完整四要素的那条）  → 75 分
```

**一个纯废话拿到 8 分，一条好问题只比它高 67 分。** 这个结果让我意识到：
分数不是判「好不好」，是判「够不够清楚」。而**「排除项」才是真正省别人时间的东西**——
因为群里最常见的浪费不是「没人回答」，是「三个人分别建议你试一遍你已经试过的东西」。

### V3（本文件这一版）：加了「可复现命令」和「别替我下结论」

```
+ 6. 一条能复制就跑的命令
+ 10. 你想让别人具体帮你什么
- 删掉：「开头要有礼貌」「先说谢谢」
```

**为什么删掉礼貌那两条**：不是礼貌不重要，是它不解决「别人能不能帮你」。
一条「您好，打扰一下，我遇到了一个问题想请教大家」（+ 没有任何信息）比
一条「M1 上 `library=cpu`，你们 serve 在哪个目录起的？」更没礼貌——**因为它浪费了 20 个人的 10 秒钟。**

**为什么加第 10 条**：我参与一那条最后写的是「你们是在哪个目录起的 serve？」。
这句是刻意加的。因为我原来的结尾是「有没有人遇到过？」——那是个**是/否问题**，
答案是「有」，然后就没了。改成具体问题之后，回答的人必须给出一个目录，这就是可执行的信息。

## 3. 反过来看：一条好问题里，哪一句最值钱

拿我参与一那条逐句拆：

| 句子 | 作用 | 值钱程度 |
|---|---|---|
| 「M1 / 8GB / macOS 14.5 / Ollama 0.3.x」 | 让同类人 1 秒认亲 | ⭐⭐⭐ |
| 「`ollama run` 能出字，但慢到不能用：40 多秒」 | 把「不行」变成「能跑但慢」——这是完全不同的两个 bug | ⭐⭐⭐⭐ |
| 「以为是内存不够，`top` 看只用 4.1GB → 排除 OOM」 | 直接砍掉最常见的错误建议 | ⭐⭐⭐⭐⭐ |
| 「日志第一行就是 `library=cpu`」 | 让对方不用问就能判断自己是不是同一个坑 | ⭐⭐⭐⭐⭐ |
| 「我的判断（不一定对）」 | 给对方一个可以否定的靶子，比问「为什么」更容易被回答 | ⭐⭐⭐⭐ |
| 「你们是在哪个目录起的 serve？」 | 把开放问题收成一个可执行回答 | ⭐⭐⭐⭐ |

**结论：最值钱的不是「我遇到了什么」，是「我已经替你排除了什么」。**
这也是我这次做工具时最硬的一条规则：**排除项单独占 1/4 的分数。**

## 4. 我写过的差版本，以及它们为什么该是 0 分

为了让检查器有基线，我把三种最常见的差写法写成了样本（`01_提问自检器/samples/bad_*.txt`）：

| 样本 | 原文 | 得分 | 病因 |
|---|---|---|---|
| bad_01 | 「这个报错了怎么办」 | 0 | 四个维度全空。对方连「哪个文件」都不知道 |
| bad_02 | 「+1 同问」 | 0 | 灌水。按 C3 rubric 直接 0 |
| bad_03 | 「`ModuleNotFoundError: No module named 'markdown'`，怎么装？」 | 8 | 有报错、但没环境没上下文——**这种最危险，因为它「看起来像个问题」** |

bad_03 是我最想说的一个：它其实**不算差**，因为报错是真的。但它的问题是——
回答者只能给出「`pip install markdown`」这种通用答案，而真正的答案可能是「你解释器选错了」。
**一句话的信息量决定了回复的天花板。**

还有一条更隐蔽的：我在 C7 里差点发出去的那句「我做了十几个挑战，只有 1 个公开过」。

> 它语法通顺、有冲击力、还带数字——**唯一的毛病是那个 1 是错的，真值是 3。**
> 后来我给自己定了顺序：**先核数，再定标题**。因为标题一旦定了，人就舍不得改数字了。

## 5. 提问前的 60 秒流程（我实际在用的）

```text
第 0-20 秒  先问自己：这个问题搜一下能不能答？
            → 能，就别发（这是我 V1 之前最缺的一步）

第 20-40 秒  把问题按四格写：环境 / 在做什么 / 卡在哪 / 试过什么
            → 写不满的格子，说明我还没想清楚

第 40-50 秒  跑一次自检：
            python3 01_提问自检器/ask_checker.py 我的问题.txt
            → <70 分不出手

第 50-60 秒  删掉三样东西：
            ① 情绪（「崩溃了」「救命」）
            ② 客套（「打扰一下」「小白求助」）
            ③ 我的猜测性结论（除非标了「不一定对」）
```

第 60 秒那三条是这次才想明白的：**客套和情绪会稀释信息密度，而群消息的阅读预算是 3 秒。**

## 6. 我这次没做好的（不粉饰）

1. **我没有真的把这三条发出去。** 所以在「被同学/教师回应」这一条上，我是 0。
   这不是能力问题，是我在写这份交付物的时间窗口里没做这一步。回填流程已经写好了（`04_群聊原文_待补/`），发出后 3 分钟能补完。
2. **我把工具做得比参与更用力。** 说难听点，这是「用做工具来回避社交」。
   工具确实有用（它抓出了我自己的一条假分规则），但它不能替代「真的在群里说话」。
3. **我最初想把「参与」定义成「我在自己项目里的思考过程」**，这是偷换概念。
   群内参与的最小单位是**别人看得见的一条消息**，不是我的日志。

## 7. 如果重来一次，我会怎么排顺序

```text
第 1 天  先把三条消息发出去（不等写完工具）
第 2 天  用真实回复改工具（而不是用我自己写的样本）
第 3 天  把结论沉淀帖发出去，闭环
```

**理由**：C3 考的是「参与」，工具是参与的副产品。
我现在是反过来的——先做完工具再想发什么，这个顺序让我到最后一步反而卡在「发不发」上。
下次顺序要反过来：**先用最烂的版本占住位置，再用工具把它改好。**
