## 五、这次的三个关键判断（也是这份交付物真正的「内容实质」）

### 1. 「提到问题」不等于「提供证据」

检查器第一版给「这个报错了怎么办」判了 **8 分**——因为里面出现了「报错」两个字。
我没有调阈值让它好看，而是**改评分结构**：具体错误串才算证据；宽泛措辞只有在贴了代码块时才算。
现在这条规则有测试守着（`test_vague_complaint_gets_no_error_credit`）。

### 2. 最省别人时间的一句话，是「我已经排除了什么」

参与一那条里最值钱的一句不是日志，是「`top` 看内存只用 4.1GB → 排除 OOM」。
**它直接砍掉了群里 80% 会出现的建议。**
所以「已尝试」在检查器里占满 25 分，和「上下文」一样重。

### 3. 自动校验只能证明「行存在」，证明不了「这行是证据」

`evidence_lint` 曾让一条指向标题行的弱引用通过（`L111` 是 `### R4 · 第二次打脸`）。
我当时的念头是加「语义相关性打分」——**否掉了**，那只会多一个不可靠的裁判。
最后它只做一件事：打开文件、翻到那一行、把原文打印给人看。
