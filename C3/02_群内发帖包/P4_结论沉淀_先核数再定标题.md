# P4 ｜ 结论沉淀：先核数，再定标题

> 类型：结论回馈 ｜ 状态：〔待发〕
> 这条不是提问，是把「问题 → 讨论 → 结论」的最后一步补上

## 复制这段发出去

```text
分享一个我踩过的坑，能省大家一次返工。

我写文章时想说「我做了 16 个东西，只有 1 个被公开过」——很有冲击力，我差点就用了。
发之前我核了一遍：其实是 3 个（公众号 1 篇 + 一个公开仓库 + 一个在线应用）。
16 个条目、3 个公开，这个数字比我原来那句更难听，但它能被验证。

教训不是「要诚实」这种空话，是一个动作：先核数，再定标题。
因为一旦标题定了，你就舍不得改数字了 —— 我差点就是。

顺手做了个小工具，可以把要发的提问按「上下文 / 已尝试 / 具体卡点 / 证据」四格自检。
0 分长这样：「这个报错了怎么办」。100 分是能让人直接动手的那种。
有需要的我把工具和用法发群里。
```

## 为什么这条比三条提问都重要

C3 要的是「问题提出 → 讨论 → 结论沉淀」的完整闭环。
**前三条是「提出」，这条才是「沉淀」——而沉淀是唯一能被别人复用的部分。**

## 如果有人问「工具能发我吗」

这就是 C3 想要的「产生实质进展」。回复模板：

```text
可以，零依赖，单文件：
python3 ask_checker.py 你的问题.txt
低于 70 分会告诉你缺哪一格，不用装任何东西。

提醒一句：它只判「结构完整」，不判「问题有没有价值」——
一个问题结构满分但没人关心，它照样给 100。
```

**最后那句提醒是故意的**：不夸大工具的作用，别人才会信前面的话。
