# P3 ｜ 给同学 C4 提交的补件建议

> 类型：帮助他人 ｜ 自检 **84 / 100** ｜ 状态：〔待发〕
> 注意：发之前把 `@某某` 换成真实的人，并把「第 42 行 / 第 112 行」两处自己再核一遍

## 复制这段发出去（改了 @ 之后）

```text
@某某 昨晚跑了你 C4 交的 wechat-doc-mapper.skill，可执行、可验证两栏我都验了，是 ✅。
问题只在完整性：我按五件套对了一遍，你交了 3 件，缺 教学说明 和 demo。
另外排除了「路径写错」——我把你 .skill 包解开放在群的同一个目录下跑，识别正常。

为什么这条最要紧：我拿评审器扫了 3 份真实提交，全班最常缺的就是教学说明（2/3 份），
不是只有你一个；而且评审器对「教学说明」只认证据强度 1.00 / 0.80 / 0.50 三档，
你 SKILL.md 里现在是分节写法、没有安装步骤，被判 0.80（弱证据），要人工复核。

最小补法（10 分钟，不用做网页），SKILL.md 里加这三段就够：

## 安装
tar -xzf wechat-doc-mapper.skill -C ~/.workbuddy/skills/

## 最小用法
python3 scripts/map_docs.py --in <群文件夹> --out ./out

## 预期输出
out/index.html（单文件，双击可开）+ out/映射表.csv

demo 不用写 HTML，录 30 秒屏也算，挑战原文只要求「能演示」。
依据：我 C4A 的评审报告第 42 行（全班最常缺失）、第 112 行（你的教学说明判 0.80）。
补完还缺的话，我这边可以让评审器单跑你一个人复验一次。
```

## 为什么这条是「帮助」不是「点评」

| 写法 | 效果 |
|---|---|
| 先给 ✅ | 对方不会觉得被挑刺，愿意看完 |
| 「2/3 份都缺」 | 把「你的问题」变成「全班的习惯问题」 |
| 连三段标题都写好 | 他不用再想「教学说明该写什么」 |
| 「我可以单跑你一个人复验」 | 给了一个明确的下一步，而不是「你自己看着办」 |

## 我第一版写的是

> 「你缺教学说明和 demo，建议补上。」

**这句话看着客气，实际是废话**——他不知道补成什么样才算过。
所以改成了「加这三段就够」。**区别就在于「他拿到之后能不能立刻动手」。**
