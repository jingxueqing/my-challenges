# 发帖包使用说明

四条文本都过了 `ask_checker.py`，**直接复制代码块里的内容**发到群里即可，不需要改格式。

| # | 帖子 | 类型 | 自检分 | 建议发送时机 | 文件 |
|---|---|---|---|---|---|
| P1 | M1 上 Ollama 退化成纯 CPU | 提问 | **100** | 任何时候（技术问题不挑时间） | `P1_C4D_Ollama退化CPU.md` |
| P2 | 技能该不该自己装依赖 | 提问 + 挑讨论 | **92** | 白天，容易有人接话 | `P2_C4B_依赖该不该自动装.md` |
| P3 | 给同学 C4 提交的补件建议 | 帮助他人 | **84** | 看到有人交 C4 之后 | `P3_C4A_给同学补件建议.md` |
| P4 | 先核数，再定标题 | 结论沉淀 | — | 群里聊到「数据 / 传播」时 | `P4_结论沉淀_先核数再定标题.md` |

## 发送顺序（重要）

**不要四条一起发。** 一起发会变成刷屏，而刷屏和灌水只有一线之隔。

```text
第 1 天  P1（提问）        → 拿到回复后，把回复和结论整理成 P4 的一部分
第 2 天  P4（结论沉淀）     → 这是「问题 → 讨论 → 结论」的闭环，C3 最看重这一步
第 3 天  P2（争议题）       → 用来引出讨论，比提问更容易让人说话
第 3 天  P3（帮别人）       → 单独发，不要和 P2 挨着
```

## 发出去之后（这一步决定 C3 的分数）

1. **24 小时内**：每条都回一次，哪怕只是「谢谢，我试一下」；
2. **立刻截图**：把「我发的消息 + 至少一条回复」截成一张图，存进 `../04_群聊原文_待补/`；
3. **回填**：打开 `../JingXueQing_C3_参与记录.md`，把 §1.4 / §2.3 / §3.4 的〔待回填〕换成真实内容；
4. **改自评**：§6 验收表里那条 ❌ 改成 ✅，并把截图路径写上去。

## 一条底线

**回填的时候只写截图里能看见的东西。** 记不清对方说了什么，就写「记不清」——
这比编一句「助教说要 cd 到 Resources 目录」有用得多，因为后者一旦被追问就是 0 分。
