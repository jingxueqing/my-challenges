# P2 ｜ 技能该不该自己装依赖

> 类型：提问 + 挑起讨论 ｜ 自检 **92 / 100** ｜ 状态：〔待发〕
> 预期收益：这不是求答案，是抛一个没有标准答案的设计选择

## 复制这段发出去

```text
【环境】macOS 14.5 / 系统自带 python3 3.9 / 另有一个托管 python 3.13
【在做什么】用我 C4B 做的公众号排版技能 wechat_publisher.py，把 A1.md 转成公众号 HTML。
【进度】这是第 3 次跑，前两次是好的。

【卡点】直接跑 python3 scripts/wechat_publisher.py A1.md A1.html：
ModuleNotFoundError: No module named 'markdown'
我期望能直接出 HTML，实际第一行就崩了，后面什么都没生成。

【已尝试】
1. pip3 install markdown 我没装 —— 会污染系统 python，而且我自己技能里写了「禁止自动装依赖」；
2. 用 python3 -c "import markdown" 确认系统 python 确实没有这个包 → 排除「装错位置」；
3. 换托管解释器跑，md ok，直接跑通。

【我的结论】不是代码问题，是解释器选错。

【想讨论的】你们写技能时是「要求用户自己备环境」，还是「技能自带 requirements」？
我倾向后者，但要加一个「缺依赖就打印指引并退出」的开关，默认不装。
```

## 这条的重点不是「怎么装」

如果只是想解决，搜一下就有答案。**真正值得讨论的是：一个给别人用的技能，应该替用户做到哪一步。**

三个预设的立场，方便别人接话：

| 立场 | 理由 | 弱点 |
|---|---|---|
| A 自带 requirements 并自动装 | 用户体验最好，一次跑通 | 会改别人的环境，出问题找不到原因 |
| B 自带 requirements 但不装，缺了就退出并打印指引 | 可控 | 用户要手动跑一次 |
| C 完全不管环境 | 技能最轻 | 新手直接卡死 |

## 如果有人说「你不会加个 try 吗」

**这是一个好回复，值得追一句：**

```text
try 我能加，但 try 之后 print 一句「请装 markdown」，
和真的把环境搞好之间还差一步。你倾向让技能自己去装吗？
```

把「技术怎么做」拉回「边界划在哪」，这样讨论才会往前走，而不是停在「加个 try」。
