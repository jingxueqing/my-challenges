## 2. 它到底判什么

四个维度，各 25 分，每个维度 3 个检查格，命中 1 格得 1/3：

| 维度 | 检查格 | 一句话 |
|---|---|---|
| **上下文** | 环境 / 在做什么 / 走到哪一步 | 别人要知道你在哪、干什么、到哪了 |
| **已尝试** | 试过什么 / 排除了什么 / 可复现命令 | 别人要知道你已经排掉了什么，才不会重复建议 |
| **具体卡点** | 真实报错 / 具体现象 / 预期 vs 实际 | 「不行」不是卡点，「停在第 3 行」才是 |
| **证据** | 日志或代码块 / 路径行号 / 截图或链接 | 别人要能自己看到，而不是听你转述 |

```
0 分    「+1 同问」                    → 灌水，不要发
8 分    「ModuleNotFoundError，怎么装？」 → 甩问题，重写
84 分   能发，但差一格
100 分  四维全中
```

## 3. 三条设计原则（写死在代码里）

### ① 打分必须可解释

不只给分，还**回引原文片段**。没有命中片段的就是缺项，缺项一定配一句「补什么」：

```text
具体卡点     8/25  ✅ 真实报错  ❌ 具体现象  ❌ 预期 vs 实际
          命中「真实报错」：…tFoundError: No module named…
          缺「具体现象」→ 补一句具体现象（不是「不行」，而是「卡在第几行/停在什么状态」）
```

### ② 只做减法，不做加法

默认 0 分，命中一条加一条。**宁可低估，也不虚构「看起来很专业」的分。**

### ③ 不联网、不调大模型

纯正则。因为「提问质量」这件事要能复现——同一句话今天 80 分、明天 60 分，就没有意义。

## 4. 一个真实的设计缺陷（以及修法）

**第一版把「这个报错了怎么办」判成了 8 分。**

原因：只要出现「报错」两个字，就被当成「提供了报错」。

```python
# 第一版（错的）
r"Traceback|Exception|Error|...|失败|报错|崩"
```

**修法不是把词删掉就完了**，而是拆成两层：

```python
patterns  = [具体错误串：Traceback / ModuleNotFoundError / 4xx / timeout / 0.80 这类评分]
gated     = {"codeblock": [宽泛措辞：报错 / 失败 / 崩]}   # 只有贴了代码块才算数
```

于是：

| 输入 | 真实报错格 |
|---|---|
| 「这个报错了怎么办」 | ❌ 不给分 |
| 「我跑了一下，它报错了：`Error: xxx`（带代码块）」 | ✅ 给分 |

这条规则现在有测试守着：`test_vague_complaint_gets_no_error_credit`。

## 5. evidence_lint 只做一件事

它不判断「这条引用相不相关」——那需要语义理解，会变成第二个不可靠的裁判。

它只做：**打开文件 → 翻到第 N 行 → 把原文打印出来。**

```text
✅ JingXueQing_C3_参与记录.md:128 → JingXueQing_C7_AI日志.md:L120
     我没有去 `pip install`（那会污染系统环境，而且 C4B 那次…）
```

这个设计是被现实逼出来的：它曾让一条「指向标题行」的弱引用通过（`L111` 是 `### R4 · 第二次打脸`）。
**自动校验能证明「行存在」，证明不了「这行是证据」——最后那一眼必须是人看的。**

## 6. 局限（写在前面，省得被误解）

| 局限 | 说明 |
|---|---|
| 判的是**结构完整**，不是**问题价值** | 结构满分但没人关心的问题，照样 100 分 |
| 词表是**中文口语**的 | 英文提问、大量术语堆叠的提问，命中率会下降 |
| 判不了「**该不该发**」 | 有些问题再完整也不该占群资源（搜一下就有答案的） |
| 正则判不了**逻辑矛盾** | 环境写 macOS 但命令是 `apt install`，它看不出来 |

**它的定位是「发之前照一遍镜子」，不是「替你判断该不该说」。**

## 8. 怎么改成你自己的

三个地方：

1. **`SLACK_PATTERNS`** — 你们群里哪些话算灌水（比如内部黑话「收到收到」）；
2. **`DIMENSIONS` 里的 `patterns`** — 换成你们领域的术语（医学/法律/财务的问法完全不同）；
3. **`--min`** — 默认 70。如果你在的群很冷，降到 60；如果群里消息很贵，提到 85。

改完**先跑测试**：`python3 tests/test_ask_checker.py -v`。
如果 `test_floors` 红了，说明你把好稿子判低了——那多半是词表改坏了，不是稿子变差了。
