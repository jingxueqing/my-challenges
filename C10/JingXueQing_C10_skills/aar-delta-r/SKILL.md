# aar-delta-r · 用 ΔR 复盘，而不是用形容词复盘

## What（做什么）

在动手**之前**写下 R̂（预期结果，0–1 达成率），做完后量 R，算 ΔR = R̂ − R，
然后只回答一个问题：**这个偏差是"能力不足"还是"口径错了"？**

## When to Use（什么时候用）

- 项目/周结束要写 AAR。
- 连续两次在同一类任务上失败。
- 想把一次经验变成可复用知识（ΔR 是它的必要字段）。
- 接手别人交付时想快速看"他哪里高估了自己"。

## Input（输入）

1. 动手前的 R̂（**必须是事前写的**，事后补写等于自欺）；
2. 验收硬指标（最好带数字口径）；
3. 实际结果（从磁盘/日志/看板取，不靠回忆）；
4. 过程中的返工清单（哪几次是白干的）。

## Steps（步骤）

1. **事前写 R̂，单一量纲**（v2 铁律）：一个 R̂ 里不许塞两个不同性质的东西。
   C2 的教训：把"四件交付物交齐"和"论文有说服力"塞进一个 1.0，结果必然高估。
2. **R̂ 里只放"我能单方面决定"的事**：需要别人扫码/点一下/批准才能发生的，单列成风险项。
   C7 的"至少 2 篇公开发布"就是典型错误（发布权不在我手上）。
3. **同一个口径量 R**：如果量法变了，先把旧口径也重算一遍，再比。
4. **算 ΔR 并分类**：
   - `ΔR ≈ 0` → 口径稳、可加难度；
   - `0 < ΔR ≤ 0.2` → 轻度高估，微调步骤；
   - `ΔR > 0.2` → 显著高估，**必须回到"我量错了什么"**；
   - `ΔR < 0` → 低估，通常说明"验证成本被高估了"（C9 的 −0.35）。
5. **写"看起来像根因但不是"的清单**：这一栏比根因栏更有价值（C8 列了 3 条）。
6. **落 L2**：`kstar.py ep new --rhat ... --r ...`，让 ΔR 进库，后续按 tag 聚合看趋势。

## Tools（需要什么工具）

- 本仓库：`kstar.py loop start/close`（自动算 ΔR 并落草稿）、`ep list`（看平均 ΔR 趋势）
- 交付物里的验收记录、测试输出、`logs/usage.jsonl`

## Output（输出）

一份含 R̂/R/ΔR 表的 AAR + 一条"可复用的一句" + 1–3 个已固化的动作（写进 Skill 或 identity）。
