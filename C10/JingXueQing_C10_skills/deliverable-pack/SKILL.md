# deliverable-pack · 交付不是"文件放一起"

## What（做什么）

把一堆产物整理成**可被陌生人独立验证**的交付包：
一眼看到"要求什么 / 交了哪个文件 / 怎么跑 / 证据在哪 / 什么没做到"。

## When to Use（什么时候用）

- 提交作业、交接项目、对外发布前的最后一步。
- 有人问"你这个东西怎么用"时。
- 自己两周后要回头复现时（最常见的真实用户是自己）。

## Input（输入）

1. 任务要求原文（CHALLENGE / 需求文档）；
2. 实际产物清单（用 `ls`/`find` 生成，不靠记忆）；
3. 每条验收指标的实测证据（终端输出、截图、日志、URL）。

## Steps（步骤）

1. **对照表先写**：左列 = 要求原文的每一项，右列 = 对应文件路径。
   缺的格子里写 `[待补]`，**不留空、不写"已完成"**。
2. **复现命令逐条跑一遍**：在干净终端里复制粘贴，确认能出结果。
   （C8 的教训：没第二个人冷启动过，就不能声称"15 分钟上手"。）
3. **证据索引**：每个数字指向文件+行号/截图名/命令。
4. **数字由脚本生成**：看板、统计、使用次数一律 `dash` / `report` 生成，禁止手写。
5. **写"诚实声明"一段**：哪些是回填、哪些没验证、哪些是别人的权限。
6. **压测"陌生人视角"**：只看 README 能不能跑起来；不能就改 README，别改解释。

## Tools（需要什么工具）

- 本仓库：`kstar.py dash` / `kstar.py report` / `kstar.py export-skills`
- `find` / `ls -R`（生成真实文件清单）、git（提交号作为时间戳证据）

## Output（输出）

`README_提交说明.md`（对照表 + 复现命令 + 证据索引 + 待补台账 + 诚实声明）+ 冻结的产物快照。
