# scope-probe-first · 先探边界，再报数字

## What（做什么）

在承诺任何"覆盖率 / 完成度 / 可达性"之前，先用最小成本探一遍现实边界：
哪些输入拿得到、哪些工具在这台机器上真能用、哪些页面/接口/权限根本不通。
产出不是代码，是一张**缺口台账**。

## When to Use（什么时候用）

- 接手一个别人给的资料包 / 数据集 / 代码库，还没读过内容。
- 任务里出现"全部""完整""覆盖""支持"这类词。
- 要在陌生环境里承诺"能跑"（本地模型、浏览器、依赖、权限）。
- 想在 R̂ 里写一个高数字之前。

**不适用**：需求边界已经完全清楚、且是自己上周刚做过的同一件事。

## Input（输入）

1. 目标物（目录 / URL 列表 / 设备 / 账号权限）；
2. 任务里所有"数量级承诺"（覆盖率、条数、时长）；
3. 一条可执行的探测手段（脚本、`system_profiler`、`--help`、试抓一页）。

## Steps（步骤）

1. **列出承诺项**：把任务里所有可被追责的数字抄成一张表（如"覆盖度≥80%""术语≥50条"）。
2. **对每项做一次 30 秒探测**：能拿到就标 ✅，拿不到就记下失败原因（不是"失败"两个字，
   是"站点不可达 / JS 渲染 / 需登录 / 需 attach 进程"）。
3. **验量具**（v2 新增）：确认"我用来量的东西"本身可信。
   例：无头浏览器 `--window-size=390` 在 macOS 上其实是 500px 裁图 → 量具坏了，数字全废。
4. **写缺口台账**：`缺口项 | 原因 | 是否可补 | 补的代价`，放进交付物里，不要藏在心里。
5. **重写 R̂**：把探出来"做不了"的部分从预测里扣掉，再报数。

## Tools（需要什么工具）

- 任意脚本语言（探测循环）、`system_profiler` / `uname -m`、`--help` / `--version`
- WebFetch（试抓一页判断是否 JS 渲染/收费墙）
- 本仓库：`python3 scripts/kstar.py add`（把探测结果落 L1）

## Output（输出）

一张缺口台账 + 一个被修正过的 R̂。折损版：至少一句"这里做不了，原因是 X"。
