# C9 先做 200 行单文件：40 分钟证明闭环成立

## S（Situation）

自驱项目「家里有什么」（照片/口语入库 → 模糊搜 → 过期提醒 → 出菜）。
第一天，我面临一个选择：先搭包结构，还是先写一个能跑的单文件。

## T（Task）

在 1 小时内回答一个问题：**这个闭环到底有没有用？**

## A（Action）

- 写 200 行零依赖单文件 `JingXueQing_C9_mvp.py`，一次打印完整链路：
  入库 → 模糊搜 → 预警 → 出菜。
- 只在它跑通之后，才去搭 2,434 行的 `homepantry/`（388 行测试、54 个测试全绿）。
- 顺手把 33 句真实口语当播种数据——等于每天免费跑一次端到端自检。

## R（Result）

- MVP 40 分钟跑通，结论"有用"；随后一天内 V1 落地（12 个 CLI 命令 / 12 个 HTTP 端点 / SQLite）。
- 关键收益不是速度，是**在写 2,400 行之前就知道值不值得写**。

## ΔR（R̂ − R）

- R̂ = 0.6（我以为要一天才能验证）｜ R = 0.95 ｜ **ΔR = −0.35**
- 判定：低估（少见的一次）
- 解释：我把"验证想法"想得太贵了。实际上验证只需要一条打印链路，
  不需要架构、不需要分层、不需要配置。

## 可复用的一句

**验证成本被系统性高估了。** 任何新方向的第一天，
产出一个"能在终端里看见结果"的单文件，比产出一个结构正确的骨架更有价值。
