# C1 课程资料包：先做「尸体解剖」，再动手翻译

## S（Situation）

拿到 Stanford CS146S 的离线课程包，要求产出「可读的中文资料包 + 可复跑的管线」。
约束：4 个工作日；一手来源只能来自离线包（带 URL 映射）；质量要求是覆盖度 ≥80%、
术语表 ≥50 条且全文一致、陌生人能按 README 独立使用。

未知量不是"怎么翻译"，而是**"这堆页面里有多少是根本抓不出正文的"**。

## T（Task）

1. 5 分钟内判断哪些页面可提取、哪些是死页；
2. 把「提取 / 翻译 / 质检」拆成与课程无关的脚本；
3. 11 批并行翻译，保证术语一致；
4. 用脚本量化覆盖度，而不是靠自觉。

## A（Action）

- **D1 尸体解剖**：逐页探测正文可提取性 → `page_map` + 缺口清单（5 处：站点不可达 / JS 渲染 / Medium 拦截）。
- **D2 建线**：3 个课程无关脚本，课程相关量（目录名、术语表路径、引擎）全部走环境变量。
- **D3 量产**：按文件大小分 11 批并行；每批注入同一份「术语块 + 结构规则 + 产品名清单」。
  82 条术语表，脚本扫描一致性违规 **0**。
- **D4 收口**：脚本全量质检 + 人工抽检 6 篇；双口径覆盖度（篇数 / 正文字数）写进 README。

## R（Result）

- 正文全译质检通过 30/31 = **96.8%**，按篇数 100%（含缺口台账，交付后补抓成功 2 篇）。
- 术语 82 条、一致性违规 0；4 个脚本换一门课可复用。
- 未覆盖：3 篇死页（留台账）、视频字幕 3 个、Google Slides 14 个（离线包本就不含）。
- 4 篇超长文用「详注节译」而非逐字全译。

## ΔR（R̂ − R）

- R̂ = 0.95 ｜ R = 0.92 ｜ **ΔR = +0.03**
- 判定：命中（预测准）
- 解释：因为我**先量了边界再承诺覆盖率**。如果 D1 没做，R̂ 会写成 1.0，
  最后被 3 篇死页打成 0.7。探边界这个动作，本质是把"未知"从 R̂ 里扣掉。

## 可复用的一句

**开工第一小时不要产出内容，要产出「哪些做不了」的清单。**
能提前说清"这里做不了"的人，才敢对"那里能做好"报价。
