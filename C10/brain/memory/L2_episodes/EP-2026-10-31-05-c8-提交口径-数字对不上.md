# C8 提交口径：数字对不上，功能再全也没人用

## S（Situation）

班级群管理 Agent 要报「谁交了、交了哪些文件」。
第一版按"消息里说交了"判定，跑出来 7 个人显示「已交」但 0 个完整文件。

## T（Task）

让提交模块的数字和老师手工核对的结果**一致**，而不是"看起来合理"。

## A（Action）

- 先怀疑数据？没有——AI 的第一反应是「学生没交齐，建议催交 7 个人」。
- 我停下来去核对 config：**C8 的必备件字段我写错了**（`deliverable` 填成了 `proposal` 的同义词）。
- 改口径：从"消息里说交了"改为**以磁盘/文件消息为准**。
- 加 `doctor` 自检 + 62 条测试（含提交口径的边界用例）。

## R（Result）

- 改为文件为准后，数字立刻和老师手工核对一致：44 项提交 / 307 文件。
- 但代价是：**这 7 个人的误判如果发生在真实场景，我会去催 7 个已经交了作业的人。**

## ΔR（R̂ − R）

- R̂ = 0.9（我以为这个模块"写完就能用"）｜ R = 0.4 ｜ **ΔR = +0.50**
- 判定：显著高估
- 解释：我高估的是"功能完成度 ≈ 结果正确性"。
  功能是全的，但**口径错了，全等于零**。这类错误的特征是：
  代码没有 bug、测试也能过，但它在量错的东西。

## 可复用的一句

**先对准"我在量什么"，再动手写"怎么量"。**
功能完成度是 0，口径正确度是 1 —— 乘起来才是可用性。
