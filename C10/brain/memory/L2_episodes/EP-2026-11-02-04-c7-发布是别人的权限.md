# C7 内容传播：发布是别人的权限，不是我的能力

## S（Situation）

要交「内容 + 传播」的证据链。我手上素材很足（C1–C6 的真实交付），
但公众号发布需要管理员扫码，而我不能替账号所有者操作。

## T（Task）

1. 3 篇文章（公众号 2 + 知乎 1），全部来自 C1–C6 的真实实践；
2. 排版合规（`div=0 / class=0`、样式 100% 内联、0 高危）；
3. 传播设计四项：渠道 / 节奏 / 互动 / 数据追踪；
4. 数据真实：拿不到就写「待回填」，不估算。

## A（Action）

- 先建**事实台账**（30+ 条，每条带来源路径），再动笔——避免"写着写着开始编"。
- 转换器跑 `--audit` 全过：2 篇公众号 HTML 0 高危；A1 7 个提示框 / A2 5 个（用提示框替代配图做视觉节奏）。
- 4 张封面（900×383 ×2 + 383×383 ×2）逐张肉眼复核。
- 传播追踪 CSV 预置 9 行记录位，**留空**。

## R（Result）

- 3 篇成稿（2073 / 2372 / 2950 字），排版与结构全部可核验；
- **发布数 = 0**（需扫码），**数据截图 = 0 张**（刻意留空）；
- AAR 第 1 行就写「发布与数据截图待本人执行（不隐瞒）」。

## ΔR（R̂ − R）

- R̂ = 0.9 ｜ R = 0.6 ｜ **ΔR = +0.30**
- 判定：显著高估
- 解释：**我把"别人的权限"当成了"我的计划"。**
  R̂ 里写「至少 2 篇公开发布」，但发布权的钥匙不在我手上。
  这和 C8「真实微信群没接上」是同一个错误：把假设写成了计划。

## 可复用的一句

**R̂ 里只放"我能单方面决定"的东西。**
凡是需要别人点一下才能发生的，都要单列成风险项，不能计入达成率。
