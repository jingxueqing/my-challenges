# C9 移动端"还在溢出"：我拿错了尺子

## S（Situation）

移动端（390px）横向溢出。AI 给了两轮"语义上合理"的 CSS 修复（改 `flex-basis`、改 `order`），
截图看还是溢出。

## T（Task）

让 390px 视口真的不溢出，并且能证明。

## A（Action）

- 第三轮才做根因分析：`input` 默认 `min-width:auto` 与行内 `style="flex:0 0 96px"` 优先级冲突。
- 更关键的一步：把 `window.innerWidth` 打进页面读出来 —— 发现**无头 Chrome 在 macOS 上最小视口是 500px**，
  `--window-size=390` 只是把 500px 的布局裁成 390px 的图。
- 于是前几轮"还在溢出"里有一部分是**假的**：那是 500px 布局被裁掉的右边。
- 立规矩：样式类改动先输出「哪个元素超出视口、超出多少、依据是什么」，再改代码。

## R（Result）

- 真修好了，但花掉 3 轮截图 + 20 分钟，其中至少 1 轮打在一个不存在的 bug 上。
- 差点在验收记录里顺手写「已修复」——最后改成 `[待补]`，因为截图拿不出来。

## ΔR（R̂ − R）

- R̂ = 0.9（我以为"改完就好"）｜ R = 0.45 ｜ **ΔR = +0.45**
- 判定：显著高估
- 解释：我高估的不是修复能力，是**测量可信度**。
  在错误的口径上改代码，改得越对越偏。

## 可复用的一句

**先验尺子，再改代码。**
"我看到的是不是真的"必须先于"我改得对不对"。
拿不到证据时，宁可写 `[待补]` 也不写「已完成」——写下的每个「已完成」都要能被别人复现。
