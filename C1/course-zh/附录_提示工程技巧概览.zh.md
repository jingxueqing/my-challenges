# 附录：提示词工程技巧速览与使用建议

> 注：官方 18 条技巧总览已于交付期间联网补抓并全译，见《prompt-engineering-guide.zh.md》。本附录保留为速览 + 使用建议，技巧清单已与官方抓取版本对齐（曾在本附录初版中列入的 MRKL、链式验证等条目不在官方总览中，已移除）。

## 官方 18 条技巧（速览）

零样本提示 → 少样本提示 → 思维链（CoT）→ 元提示（Meta Prompting）→ 自洽性 → 生成知识提示 → 提示链 → 思维树（ToT）→ 检索增强生成（RAG）→ 自动推理与工具使用（ART）→ 自动提示词工程师（APE）→ 主动提示（Active-Prompt）→ 方向性刺激提示（DSP）→ 程序辅助语言模型（PAL）→ ReAct → 反思（Reflexion）→ 多模态思维链（Multimodal CoT）→ 图提示（Graph Prompting）

## 使用建议

1. 先试最简单的零样本 → 不够再上少样本 → 涉及推理上思维链 → 需要外部知识上 RAG → 需要工具上 ReAct/ART。
2. 示例质量与多样性比示例数量更重要；示例标签覆盖要均衡。
3. 温度（temperature）调低可获得更稳定的结构化输出。
4. 所有技巧都应配合明确输出格式约束（JSON schema、markdown 模板等）使用。
5. 复杂任务优先考虑"提示链"拆解为多步，而不是把所有要求塞进一个提示词——这与课程第 3 周"规格说明是新的源代码"的观点互为呼应。
