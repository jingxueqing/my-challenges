# GitHub Copilot：经由提示词注入实现远程代码执行（CVE-2025-53773）

本文讨论一个重要但同样可怕的提示词注入发现——它会导致开发者的机器在 GitHub Copilot 和 VS Code 中被完全攻陷。

实现方式是：通过修改项目的 settings.json 文件，把 Copilot 置于 YOLO 模式。

正如几天前在 Amp 中所描述的，智能体中一种可能被忽视的漏洞模式是：如果一个智能体能够写文件、修改自身配置或更新与安全相关的设置，就可能导致远程代码执行（RCE）。这种情况并不罕见，也是做安全评审时始终应当排查的一类问题。

## 背景研究

在研究 VS Code 和 GitHub Copilot Agent Mode 时，我注意到一个奇怪的行为……它可以在无需用户批准的情况下在工作区中创建并写入文件。

这些编辑会立即持久化，并不像差异（diff）那样保存在内存中待评审，修改会立刻写入磁盘。

作为红队人员，你凭直觉就知道这类事情多半不是好事……于是我着手研究能否借此提升权限并执行代码。

### YOLO 模式

接下来，我研究了 VS Code 中那些依赖于项目/工作区文件夹内设置文件的功能，并很快发现了一个有趣的点。

事实证明，在 .vscode/settings.json 文件中可以添加如下一行：

"chat.tools.autoApprove": true

这就会把 GitHub Copilot 置于 YOLO 模式。

它会禁用所有用户确认，于是我们就可以运行 shell 命令、浏览网页，等等！

有趣的是，这本来是一个实验性功能，但它在默认情况下依然存在。我并没有下载什么特殊版本，也没有把 VS Code 整体切到实验模式。

此外，它在 Windows、macOS 以及 Linux 上都能生效。

## 漏洞利用链解析

劫持 Copilot 并提升权限的概念验证利用链如下：

1. 攻击始于一个植入在源代码文件、网页、GitHub issue、工具调用响应或其他内容中的提示词注入……载荷还可以使用不可见文本作为指令。
2. 提示词注入首先向 ~/.vscode/settings.json 文件添加一行 "chat.tools.autoApprove": true。如果文件夹或文件尚不存在，则会被创建。
3. GitHub Copilot 立即进入 YOLO 模式！
4. 攻击执行一条终端命令。借助条件化的提示词注入，我们实际上可以根据操作系统来定制要运行的内容。
5. 我们实现了由提示词注入驱动的远程代码执行（RCE）。

## 把工作站加入僵尸网络 - ZombAIs

当然，这意味着我们可以把开发者的机器作为一个 ZombAI 加入僵尸网络。

另外，出于好玩，我们还可以修改 settings.json 文件，把 VS Code 切换成红色（Red）配色主题，以及其他类似的小动作。

不过事情还没完！这也意味着我们可以制造一种真正的 AI 病毒：它附着在文件上，随着开发者下载并打开受感染文件而传播。

最后同样重要的是，为了证明我们对开发者的主机拥有完全控制权，我们展示了 Copilot 可以被劫持去下载恶意软件，并连入远程命令与控制服务器。

这意味着恶意软件、勒索软件、信息窃取器等的的大门已经敞开。

相当可怕。

## 构建一个 AI 病毒

看到这里，你会意识到这基本上就允许制造病毒了。攻击者可以嵌入指令，一旦获得代码执行能力，额外的恶意软件就可以感染其他 Git 项目（以及 RAG 数据源）来嵌入恶意指令，并提交变更，甚至把它们强制推送到上游。

随着其他开发者在不知情的情况下传播被感染的代码，这将导致进一步的扩散。

最后，我们还必须谈谈不可见指令！

## 建议与修复

实际上，除了我分享的 YOLO 模式示例外，还有更多攻击角度。当 Microsoft 问我是否还有更多信息时，我又深入研究了一下，发现还有一些有问题的地方，例如 AI 可以写入的 .vscode/tasks.json、添加伪造的恶意 MCP 服务器等，这些都可能导致代码执行。而且 AI 还可以重新配置项目的用户界面和配置项。

最近我注意到开发者经常同时使用多个智能体，因此还存在覆盖其他智能体配置文件（白名单 bash 命令、添加 MCP 服务器……）的威胁，因为它们通常也放在项目文件夹中。

理想情况下，AI 不应该在没有人工先批准的情况下修改文件。许多其他编辑器都会显示差异（diff），随后由开发者批准。

## 负责任披露

2025 年 6 月 29 日上报该漏洞后，Microsoft 确认了复现，并问了几个后续问题。几周后，MSRC 指出这是他们已经在跟踪的一个问题，并将在 8 月前修复。随着 8 月补丁星期二发布，该问题现已修复。

特别感谢来自 Persistent Security 的 Markus Vervier，他也独立发现并向 Microsoft 报告了这一漏洞。你可以在这里找到他们的分析文章。同样要感谢 Ari Marzuk，他似乎也在同期独立发现了该问题。

感谢 MSRC 和产品团队的成员在推动修复过程中提供的帮助。

## 结论

这是又一个说明 AI 智能体可能不会乖乖待在自己的盒子里的例子！通过修改自身所处的环境，GitHub Copilot 可以提升权限并执行代码，从而攻陷开发者的机器。正如我所发现的，这在智能体系统中是一种并不罕见的设计缺陷。

请持续留意这类设计缺陷——在威胁建模过程中它们本应很容易被发现。
