# Anthropic 团队如何使用 Claude Code

> 本文为详注节译版（自 PDF 提取文本整理）。原文为 Anthropic 内部文档《How Anthropic teams use Claude Code》，PDF 提取文本存在大量换行断句与页眉页脚噪声，已按语义重组段落并去除页码噪声后翻译。文中各章先用中文详述要点，凡涉及关键做法、流程步骤、数字/指标、工具名、示例提示词的内容均给出全文翻译；开头背景与结尾结论部分为全文翻译。

Anthropic 的内部团队正在借助 Claude Code 改变他们的工作方式，让开发者和非技术员工都能应对复杂项目、自动化日常任务，并弥合此前限制生产力的技能鸿沟。

通过对 Anthropic 内部 Claude Code 重度用户的访谈，我们收集了不同部门如何使用 Claude Code、它对工作产生了哪些影响，以及其他考虑引入的组织可以借鉴的经验建议。

## 一、数据基础设施团队

**要点详述**：数据基础设施团队负责为公司各部门组织全部业务数据，他们用 Claude Code 自动化常规数据工程任务、排查复杂基础设施问题，并为技术和非技术成员创建可独立访问和操作数据的文档化工作流。最有代表性的案例是 Kubernetes 故障诊断——当集群宕机、无法调度新 Pod 时，团队把仪表盘截图喂给 Claude Code，由它逐菜单引导他们走完 Google Cloud 的界面，最终定位到 Pod IP 地址耗尽的告警，并给出创建新 IP 池并加入集群的精确命令，无需再找网络专家。另一大亮点是"纯文本工作流"：财务人员只需用纯文本描述数据流程，Claude Code 即可全自动执行，包括主动询问所需输入（如日期）。团队还用 Claude Code 帮助新数据科学家上手庞大的代码库（通过读取 Claude.md 文档定位相关文件、解释数据管道依赖），并在每次任务结束时让 Claude Code 总结会话、建议改进，形成持续优化 Claude.md 文档的闭环。

### 主要用例（全文翻译）

**结合截图调试 Kubernetes**
当 Kubernetes 集群宕机、无法调度新 Pod 时，团队用 Claude Code 诊断问题。他们把仪表盘截图喂给 Claude Code，它逐菜单引导他们走完 Google Cloud 的界面，直到发现一条表明 Pod IP 地址耗尽的告警。随后 Claude Code 给出了创建新 IP 池并将其加入集群的精确命令，从而无需再请网络专家介入。

**面向财务团队的纯文本工作流**
团队教会财务成员编写纯文本文件来描述他们的数据工作流，再加载到 Claude Code 中获得全自动执行。没有任何编程经验的员工可以描述诸如"查询这个仪表盘、获取信息、运行这些查询、生成 Excel 输出"这样的步骤，Claude Code 就会执行整个工作流，包括主动询问所需的输入（例如日期）。

**帮助新员工导航代码库**
新数据科学家入职时，会被引导使用 Claude Code 导航他们庞大的代码库。Claude Code 会阅读他们的 Claude.md 文件（文档），为特定任务定位相关文件，解释数据管道的依赖关系，并帮助新人理解哪些上游数据源汇入仪表盘。这取代了传统的数据目录和数据发现工具。

**会话结束时的文档更新**
团队会在每项任务结束时让 Claude Code 总结已完成的工作会话并提出改进建议。这形成了一个持续改进的循环：Claude Code 基于实际使用情况帮助打磨 Claude.md 文档和工作流说明，让后续迭代更加高效。

**跨多个实例并行管理任务**
处理长时间运行的数据任务时，他们会在不同仓库为不同项目打开多个 Claude Code 实例。每个实例都保持完整上下文，因此即使切换回来已是数小时或数天之后，Claude Code 仍清楚地记得他们在做什么、进行到了哪里，实现了真正无上下文丢失的并行工作流管理。

### 团队影响（全文翻译）

- **无需专业知识即解决基础设施问题**：解决了通常需要拉入系统或网络团队成员才能处理的 Kubernetes 集群问题——用 Claude Code 诊断问题并提供精确修复方案。
- **加快新人上手**：新数据分析师和团队成员能够快速理解复杂系统，无需大量指导即可做出实质性贡献。
- **增强支持工作流**：能够处理更大数据量并识别异常（例如监控 200 个仪表盘），这是人工审查不可能做到的。
- **实现跨团队自助服务**：毫无编程经验的财务团队现在可以独立执行复杂的数据工作流。

### 数据基础设施团队的经验建议（全文翻译）

**编写详尽的 Claude.md 文件**
你在 Claude.md 文件中对工作流、工具和期望记录得越详细，Claude Code 的表现就越好。这让 Claude Code 在"已有现成模式时搭建新数据管道"这类常规任务上表现出色。

**敏感数据用 MCP 服务器而非 CLI**
他们建议使用 MCP 服务器而不是 BigQuery CLI，以便对 Claude Code 可访问的内容保持更好的安全控制，尤其是在处理需要留痕或存在潜在隐私风险的敏感数据时。

**分享团队使用会话**
团队举办了成员之间互相演示 Claude Code 工作流的分享会。这有助于传播最佳实践，也展示了他们自己可能发现不了的多种工具用法。

## 二、产品开发团队（Claude Code 团队）

**要点详述**：Claude Code 团队"吃自己的狗粮"，用自己的产品来构建 Claude Code 的更新，扩展其企业能力和智能体循环（agentic loop）功能。他们区分两种工作模式：对不熟悉的抽象问题，开启"自动接受模式"（shift+tab）让 Claude 自主写代码、跑测试、持续迭代，最后人工接手完成剩余 20% 的收尾；对触及业务逻辑的核心功能，则同步协作、给出带具体实现指令的详细提示词并实时监督。最成功的异步项目是为 Claude Code 实现 Vim 按键绑定——最终实现中约 70% 的代码来自 Claude 的自主工作，只需几轮迭代即可完成。团队强调从干净的 git 状态出发、定期提交检查点，以便在 Claude 跑偏时轻松回滚；同时利用 GitHub Actions 集成让 Claude 自动处理拉取请求（PR）评论中的格式问题或函数重命名等事项。

### 主要用例（全文翻译）

**用自动接受模式快速原型化**
工程师通过开启"自动接受模式"（shift+tab）并搭建自主循环，让 Claude 写代码、跑测试、持续迭代，从而快速原型化。他们把不熟悉的抽象问题交给 Claude 自主完成，然后审查这个完成度约 80% 的方案，再接手做最后的打磨。团队强调要从干净的 git 状态开始并定期提交检查点，这样当 Claude 跑偏时就能轻松回退任何错误的更改。

**核心功能的同步编码**
对于触及应用业务逻辑的更关键的功能，团队与 Claude Code 同步协作，提供包含具体实现指令的详细提示词。他们实时监控过程以确保代码质量、风格指南合规和架构合理，同时让 Claude 承担重复性的编码工作。

**构建 Vim 模式**
他们最成功的异步项目之一是为 Claude Code 实现 Vim 按键绑定。他们让 Claude 构建整个功能（尽管它并非优先事项），最终实现中约 70% 来自 Claude 的自主工作，只需几轮迭代即可完成。

**测试生成与缺陷修复**
他们用 Claude Code 在实现功能后编写全面的测试，并处理拉取请求（PR）评审中发现的简单缺陷修复。他们还利用 GitHub Actions 集成，让 Claude 自动处理拉取请求（PR）评论中提到的格式问题或函数重命名等事项。

**代码库探索**
在不熟悉的代码库中工作（如 monorepo 或 API 侧）时，团队用 Claude Code 快速理解系统的运作方式。与其等 Slack 回复，他们直接向 Claude 提问以获得解释和代码引用，显著节省了上下文切换的时间。

### 团队影响（全文翻译）

- **更快实现功能**：成功实现了 Vim 模式等复杂功能，其中 70% 的代码由 Claude 自主编写。
- **提升开发速度**：可以快速原型化功能并迭代想法，而不会陷入实现细节的泥潭。
- **通过自动化测试提升代码质量**：Claude 生成全面测试并处理常规缺陷修复，在减少人工投入的同时保持高标准。
- **更好的代码库探索**：团队成员无需等待同事回复，即可快速理解 monorepo 中不熟悉的部分。

### Claude Code 团队的经验建议（全文翻译）

**创建自给自足的循环**
让 Claude 通过自动运行构建、测试和 lint 来验证自己的工作。这样 Claude 能更长时间地自主工作并发现自身错误——当你让 Claude 在写代码之前先生成测试时尤其有效。

**培养任务分类直觉**
学会区分适合异步完成的任务（外围功能、原型开发）与需要同步监督的任务（核心业务逻辑、关键修复）。产品边缘的抽象任务可以用"自动接受模式"处理，而核心功能需要更近的监督。

**形成清晰、详细的提示词**
当组件名称或功能相似时，务必在请求中做到极其具体。你的提示词越好、越详细，就越能信任 Claude 独立工作，而不会对代码库中错误的部分做出意外修改。

## 三、安全工程团队

**要点详述**：安全工程团队专注于软件开发生命周期安全、供应链安全和开发环境安全，他们大量使用 Claude Code 编写和调试代码。效果最显著的是复杂基础设施调试：处理事故时把堆栈跟踪和文档喂给 Claude Code，让它追踪代码库中的控制流，原本需要 10–15 分钟人工扫描代码才能理解的问题缩短到约 5 分钟。Terraform 代码评审方面，团队把 Terraform 计划粘贴进 Claude Code，直接问"这会做什么？我会后悔吗？"，形成更紧的反馈循环，让安全团队快速评审和批准基础设施变更，消除开发流程瓶颈。他们还有效推进了测试驱动开发：先让 Claude Code 生成伪代码，再引导它走 TDD 流程并定期介入纠偏，取代了过去"设计文档 → 粗糙代码 → 重构 → 放弃测试"的模式。值得一提的是，整个 monorepo 中 50% 的自定义斜杠命令实现都来自安全工程团队。

### 主要用例（全文翻译）

**复杂基础设施调试**
处理事故时，他们把堆栈跟踪和文档喂给 Claude Code，让它追踪代码库中的控制流。这显著缩短了生产问题的解决时间——通常需要 10-15 分钟人工代码扫描才能理解的问题，现在大约 5 分钟即可搞定。

**Terraform 代码评审与分析**
对于需要安全审批的基础设施变更，他们把 Terraform 计划复制到 Claude Code 中，询问"这会做什么？我会后悔吗？"这形成了更紧密的反馈循环，让安全团队更容易快速评审并批准基础设施变更，减少了开发流程中的瓶颈。

**文档综合与操作手册**
他们让 Claude Code 摄取多个文档来源，创建 Markdown 格式的操作手册（runbook）、故障排查指南和概述。这些精炼后的文档被用作调试真实问题时的上下文，比翻查完整知识库更高效。

**测试驱动开发工作流**
不再沿用过去"设计文档 → 粗糙代码 → 重构 → 放弃测试"的模式，他们现在让 Claude Code 先给出伪代码，引导它走测试驱动开发流程，并定期检查、在卡住时进行引导，最终产出更可靠、更可测试的代码。

**上下文切换与项目新人上手**
在为既有项目（如"dependant"——一个用于安全审批工作流的 Web 应用）贡献代码时，他们用 Claude Code 编写、评审并执行以 Markdown 形式存放在代码库中的规格说明，让有意义的贡献从数周缩短到数天之内。

### 团队影响（全文翻译）

- **缩短事故解决时间**：过去需要 10-15 分钟人工代码扫描的基础设施调试，现在只需约 5 分钟。
- **改善安全评审周期**：用于安全审批的 Terraform 代码评审快了很多，消除了开发者等待安全团队批准时的阻塞。
- **增强跨职能贡献**：团队成员几天内（而非数周的上下文积累）就能实质性参与项目。
- **更好的文档工作流**：从多个来源综合出的故障排查指南和操作手册让调试流程更高效。

### 安全工程团队的经验建议（全文翻译）

**大量使用自定义斜杠命令**
安全工程团队用了整个 monorepo 中 50% 的自定义斜杠命令实现。这些自定义命令简化了特定工作流，加快了重复任务的速度。

**让 Claude 先说**
他们不再针对代码片段提定向问题，而是告诉 Claude Code"边做边提交（commit your work as you go）"，让它带着定期检查点自主工作，从而得到更全面的解决方案。

**把它用在文档工作上**
除了编码，Claude Code 在综合文档和生成结构化输出方面也很出色。他们会提供写作样例和格式偏好，得到可以直接在 Slack、Google Docs 等工具中使用的文档，避免界面切换疲劳。

## 四、推理团队

**要点详述**：推理团队负责管理 Claude 读取提示词并生成响应时的记忆系统。团队中不少人没有机器学习背景，他们大量借助 Claude Code 弥补知识差距。典型收益：ML 概念研究时间减少 80%——过去要花一小时 Google 搜索加读文档的问题，现在 10-20 分钟解决；代码库理解从询问同事变为数秒内定位相关文件；单元测试自动生成（含遗漏的边界情况）；跨语言代码翻译——需要用 Rust 测试时无需先学 Rust，由 Claude 直接写出逻辑。此外还常用 Claude 直接询问 Kubernetes 命令语法（如"如何查看所有 Pod 或部署状态"），省去记忆复杂命令的负担。

### 主要用例（全文翻译）

**代码库理解与新人上手**
团队非常依赖 Claude Code 在加入复杂代码库时快速理解架构。他们不再手动搜索 GitHub 仓库，而是让 Claude 找出哪些文件调用了特定功能，几秒钟即可得到结果，无需询问同事或手动搜索。

**覆盖边界情况的单元测试生成**
写完核心功能后，他们让 Claude 编写全面的单元测试。Claude 会自动补上被遗漏的边界情况，在几分钟内完成通常需要大量脑力投入的工作，就像一个可以事后审查的编码助手。

**机器学习概念解释**
由于没有机器学习背景，团队成员依赖 Claude 解释模型相关的函数和设置。过去需要一小时 Google 搜索加阅读文档的工作，现在只需 10-20 分钟，研究时间减少了 80%。

**跨语言代码翻译**
在不同编程语言中测试功能时，他们说明想测试什么，Claude 就用所需的语言（如 Rust）写出逻辑，免去了仅为测试目的而学习新语言的需要。

**命令回忆与 Kubernetes 管理**
无需记住复杂的 Kubernetes 命令，他们直接向 Claude 询问正确语法，比如"如何获取所有 Pod 或部署状态"，即可获得基础设施工作所需的精确命令。

### 团队影响（全文翻译）

- **加速 ML 概念学习**：研究时间减少 80%——过去花一小时 Google 搜索，现在只需 10-20 分钟。
- **更快的代码库导航**：无需询问同事，数秒内即可找到相关文件并理解系统架构。
- **全面的测试覆盖**：Claude 自动生成带边界情况的单元测试，在保持代码质量的同时减轻脑力负担。
- **消除语言障碍**：无需学习 Rust 等不熟悉的语言，也能用它们实现功能。

### 推理团队的经验建议（全文翻译）

**先测试知识库功能**
试着用各种问题看看 Claude 能否比 Google 搜索回答得更快。如果它更快、更准确，它就是你工作流中宝贵的省时工具。

**从代码生成入手**
给 Claude 具体指令，让它编写逻辑，然后验证正确性。这有助于在使用它做更复杂任务之前，建立对工具能力的信任。

**用它写测试**
让 Claude 编写单元测试能显著减轻日常开发工作的压力。利用这一功能，无需花时间手动穷举所有测试用例，也能保持代码质量。

## 五、数据科学与可视化团队

**要点详述**：数据科学与机器学习工程团队需要复杂的可视化工具来理解模型性能，但构建这些工具通常需要掌握不熟悉的语言和框架。借助 Claude Code，他们在"对 JavaScript/TypeScript 知之甚少"的情况下构建了完整的 React 应用（例如 5000 行的 TypeScript 应用）来可视化 RL 模型性能和训练数据——之所以可行，是因为可视化应用上下文相对独立，不需要理解整个 monorepo，因此可以快速原型化。团队把 Claude Code 形容为"老虎机"式用法：先提交状态，让 Claude 自主运行 30 分钟，要么接受结果，要么推倒重来——因为推倒重来的成功率往往高于修复 Claude 的错误。另一个重要转变是从一次性 Jupyter notebook 转向可复用的 React 仪表盘：理解 Claude 的训练与评估表现是团队最重要的事之一，而"只看一个数字上涨无法获得足够信号"。

### 主要用例（全文翻译）

**构建 JavaScript/TypeScript 仪表盘应用**
尽管"对 JavaScript 和 TypeScript 知之甚少"，团队仍用 Claude Code 构建了完整的 React 应用，用于可视化 RL 模型性能和训练数据。他们让 Claude 从头编写整个应用，比如一个 5000 行的 TypeScript 应用，而自己无需理解代码。这一点至关重要，因为可视化应用的上下文相对独立，不需要理解整个 monorepo，从而可以快速原型化各种工具，在训练和评估期间理解模型性能。

**处理重复性重构任务**
面对合并冲突或"对编辑器宏来说太复杂、但又不足以启动大型开发工程"的半复杂文件重构时，他们把 Claude Code 当作"老虎机"使用——先提交（commit）当前状态，让 Claude 自主运行 30 分钟，然后要么接受方案，要么无效就推倒重来。

## 十、法务团队

**要点详述**：法务团队通过实验和学习 Anthropic 产品意愿发现了 Claude Code 的潜力。一位成员有一个私人用例：为因医疗诊断而语言困难的家人打造无障碍沟通工具——仅用一小时，就基于系统原生语音转文字创建了一个预测文本应用，它能建议回复并用语音库朗读出来，填补了言语治疗师推荐的现有无障碍工具的空白。部门内部，他们创建了原型"电话树"系统帮助成员对接 Anthropic 内部合适的律师，管理者还构建了 G Suite 应用来自动化每周团队汇报、跨产品追踪法务评审状态——律师只需点击按钮即可标记待评审项，而不再靠电子表格管理。工作方式上是"在 Claude.ai 规划、在 Claude Code 构建"的两步法，并且以视觉为先：大量使用截图展示想要的界面效果，基于视觉反馈迭代。作为产品律师，他们敏锐指出深度 MCP 集成的安全影响，并呼吁随着 AI 能力扩张应尽快建设合规工具。他们也强调要克服分享"玩具"原型的心理障碍——这些演示能激发其他人看到自己未曾考虑的可能性。

### 主要用例（全文翻译）

**为家人定制的无障碍方案**
团队成员为因医疗诊断而说话困难的家人构建了沟通助手。仅用一小时，他们就创建了一个基于原生语音转文字的预测文本应用，它可以建议回复内容并通过语音库朗读出来，填补了言语治疗师推荐的现有无障碍工具的空白。

**法务部门工作流自动化**
他们创建了原型"电话树"（phone tree）系统，帮助团队成员对接 Anthropic 内部合适的律师，展示了法务部门无需传统开发资源即可为常见任务构建自定义工具的可能性。

**团队协作工具**
管理者们构建了 G Suite 应用，自动化每周团队汇报、跨产品追踪法务评审状态，让律师通过简单的按钮点击即可快速标记需要评审的事项，而不是靠电子表格管理。

**用于方案验证的快速原型**
他们用 Claude Code 快速构建功能原型，拿给领域专家看（比如把无障碍工具展示给 UCSF 的专家）以验证想法、识别已有方案，再决定是否投入更多时间。

### 工作方式与影响（全文翻译）

**在 Claude.ai 规划，在 Claude Code 构建**
他们采用两步法：先用 Claude.ai 头脑风暴和规划，再转到 Claude Code 实现，并要求它放慢速度、一步一步地做，而不是一次性输出所有内容。

**视觉优先的方法**
他们经常用截图向 Claude Code 展示希望界面长什么样，然后基于视觉反馈迭代，而不是用文字描述功能。

**原型驱动的创新**
他们强调要克服分享"傻乎乎的"或"玩具"原型的心理障碍，因为这些演示能激发其他人看到他们未曾考虑过的可能性。

**安全与合规意识：MCP 集成的隐忧**
作为产品律师，他们立刻识别出深度 MCP 集成的安全影响，并指出随着 AI 工具访问更多敏感系统，保守的安全姿态会制造障碍。

**合规工具建设的优先级**
他们主张随着 AI 能力的扩展尽快建设合规工具，认识到创新与风险管理之间的平衡。

### 法务部的经验建议（全文翻译）

**先在 Claude.ai 中充分规划**
先用 Claude 的对话界面把整个想法打磨清楚，再转到 Claude Code。然后让 Claude 把所有内容总结成一份分步骤的提示词，用于实现。

**增量且可视化地工作**
让 Claude Code 放慢速度、一次实现一步，这样你可以逐段复制粘贴而不会手忙脚乱。大量使用截图来展示你想要的界面效果。

**即使不完美也分享原型**
克服藏起"玩具"项目或未完成工作的冲动——分享原型能帮助其他人看到可能性，并在通常不产生交集的部门之间激发创新。

## 结语

这份内部文档贯穿的核心结论是：Claude Code 的价值不仅限于工程师——从数据基础设施、安全工程、推理、RL 工程等核心工程团队，到数据科学、API、增长营销、产品设计乃至法务等非传统开发角色，都在用它自动化重复劳动、跨越技能鸿沟、加速新人上手。反复出现的最佳实践包括：把工作流、工具与期望写入详尽的 Claude.md 记忆文件；从干净的 git 状态出发并频繁提交检查点以便随时回滚；区分适合异步自主执行与需要同步监督的任务；让 Claude 自验证（跑构建、测试、lint）；先在 Claude.ai 规划、再在 Claude Code 分步实现；以及把复杂工作流拆分为专门化的子智能体。对于考虑引入 Claude Code 的组织，Anthropic 的经验表明：即便是没有编程经验的个人或小团队，也能借助它承担传统上需要专职工程资源的工作。
