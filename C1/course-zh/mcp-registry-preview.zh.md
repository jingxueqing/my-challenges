# MCP 注册中心正式亮相

今天，我们正式推出模型上下文协议（MCP）注册中心（MCP Registry）——一个面向公开可用 MCP 服务器的开放目录与 API，旨在提升其可发现性与落地实施。通过将服务器的分发与发现方式标准化，我们既扩大了 MCP 服务器的覆盖范围，也让客户端更容易接入。

MCP 注册中心现已在预览版（preview）中可用。开始使用的方法：

- 按照我们的指南《向 MCP 注册中心添加服务器》添加你的服务器（面向服务器维护者）
- 按照我们的指南《访问 MCP 注册中心数据》获取服务器数据（面向客户端维护者）

# MCP 服务器的唯一事实来源

2025 年 3 月，我们曾表示希望建设一个面向 MCP 生态的中央注册中心。今天我们宣布，https://registry.modelcontextprotocol.io 已作为官方 MCP 注册中心正式上线。作为 MCP 项目的一部分，MCP 注册中心以及一份父级 OpenAPI 规格说明均已开源——任何人都可以据此构建兼容的子注册中心（sub-registry）。

我们的目标是标准化服务器的分发与发现方式，提供一个可供子注册中心在其之上构建的主要唯一事实来源。这将扩大服务器的覆盖范围，并帮助客户端在整个 MCP 生态中更轻松地找到服务器。

## 公开与私有的子注册中心

在建设中央注册中心的过程中，对我们来说很重要的一点是，不去削弱社区和公司已经建成的现有注册中心。MCP 注册中心充当公开可用 MCP 服务器的主要唯一事实来源，而各组织可以基于自定义标准创建子注册中心。例如：

公开子注册中心：例如与每个 MCP 客户端绑定的、带有强烈主张色彩的"MCP 市场"，它们可以自由地对其从上游 MCP 注册中心摄取的数据进行增补和增强。每类 MCP 最终用户画像的需求各不相同，如何以带有主张色彩的方式服务好各自的最终用户，由各 MCP 客户端市场自行决定。

私有子注册中心：存在于对隐私和安全有严格要求的企业内部，而 MCP 注册中心为这些企业提供了可以在此之上构建的单一上游数据源。至少，我们的目标是与这些私有实现共享 API 模式（schema），使相关的 SDK 和工具可以在整个生态中共享。

在上述两种情形中，MCP 注册中心都是起点——它是 MCP 服务器维护者发布并维护其自报信息的集中位置，供下游使用者加工并交付给各自的最终用户。

## 社区驱动的内容治理机制

MCP 注册中心是由注册中心工作组维护的官方 MCP 项目，采用宽松许可证授权。社区成员可以提交 issue，标记违反 MCP 内容治理准则的服务器——例如包含垃圾信息、恶意代码或冒充正规服务的条目。注册中心维护者随后可以将这些条目列入黑名单，并追溯性地将其从公开访问中移除。

# 开始使用

开始使用的方法：

- 按照我们的指南《向 MCP 注册中心添加服务器》添加你的服务器（面向服务器维护者）
- 按照我们的指南《访问 MCP 注册中心数据》获取服务器数据（面向客户端维护者）

本次 MCP 注册中心预览版旨在帮助我们在正式发布（GA）之前改进用户体验，不提供数据持久性保证或其他任何担保。我们建议 MCP 使用者密切关注其发展动态，因为在注册中心正式发布之前可能会出现破坏性变更。

在注册中心持续开发的过程中，我们欢迎大家在 modelcontextprotocol/registry GitHub 仓库上提出反馈和贡献：讨论、Issue 和拉取请求（PR）都欢迎。
