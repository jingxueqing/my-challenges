# 拿来说明 02：术语一致性是怎么靠"表 + 校验"守住的

> 对应交付物：`pipeline/glossary.csv`（82 条）、`pipeline/check_quality.py` 的术语扫描
> 决策类型：质量决策——"82 条术语、31 篇并行翻译，怎么保证全文一个译法"

## 1. 原文（验收要点原文）

> "术语表 ≥ 50 条且全文一致（如 Vibe Coding / Scaffolding / Context Engineering 的译法统一）"

## 2. Prompt（术语块设计，经历一次关键迭代）

**v1（失败版）**：给每个翻译批次只写一句——
> "术语翻译请参考 pipeline/glossary.csv，保持全文一致。"

结果：并行批次各自发挥，CI/CD、Embedding 出现 4 处不一致——因为 11 个并行子代理**互相看不到对方的产出**，"参考一个文件"在无共享上下文的并行体系里形同虚设。

**v2（采纳版）**：把术语约束**内联**进每个任务，且只注入该批相关的高频条目：
> 术语必须遵守（内联，逐条给出）：
> Vibe Coding→氛围编程；Context Engineering→上下文工程；Context Rot→上下文腐烂；code review→代码评审；prompt injection→提示词注入；SAST→静态应用安全测试（SAST）；DAST→动态应用安全测试（DAST）……
> 产品名一律不译：Claude Code、Codex、Copilot、Devin、Cursor、Warp、Kubernetes、Semgrep、Graphite、Vercel。

## 3. 产出（校验脚本核心逻辑）

```python
# check_quality.py：原文出现过的术语，译文必须包含其统一译法
for en_t, zh_t in glossary:
    if re.search(r"(?<![A-Za-z])" + re.escape(en_t) + r"(?![A-Za-z])", en):
        base = zh_t.split("（")[0].split("/")[0].strip()
        if en_t in zh and base not in zh and not re.search(base, zh):
            bad.append(en_t)
```

## 4. 对比（三处真实的修正记录）

| 违规点 | 修复前（并行批次各自的译法） | 修复后（统一） |
|---|---|---|
| CI/CD | 有的写 "CI/CD 流水线"，有的写 "持续集成/持续交付流水线" | 首次出现 "持续集成/持续交付（CI/CD）"，其后可简称 |
| Embedding | 有的 "向量表示"，有的 "嵌入" | 全文统一 "嵌入"（嵌入模型/嵌入向量） |
| 术语表本身 | Embedding 词条推荐 "向量表示/嵌入" 二选一 | 词条改定为 "嵌入"——**术语表服从语料现实**，把模糊词条删掉 |

**拿来说明的点**：
1. "全文一致"在 AI 并行生产体系里，**靠 prompt 祈祷是守不住的，必须表（glossary）+ 扫（checker）双保险**；
2. 扫描器会误伤（如把缺口台账里的英文标题也算违规），需要人工复核每一处报告——**AI 扫全量，人判少量**；
3. 术语表是活文档：当推荐译法与语料现实冲突时，修正方向是改表，让表始终描述真实约定。
