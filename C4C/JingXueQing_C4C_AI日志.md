### 阶段 B：三学科求解器（6 轮，含重大返工）

**目标**：线代/ ODE / 物理。

#### B1 轮：第一版自测 5/6

写完直接跑，出现两个**严重错误**：

```
✅ P5: y'' + y = 0 → y(x) = 0❌ 应该 y = C₁sinx + C₂cosx
✅ P7: 牛顿第二定律 → a = 1/5 m/s²   ❌ 应该 a = 5 m/s²
```

**这两个都是"看起来正常"的错误答案**，最危险的那一类。

#### B2 轮：定位 B5 的根因（花了最久）

初版用 `re.search(r"y(\'\'\')?\s*=\s*([^\n;。]+)", text)` 抓方程，
对 `y'' + y = 0` 会匹配到**末尾的 `y = 0`**，于是把二阶方程当成 `y=0` 求解。

我先验证了 sympy 自己是对的：

```python
sp.dsolve(sp.Eq(sp.diff(y(x),x,2)+y(x), 0), y(x))
# → Eq(y(x), C1*sin(x) + C2*cos(x))    ← sympy 没错
```

说明错在我的**方程构造**。重写为：取 `$...$` 片段 → 按第一个顶层 `=` 切分
→ 整体移项 → 阶数由撇号数量决定。

修完：`y'' + y = 0` 正确。

#### B3 轮：修复后暴露"正确但残差不为零"

修好方程构造后，`y' + 2y = 0` 却给出 `y = C₁ - 2xy`。

我**没有**因为"能跑出结果"就接受，而是加了一个残差检验脚本手工验证：

```python
# 把 y = C1-2xy 解出来代回原方程
yexpr = C1/(1+2*x)
residual = simplify(diff(yexpr,x) + 2*yexpr)
# → 4*C_1*x/(2*x + 1)**2  ← 不为零！
```

**根因**：`_fix_implicit_mul` 与 `y→y(x)` 替换的**顺序**错了。
`2y` 里的 `y` 前面紧邻数字，`\b` 词边界不成立，y 没被替换，
sympify 把 `y` 当成"未定义的函数对象"，方程退化成 `Eq(2*y + Derivative(y(x),x), 0)`。

修复：**先展开隐式乘法，再替换 y**。

> **这是整个项目最重要的时刻**。
> `dsolve` 是可信的符号引擎，返回的解形式完美、步骤完整、排版正常——
> 但结果是错的。如果没有手工算残差，这个错误会**100% 流入最终 PDF**。
>
> 这一刻直接催生了后面的 `verify.py` 模块。

#### B4 轮：物理题的顺序猜测翻车

```
题面：一质量为 2 kg 的物体受合力 10 N，求加速度
初版：nums=[2,10] → F=2, m=10 → a = 2/10 = 0.2 m/s²   ❌
正确：F=10, m=2 → a = 5 m/s²                            ✅
```

这个错误**比B2 更隐蔽**：步骤完整、单位正确、量纲正确，只有数值全错。

> **AI 的失误**：我最初设计 `extract_quantities` 时用了
> "按出现顺序取数 + 单位反推"这种直觉做法。这在测试数据上碰巧能用，
> 一旦题目顺序变化就全错。**测试通过了，能力却是假的。**

改法：**标签锚定**——只有当数字旁能找到物理量名称才采用，
并显式校验"变量名↔单位"相容性（`h` 的单位是 m 但语义是高度而非距离 `r`；
`g` 的单位是 m/s² 但语义是重力加速度而非某物的加速度 `a`）。

#### B5 轮：路由顺序错误

第 11 题「**证明**可逆矩阵的特征值非零」因含"矩阵"被路由到符号引擎，
报出"未找到矩阵"这种驴唇不对马嘴的失败原因。

修正：证明类标记**优先于**关键词匹配。

#### B6 轮：特征多项式泄漏内部符号

```
输出：det(A - λI) = λ² + 2λλ - 4λλ + λ² - 4λ + 3   ← 冗余未合并
```

三次尝试：
1. 改用 `Symbol("__LAMBDA__")` → 渲染成 `\left(__LAMBDA^{}\right)^{2}`，**更糟**
2. 退回 `Symbol("lambda")` + `_clean_latex()` 替换 `_lambda` → 干净了，但仍有 `λλ`
3. 改用 `simplify(det(A - λI))` 替代 `charpoly()` → 得到 `(\lambda-3)(\lambda-1)`✅

> **教训**：`charpoly()` 会做变量重命名，展开后产生无法化简的冗余项。
> 换成直接 `det()` + `simplify()` + `factor()` 一步到位。
> 试错三次才明白——**AI 在符号计算上也需要"试错 → 观察 → 换策略"的循环**。

### 阶段 C：PDF 渲染（8 轮，全部靠目视检查）

**目标**：无 LaTeX 环境出 PDF。

#### C1-C2 轮：先跑测试，再目视

我先写了 `make_preview.py` 把结果导成 PNG，
**每一轮都实际看图**，而不是只看"测试通过"。

第一版 PDF：

```
✅ 测试 23/23 通过
❌ 但图上看：一行文字被拆成5 行、矩阵括号明显歪斜
```

**这就是目视检查的价值**：单元测试只能证明"结构对"，
证明不了"排版对"。这两种错误只有看图才能发现。

#### C3 轮：\le / \ge / \to 别名

```
ParseFatalException: Unknown symbol: \le
```

sympy 的 `latex()` 输出 `\le`，mathtext 只认 `\leq`。
加了 `_ALIASES` 映射表（同时覆盖 `\dfrac→\frac`、`\text→\mathrm` 等）。

#### C4 轮：中文静默丢字（隐蔽）

```
UserWarning: Glyph 32447 (C UNIFIED IDEOGRAPH-线) missing from font(s) STIX Two Text
```

**没有报错，只有一条 warning，然后汉字直接消失了。**
原因是 mathtext 用 STIX 数学字体，不含中文字形。

修正：含 CJK 的片段一律走普通文本 + 中文字体路径（`_fam()`）。

#### C5 轮：字宽单位不一致（我自己的设计失误）

现象：中文一行只放得下 6 个字，数学片段被甩到行右侧。

我先改了一版：把 `len(text)*fontsize/190` 换成按字符计宽。
结果**更糟**——一行只有 6 个汉字。

排查后发现是**单位不一致**：

```python
def _char_w(ch, fontsize): return fontsize/72*0.95   # ← 返回【英寸】
# 但 x 坐标是页宽比例（0~1）
if cur and cur_w + w > limit:   # limit = 1 - margin - x ≈ 0.836
```

0.836 英寸 ÷ 0.132 英寸/字 ≈ 6.3 个字。**正是我看到的现象。**

修正：`_char_w` 内部除以 `fig_w` 归一到图坐标。

> **这个 bug 值得记**：我"根据公式算出来的数字"看起来合理，
> 就没有怀疑单位。**量纲/单位错误在任何领域都是最难自查的一类 bug。**

#### C6 轮：源码顺序被打乱

```
输入：A = \begin{bmatrix}4&1\\2&3\end{bmatrix}
输出：矩阵 → A = → 求 A 的行列式      ← 语义完全乱
```

原因：原实现"先抽环境、再处理剩余文本"依次 append，环境总是排在前面。

修正：抽出环境时**原位替换为等长空格**（保持后续下标有效），
记录每个块的源码位置，最后统一排序。

#### C7 轮：分页估算 → 两遍法

初版用固定常数估算各类内容高度，出现：
- 「答案压到下一题标题上」
- 「空步骤占一行，导致序号 1,2,3,5 跳号」
- 「题号在上一页，解答在下一页」

改为**两遍法**：先在探针 figure 上**实测**每段高度，再贪心分页，
且以**整道题**为不可拆单位。

#### C8 轮：多次迭代后终版

连续 5 轮迭代后（每次看图 → 定位 → 修 → 再看图），达到可交付质量：
矩阵括号对齐、行内公式同行、序号连续、答案框清晰、验证徽章可见。

### 阶段 D：验证与测试（3 轮）

#### D1 轮：写验证模块时先想"能抓什么错"

我没有只写"残差验证"，而是列了一张表：**每类验证能抓什么错**，
然后逐一实现，并用**正例反例各半**的方式测试：

```
✅ 极限(正例)   ✅ 极限(反例：声称 2，实际 1)
✅ 特征对(正例) ✅ 特征对(反例：Av−λv = [-2,-2] ≠ 0)
✅ 逆矩阵(正例) ✅ 逆矩阵(反例：AA⁻¹ = [5,4;4,5] ≠ I)
✅ 标准正交(正)✅ 标准正交(反例)
```

→ **9/9 项行为符合预期**

#### D2 轮：目视复查发现 P4 结论错误（**最重要的一次**）

在写验证报告时，我决定**对每道题都做人工复核**——
结果在 P4（线性相关性）上发现程序答案是**错的**：

```
程序输出：线性无关     ❌
手算验证：v2 = 2·v1，且 det(A)=0 → 线性相关
```

**根因**：`find_matrix_rows()` 只返回**第一个** bmatrix。
题面给的是三个向量 v1, v2, v3，但函数只匹配到 v1（3×1），
于是 `rank=1`、`向量数=min(3,1)=1`，得出 `rank==向量数` → "无关"。

修复过程中还连带发现两个 bug：
1. `_all_text` 会把 text 与 math_expressions **重复拼接**，
   导致向量数从 3 变成 6（修完后仍错）
2. nullspace 组合的索引写错，`dot product (6,1),(3,1)` 维度不匹配

> **为什么这个 bug 特别有价值**：
>
> 1. 程序输出 `solved=True`、`验证 pass`、步骤完整、排版正常——
>    **所有自动化指标都显示"成功"**
> 2. 唯一发现它的方式，是我自己手算了一遍 det
>
> 这直接印证了项目的核心论点：**验证本身也需要被验证**。
> 我因此新增了两道防线：
> - 测试里加"结论断言"（不只是断言 `solved=True`，还断言答案关键词）
> - 新增线性相关性的验证项：判"相关"时必须给出非平凡零组合作为证据

修复后 P4 正确输出 `线性相关`，并附上可核对的见证组合：
`-2·v1 + 1·v2 + 0·v3 = 0`。

## 四、Prompt 使用方式

我没有用"一句话生成整个项目"的方式，而是**分阶段、带着测试推进**：

```
1. "读这个 starter kit，分析它的架构与局限，不要写代码"      → 得到隐式 LLM 层的判断
2. "设计一个 LLM 引擎，三后端，零 SDK 依赖"                    → 一次性成型的设计
3. "先写 40 项测试覆盖 JSON 容错与降级诚实性"                 → 测试先行
4. "跑测试，失败的全是什么问题"                                → 逐个定位修复
5. "扩展线性代数/ODE/物理，先写带负例的自测"                    → 立刻暴露 2 个错误答案
6. "这里有个 bug，输出看起来对但我怀疑不对，怎么验证"           → 促成残差检查
7. "把 PDF 导成 PNG，我要看"                                    → 目视检查
8. [看图] "这里明显不对，矩阵括号歪了"                          → 逐轮修
```

**第 8 步是关键**：我把"看图发现的问题"作为**具象反馈**给 AI，
而不是笼统说"排版不好"。具象反馈让修复更准。

## 五、被 AI 犯过的错（诚实记录）

| 序| AI 的错误 | 怎么发现的 | 根因 | 修复 |
|----|----------|-----------|------|------|
| 1 | 把 `2y` 的 y 漏替换，方程退化成 `Eq(2*y+...,0)` | **手工算残差** | 隐式乘法与y 替换顺序颠倒 | 调整顺序 + 加残差验证 |
| 2 | 物理题按数字顺序取数，得出 `a=0.2`（正确 5） | 与手算对照 | 用"出现顺序"猜语义 | 改为标签锚定 |
| 3 | `\frac12` 未补花括号，PDF 崩 | 跑测试 | mathtext 方言差异 | 加正则补花括号 |
| 4 | `charpoly()` 产生 `λλ` 冗余 | 看 PDF | charpoly 变量重命名 | 改用 `simplify(det())` |
