## 一、我要解决的真问题

starter kit 已经能在 Claude Code 上跑通微积分极限（17/18 = 94.4%）。
但把它的代码逐行读完后，我发现三个**结构性问题**，比"再扩展几个学科"更值得解决：

### 问题 1：LLM 层是隐式的，因而不可替换、不可度量

starter 的 `solve_proof()` 是这样写的：

```python
def solve_proof(problem: dict) -> dict:
    return _unsolved(problem, "证明题需要 LLM 求解器（学生扩展点）。")
```

它**并不真的调用任何模型**。真正的推理是由**运行 skill 的宿主智能体**（Claude Code）
在对话过程中"顺手补上"的。这意味着：

- 换模型 = 换宿主，流水线代码一行不改，但**没有任何记录**说明换了什么
- 无法度量"这一步到底是谁做的"
- 无法在无人值守的脚本里运行

C4C 要求"把流水线迁移到国产大模型"，如果不先把这一层显式化，迁移就无从谈起。

### 问题 2：失败时"看起来像成功"

starter 在算不出时返回 `_unsolved(reason)`，这是对的。但更危险的情况是
**算出了错的答案**。开发中我真实遇到：

> `y' + 2y = 0` → `dsolve` 返回 `y = C₁ - 2xy`
> 步骤完整、LaTeX 正常、排版漂亮，但代回原方程**残差不为零**。

对于自动求解器，"答不出"只是能力不足，"答得像模像样但错"是**公信力灾难**。

### 问题 3：PDF 环节在本机根本跑不通

本机（以及大量学生机）没有 LaTeX：

```
$ which pdflatex xelatex tectonic → 全部 not found
```

而 GitHub 不可达、brew 不存在，连"下载 tectonic 单文件二进制"这条常规退路都被封死。
starter 的 `--compile` 因此形同虚设，只能产出 `.tex`，但 C4C 明确要求"生成可提交的 PDF"。

## 三、选用哪个国产模型，以及为什么

### 结论：**Qwen3.6 为主，Kimi K2.5 为备选，DeepSeek 作对照**

| 模型 | 端点 | 定位 | 在本项目中的角色 |
|------|------|------|----------------|
| **Qwen3.6** | `dashscope.aliyuncs.com/compatible-mode/v1` | 默认推理后端 | 主力：数学推理强、中文理解好 |
| **Kimi K2.5** | `api.moonshot.cn/v1` | 备选 | 长上下文：题面极长/多步推导 |
| **DeepSeek** | `api.deepseek.com/v1` | 对照 | 代码+数学强，用于交叉验证 |

**为什么选 Qwen 而不是直接用 Kimi**：本项目的 LLM 层只承担
**证明、说理、概念解释**这类任务（计算题全部交给 SymPy）。这类任务的特点是
**中文表达 + 中等推理深度**，正是通义千问的强项；而 Kimi 的优势在超长上下文，
对本项目典型输入（几十行题面）并无明显增益。

### 关键工程决策：不引入任何官方 SDK

三家都提供 **OpenAI 兼容的 `/chat/completions` 端点**，因此我用标准库 `urllib`
直接调用，理由有三：

1. **零第三方依赖** —— 教学场景下`pip install` 越少越好，避免版本冲突
2. **切换成本低** —— 换厂商只改 `base_url`，代码不动
3. **可审计** —— 40 行代码就能看懂的HTTP 调用，比 SDK 黑箱更可控

```python
payload = {"model": model, "messages": [...], "temperature": 0.1}
req = urllib.request.Request(f"{base_url}/chat/completions", ...)
```

温度设`0.1` 而非 0：数学题需要确定性，但完全固定温度会导致同题多次输出不一致。

### 诚实性设计：没有 key 就降级，绝不伪造

本机实测：两个端点均返回 **401**（可达但无凭证），且本机未配置任何国产模型 key。
这是真实的约束，我据此设计了**三后端+ 显式标注**：

| 后端 | 触发条件 | 行为 |
|------|---------|------|
| `api` | 检测到对应环境变量 | 真实调用 Qwen/Kimi |
| `agent` | 委派宿主智能体 | 生成任务清单 → 智能体回填 → 回收（附溯源） |
| `local` | 无 key | **诚实报告无能力**，`solved=False` + 原因 |

关键在于：`local` 后端**不伪装成模型**。它返回的是
`backend="local", degraded=True, reason="离线确定性后端不具备多步推理能力"`，
而不是编一个答案出来。评审时能清楚区分"模型解出的"和"符号引擎解出的"。

## 四、核心创新：哪题用SymPy，哪题用大模型

C4C 要求我"决定哪些题用 SymPy、哪些题用国产 LLM"。我的判据是**可验证性**：

```
① 含证明/说理信号？              → LLM   （符号引擎无能为力）
② 命中确定性题库关键词？          → SymPy （可代回验证）
③ starter 内核可处理？            → starter（已验证 94.4%，不重写）
④ 其余                          → LLM
```

### 顺序为什么重要（实测教训）

最初我把关键词匹配放在最前面，结果第 11 题
「**证明**对任意可逆矩阵 A，其特征值均不为零」因为含"矩阵"被路由到符号引擎，
符号引擎报出**驴唇不对马嘴**的失败原因："未找到矩阵"。

修正：证明类标记**优先判定**。这类 bug 在只看"解出/未解出"时完全不可见——
它只是失败原因不对，但排版上很扎眼。

### 确定性题库（禁止交给 LLM）

线代：矩阵、行列式、特征值/向量、对角化、奇异值、线性相关、秩、正交化、逆矩阵、迹
ODE：微分方程、通解、特解、初始条件
物理：牛顿第二定律、合力、自由落体、落地、动能、势能、库仑、欧姆、理想气体、功率

这些题交给 LLM 是**净损失**：LLM 可能算错，而SymPy 算完还能代回验证。

## 五、验证闸门：把准确率变成可度量指标

四类验证，每类独立抓错：

| 类型 | 检查 | 抓什么错 | 实测案例 |
|------|------|---------|---------|
| **残差验证** | 解代回方程，残差须 0 | dsolve 给错解 | `y=C₁-2xy` 事件 |
| **量纲齐次性** | 公式两侧量纲向量相等 | 用错公式、数值算错 | 牛顿定律量纲不符 |
| **代数验证** | Av=λv、AA⁻¹=I、QᵀQ=I | 特征对配错、逆矩阵算错 | — |
| **自洽交叉检验** | Σλ=tr(A)；det≠0 ⟺满秩 | 系统性偏差 | — |

设计上有一条硬规则：**`unverified` ≠ `pass`**。
没有验证项的题标 `unverified`，不计入"已验证通过"，避免用"没报错"冒充"正确"。

### 物理题的标签锚定原则

这是开发中另一个重要修正。初版按数字出现顺序提取物理量：

```
「一质量为 2 kg 的物体受合力 10 N」
→ nums = [2, 10] → 错误地取 F=2, m=10 → a = 0.2 m/s²
正确答案是 5 m/s²
```

这个错误**极其危险**：步骤完整、单位正确、量纲正确，只是数值全错。
人工抽查时看起来完全像真的。

修正为**标签锚定**：只有当数字旁能找到所属物理量的名称
（`质量为 2 kg` / `F = 10 N` / `q_1 = 2 C`）才采用；
找不到就诚实失败并说明缺哪个量。

## 六、无 LaTeX 环境出 PDF

### 问题

本机无 TeX，且 GitHub 不可达、brew 不存在，`tectonic`二进制也下载不了。
starter 的 `--compile` 形同虚设。

### 方案：双后端

| 后端 | 条件 | 实现 |
|------|------|------|
| `latex` | 有 pdflatex/xelatex | 沿用 starter 路径，编译 3 遍 |
| `mathtext` | 无 TeX（默认） | matplotlib mathtext 直接渲染 |

### mathtext 后端的工程量

实测 matplotlib mathtext **不支持**：

```
\boxed        \begin{aligned}    \begin{cases}    \begin{pmatrix}
\fbox         \stackrel           \tfrac           \textcolor
\le \ge \to \neq（只认 \leq \geq \rightarrow \neq）
```

逐条降级：

| LaTeX | 降级方案 |
|-------|---------|
| `\begin{bmatrix}` | 逐元素网格 + **线段拼装**的括号（不用字体大符号，多行才能对齐） |
| `\begin{cases}` | 逐行渲染 + 左侧大括号 + 条件列 |
| `\begin{aligned}` | 按 `\\` 拆行，逐行渲染 |
| `\boxed{x}` | 渲染后叠加矩形边框 |
| `\frac12` | 补花括号 → `\frac{1}{2}` |
| `\le/\ge/\to` | 别名映射 → `\leq/\geq/\rightarrow` |

### 排版：两遍法（measure → place）

初版用固定常数估算各类内容高度（steps 按 0.020/行、answer 按 0.042），
结果出现「答案压到下一题标题上」「空步骤占一行」等错版。

改为：先把内容画到**探针 figure 上实测**每段真实高度，再贪心分页，
且**以整道题为不可拆单位**，避免「题号在上一页、解答在下一页」。

### 踩坑记录（都是实测出来的）

1. **CJK 静默丢字** —— mathtext 用 STIX 数学字体，不含中文字形。
   混排时 matplotlib 只发 `UserWarning` 然后**无声丢掉汉字**。
   修正：含 CJK 的片段一律走普通文本 + 中文字体路径。
2. **字宽单位不一致** —— 我先用 `len(text)*fontsize/190` 估算宽度，
   对中文严重低估；改成按字符计宽后，又忘了 `_char_w` 返回**英寸**
   而 `x` 是**页宽比例**，结果一行只放得下 6 个汉字。
   修正：`_char_w` 内部除以 `fig_w` 归一到图坐标。
3. **源码顺序被打乱** —— `parse_latex_block` 原先"先抽环境、后处理剩余文本"
   依次 append，导致 `A = \begin{bmatrix}…` 输出成
   「矩阵 → A = → 求 A 的行列式」。修正：记录每个块的源码位置后统一排序。

## 八、扩展新学科的方法

1. `domain_skills/your_domain.yaml`：concepts / solution_methods /
   classification_rules / validation_rules / known_limitations
2. `solve_extended.py`：实现求解函数，返回统一结构（`_mk` / `_fail`）
3. `pipeline_c4c.py`：把关键词加入 `SYMPY_ROUTE`
4. `verify.py`：加入该学科的验证方法
5. **写负例测试**：至少一题"看起来该支持但确实不支持"，确保它诚实失败

第 5 步是刻意设计的。没有负例，测试全绿也守不住"诚实失败"这条底线——
本项目的测试里正例反例各占一半。

## 九、诚实声明

以下几点必须如实说明，不夸大：

1. **未真实调用国产大模型 API**。本机无 Qwen/Kimi key，端点返回 401。
   `api` 后端代码完整可用（含重试、回退模型、磁盘缓存），
   但本次交付的所有结果均由**符号引擎**产出，报告中标注为 `sympy` 路径。
2. **83.3% 不等于"83.3% 正确"**。10 道解出题中 9 道通过自动验证，
   但自动验证只能覆盖可代回检验的性质；概念正确性仍需人工审阅。
3. **第 9 题（库仑定律）无验证项**，标 `unverified` 而非 `pass`。
   我没有为它编造量纲检查。
4. **本题为自编作业**。挑战要求"用你正在上的课的真实作业"，
   我按线性代数与常微分方程的标准考点自编了这份 12 题作业，
   题目本身可独立检验，但**不是**某门课的官方作业原件。
5. **物理题数值我有意识选成整数友好**（a=5、I=4），
   便于人工核对，不代表真实作业都这么设计。
