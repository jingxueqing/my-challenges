## 3. Prompt 是怎么一步步变好的

**阶段一（需求层）**：初始需求只有一句"按挑战要求完成挑战内容"+ 资料包路径。
我补的关键约束是**评分对齐**——不是"做一个技能"，而是"做一个**会被反复使用**的技能，
因为 C4 第一条评分就是被使用次数"。这一条决定了后面所有取舍：
选"每个挑战都要交的 AI 日志"做主题，而不是选一个炫技但只用一次的方向。

**阶段二（自测层）**：这一阶段的 prompt 全部是"**输出摆在这儿，哪里不对**"型，
比阶段一有效得多。典型例子：

> 修前：`prompt 优化链：0 条`（我没说怎么改，只说"不对"）
> 修后：`相似度为 0 是因为中文按单字切分没有重合，改成二元组 + 阈值下限 0.06`
> → 一条都没改出来 → 我直接指出根因（中文分词粒度），一次修好，输出 5 条。

**质变点**：从"让它自己找 bug"改成"**我先读输出、定位根因、再让它改**"。
前者两轮没结果，后者一轮到位。这个教训我写进了 AAR，也写进了技能的第 5 节
（"报错时自己先做一次最小验证再下判断"）。

## 4. 失败与返工（6 个真 bug，全部修掉）

| # | 现象 | 根因 | 怎么修的 |
|---|---|---|---|
| ① | 7 轮对话被记成 9 轮，时间线出现 "date,region,amount…" | Claude Code 的 `tool_result` 事件也是 `role=user`，被当成"人说话" | 加 `is_tool_result` 标记：并入当前轮、只贡献错误证据，不计入轮次和用户字数 |
| ② | prompt 优化链 = 0 条 | 中文按单字分词，相邻两句几乎没有重合单字，Jaccard ≈ 0 | 中文改字符二元组 + 英文按词；判定改为"迭代信号 OR 相似度区间"；新增"渐进改写/追加新要求"分类 |
| ③ | `forge.py` 里一处非法表达式（嵌套引号 + 冗余三元） | 我起草时的残留，Python 语法错误 | 改成字符串拼接写法 |
| ④ | `AttributeError: 'str' object has no attribute 'get'` | yaml 里 `red_flags` 是**映射**，我却按列表迭代，拿到的是 key 字符串 | 兼容 dict / list 两种写法，非 dict 跳过 |
| ⑤ | 22 处占位符没填，体检仍然给 85 分 | 我把占位符只当"提醒"，没做成硬约束——**这是我的设计误判** | 每处扣 1 分（上限 20），并在报告里单列待办清单 |
| ⑥ | 失败节显示的是 AI 的话，不是报错原文 | 优先取了 assistant 文本 | 改为优先取 `errors[0]`（真实 tool_result 报错） |

**其余 4 处打磨**：时间线表格空行 → 逐轮判断列表；相似度列 → 判定列（"渐进改写/追加新要求"）；
新增"新增关键词"只保留英文标识符（中文二元组不可读）；补齐 `references/input_formats.md` 与 `run_all.sh`。

## 5. 我做了什么（AI 没做的部分）

1. **选题判断**：在 4 个候选方向（提交打包器 / 技能生成器 / 文档翻译流水线 / AI 日志）里选了 AI 日志，
   判断依据是"**每个挑战都要交 → 使用频次最高 → 正对 C4 第一条评分标准**"。这个判断 AI 给不了。
2. **定设计原则**："事实归脚本、叙事归人"。这是整个技能的地基——
   如果让 LLM 连轮次和工具数一起编，这个技能就变成了"帮你造假的工具"，价值为负。
3. **评分对齐**：把 rubric 的 5 个维度拆成 yaml 里的 signals + keywords，
   让体检分数和真实评分口径对得上，而不是自嗨打分。
4. **构造测试夹具**：`demo_session.jsonl` 是我按真实 Claude Code 结构手写的 7 轮会话，
   刻意安排了 2 次报错、5 次迭代、1 次"人自己动手"——这样体检的每一条判定都能被验证到。
5. **决定硬约束**：占位符扣分 + 退出码非 0。这是我看到 85 分那个"虚高"结果后做的判断——
   **没有牙齿的检查等于没有检查**。
6. **验收**：跑通 `run_all.sh`、解压 `.skill` 到干净目录重跑、验证 80→100 的分数变化。
7. **写四份交付文档**（说明 / 教学 / 本日志 / demo），并主动声明样例是构造夹具而非真实会话。
