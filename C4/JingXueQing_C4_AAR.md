## 4. 失败经验（评分最看重的一节）

### 4.1 设计误判：把占位符当"提醒"，结果体检没有牙齿
第一版体检给一份 22 处占位符全空的日志打了 **85 分**。
我当时的假设是"列出来提醒一下就行"——**这是错的**：一份空话连篇的日志拿 85 分，
等于告诉用户"不用改也能交"。改成每处扣 1 分（上限 20）+ 退出码非 0 之后，
才形成"补写 → 复检 → 分数上涨"的真正闭环。**教训：检查工具没有惩罚机制，就等于没有检查。**

### 4.2 中文分词粒度搞错，导致核心指标恒为 0
"prompt 优化链"一开始输出 0 条。我第一反应是调阈值，调了两轮没用；
后来才定位到根因：**中文按单字切分，相邻两句几乎没有重合单字**，Jaccard 相似度算出来≈0。
改成字符二元组后一次修好（0 → 5 条）。
**教训：指标异常时，先怀疑度量方法本身，而不是先调参数。**

### 4.3 工具结果被当成人说话，轮次虚高
Claude Code 的 `tool_result` 事件也是 `role=user`，被计成"我发言"，7 轮记成 9 轮，
时间线里出现 "date,region,amount…" 这种不像人话的行。加 `is_tool_result` 标记并入当前轮解决。
**教训：解析真实日志时，"结构上属于谁"和"语义上是谁说的"不是一回事。**

### 4.4 yaml 类型假设错误导致脚本崩溃
`AttributeError: 'str' object has no attribute 'get'` —— 我把 `red_flags` 当成列表遍历，
实际它是映射，拿到的是 key 字符串。改成兼容 dict / list 两种写法。
**教训：配置文件驱动的代码，输入类型必须做兼容，不能只按自己写的那一种格式假设。**

### 4.5 demo 图里我把扣分摊进了维度分——是数据失真，自己发现并改掉
渲染体检闭环图时，为了让"+20 分"说得通，我把「产物完整性」写成 5.0 → 25.0。
**这不是真实输出**（真实数据是三个维度都满分、扣分 −20 单列）。
我回看时发现了，重画成"扣分单列"。
**教训：做演示材料时最容易发生的造假，是"为了让图好看而调整数字"。这和本技能反对的"编造日志"是同一类错误。**

## 5. 做对了什么（可复用）

1. **选题先对齐评分标准**：C4 第一条是"被使用次数"，所以我选了「每个挑战都要交的 AI 日志」当主题，
   而不是一个炫技但只用一次的方向。**先读 rubric 再选题，比先想功能再凑理由有效得多。**
2. **事实 / 叙事 / 评分三层分离**：事实交给脚本（不可伪造），叙事留占位（人必须自己写），评分走 yaml（换标准不改代码）。
3. **用退出码把检查变成关卡**：`health_check.py` 退出码非 0 就"不许交"，比任何口头提醒都管用。
4. **双评分档案**：全套 C4 标准 + 只评日志的精简档案，避免用错标准吓到自己。
5. **诚实标注证据来源**：demo 输入是构造夹具、AI 日志是回溯撰写，都在文档里写明了。
