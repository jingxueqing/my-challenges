> 目标：**你看完这篇，能在 5 分钟内给自己生成一份 90+ 分的 AI 日志**，并且知道怎么教下一个人。

## 0. 先建立正确的心智模型（1 分钟）

这个技能只有一句话的核心：

```
脚本负责「事实」，你负责「判断」，脚本负责「打分」。
```

所以你的工作量其实很小——**只是把占位符补上**。别想着从头写日志，那是脚本的活。

```
原始记录 ──extract_trace──▶ trace.json ──forge──▶ 日志+AAR骨架 ──你补写──▶ 成品
                                                                    │
                                                              health_check
                                                                    ▼
                                                          分数 / 红旗 / 待补清单
```

## 1. 五分钟上手

### 1.1 安装

```bash
tar -xzf JingXueQing_C4_ai-log-forge.skill -C 你的skills目录
# 或者不解包也行，直接用 ai-log-forge/ 源码目录跑脚本
```

**不需要 pip install 任何东西。** 只依赖 Python 3 标准库。

### 1.2 找到你的 AI 记录（三种情况，对号入座）

| 你是哪种用户 | 记录在哪 | 命令 |
|---|---|---|
| **Claude Code 命令行用户** | `~/.claude/projects/*/*.jsonl` | `ls -t ~/.claude/projects/*/*.jsonl \| head -5` |
| **ChatGPT / Claude 网页版** | 导出成 `.json` 或 `.md` | 设置 → 数据控制 → 导出数据 |
| **什么都没有** | —— | 直接走访谈模式（见 1.5） |

### 1.3 三条命令

```bash
PY=python3   # Windows 换成 python

# ① 抽证据
$PY ai-log-forge/scripts/extract_trace.py -i 你的记录.jsonl -o trace.json --markdown

# ② 出文档
$PY ai-log-forge/scripts/forge.py -t trace.json -n 你的名字 -c C4 --title "任务标题" -o .

# ③ 体检
$PY ai-log-forge/scripts/health_check.py -f 你的名字_C4_AI日志.md 你的名字_C4_AAR.md \
    -t trace.json -p ai-log-forge/references/rubric_ai_log.yaml -o 体检报告.md
```

第①步加了 `--markdown` 会打印轮次摘要——**先扫一眼确认抽对了**，
抽错文件后面全白干。

### 1.4 装了技能之后：说人话就行

> "帮我写这次作业的 AI 日志，会话文件在 ~/.claude/projects/x/y.jsonl，我是 ZhangSan，挑战 C4"

AI 会自动跑完三步，最后把体检分数报给你，并主动帮你补写占位符（**但你必须核对**——
它不知道你当时为什么那么决策）。

### 1.5 没有记录的兜底：访谈模式

```bash
$PY ai-log-forge/scripts/forge.py --interview -n 你的名字 -c C4 -o .
```

会生成一份 8 问提纲。**回答完把答案丢给 AI**，说"按访谈生成日志"即可。

关键在第 5、6 问（哪里失败了 / 你怎么修的）——**必须写**，不写就是"没有失败经验"，
复盘质量维度直接掉到 10 分档。

## 2. 常见坑 TOP 8（都是实测踩出来的）

### 坑 1：轮次数虚高，时间线里混进了工具输出 ❗最常见

**现象**：明明只发了 5 句话，脚本说 9 轮，时间线里出现 "date,region,amount…" 这种行。
**原因**：老版本把 Claude Code 的 `tool_result` 事件也算成"你说话"。
**现状**：**已修复**（v1，pure tool_result 现在会并入当前轮，只贡献错误证据）。
**自检**：看时间线里有没有不像人话的行，有就是中招了——升级到本版本。

### 坑 2：prompt 优化链 = 0 条

**现象**：明明改了好几轮，脚本说 0 条。
**原因**：相邻两轮的话题跳跃太大（比如第一轮"写脚本"、第二轮"修复报错"），
字面上几乎没有重合词，相似度算出来接近 0。
**解决**：不用管脚本判定，自己在第 3 节手动补一句"我是怎么一步步改的"——
体检只认"有没有写"，不认脚本给了几条。

### 坑 3：纯文本记录被当成 1 轮

**现象**：粘了一大段对话，结果只有 1 轮。
**原因**：没有说话人标记，整段被当成同一个人在说话。
**解决**：每行开头加上标记，支持这些写法（中英文冒号都行）：

```markdown
我：第一句          User: 第一句        Human: 第一句
AI：回复            Assistant: 回复     Claude: 回复     模型：回复
```

### 坑 4：用错了评分档案，看到一堆"缺失"吓一跳

**现象**：只检查一份 AI 日志，报告却说"技能质量 16.7/25、可教性 13.3/20"。
**原因**：默认档案是 **C4 全套 5 维度**（含技能说明文档才需要的维度）。
**解决**：只评日志就用精简档案
`-p ai-log-forge/references/rubric_ai_log.yaml`（AI使用质量 30 / 复盘质量 45 / 产物完整性 25）。

### 坑 5：文件名里的 "demo" 让体检误判

**现象**：日志里没写演示，却显示"有演示"命中。
**原因**：体检是全文关键词匹配，文件名 `Demo_C4_AI日志.md` 里的 Demo 也算命中。
**影响**：会让分数虚高一点点。想要真实分数就把文件名换成自己的名字。
（这是关键词匹配的固有局限，我保留它，是因为"宁可宽松提示，也不要漏判"。）

### 坑 6：占位符没补完就交

**现象**：分数 80，报告底部列了 22 条待办。
**原因**：`<!-- LLM-FILL -->` 每处扣 1 分（上限 20）。
**解决**：这是**性价比最高的提分动作**——补完就从 80 → 100（实测）。

### 坑 7：ChatGPT 导出的 HTML 解析不出来

**原因**：HTML 里是 JS 内嵌 JSON，结构不固定。
**解决**：重新导出成 **Markdown 或 JSON**，别用 HTML。

### 坑 8：只有 1-2 轮记录，硬着头皮交

**现象**：体检直接触发「一句话指令直接提交、无迭代」红旗，**该维度封顶 5 分**。
**解决**：三选一——
① 找到更完整的会话文件再跑；
② 走访谈模式把过程补回来；
③ 如果确实是一次成型，**如实写**并补一节"为什么这次不需要迭代"（比编造诚实得多）。

## 3. 优化技巧（从 80 分到 100 分，按性价比排序）

| 优先级 | 动作 | 收益 |
|---|---|---|
| **P0** | 补完所有 `<!-- LLM-FILL -->` 占位符 | 每处 1 分，实测 +20 |
| **P0** | 写「失败与返工」那一节（≥1 条真实踩坑） | 解锁复盘质量最大头 |
| **P1** | 体检时带上 `-t trace.json` | 用硬证据判定，比关键词准 |
| **P1** | 逐轮时间线都写一句"我的判断" | 「人机分工清晰」信号 |
| **P2** | 产物验证写具体命令 + 结果（`pytest -q → 3 passed`） | 「可运行」「有复现说明」 |
| **P2** | AAR 的差距表 ≥3 行、改进方案写 P0/P1/P2 | 「具体问题分析」「有改进方案」 |
| **P3** | 把体检分数记进下一份日志的迭代时间线 | 证明你在持续进步 |

### 3.1 让 AI 帮你补写占位符的 prompt（复制即用）

```
请补写 <文件> 里所有 <!-- LLM-FILL: ... --> 标记的内容。
规则：
1. 严格按每个标记括号里的提示写，不要改其他任何内容；
2. "我的判断"要写具体动作（改了哪一行、否掉了什么方案），不许写"AI 给出了建议"；
3. 失败经验必须写清：为什么会错 + 我当时误判了什么 + 下次怎么提前发现；
4. 不知道的事实就写"待我确认"，不要编造。
补完告诉我：一共补了几处，还有几处需要我亲自确认。
```

**补完必须自己读一遍。** AI 写不出来"你当时为什么否定那个方案"，这段只能你自己写——
而这段恰恰是评审给分的地方。

### 3.2 反过来用：用体检结果改进你下次用 AI 的方式

体检报告里的「失败/返工轮次」其实是**你指挥 AI 的能力体检**：
- 返工多 = 你的首轮指令没给验收标准；
- 迭代多但都是"追加要求" = 你没一次性说清需求；
- 工具调用为 0 = 你只让 AI 聊天，没让它动手。

## 4. 定制你自己的评分标准（30 秒）

复制一份 yaml，改 `signal_keywords` 里的关键词即可，**代码一行都不用动**：

```bash
cp ai-log-forge/references/rubric_ai_log.yaml 我的标准.yaml
# 改 signals 和 signal_keywords
python3 ai-log-forge/scripts/health_check.py -f x.md -p 我的标准.yaml
```

写 yaml 时注意（内置迷你解析器，只支持简单结构）：
- 只用空格缩进，不要用 Tab
- 列表写成行内形式 `[a, b, c]`
- 不要在列表项里再嵌字典

## 6. FAQ

**Q：我的对话记录会被上传到哪里吗？**
A：不会。三个脚本全部本地运行，无网络请求，无外部依赖。

**Q：一定要 Claude Code 吗？我用 ChatGPT / 通义 / Kimi 可以吗？**
A：可以。把它们导出成 `.md` 或 `.txt`，按 `我:` / `AI:` 标记粘贴就行。

**Q：生成的日志能直接交吗？**
A：补完占位符、体检退出码为 0 之后可以。建议再自己读一遍"我做了什么"那节——
那是唯一能体现你是人的地方。

**Q：能不能一次处理多个会话文件？**
A：能。`--input` 指向一个目录，脚本会递归扫描 `.jsonl/.json/.md/.txt` 并按修改时间合并。

**Q：分数只有 60 怎么办？**
A：按体检报告最后一节「改进建议（按性价比排序）」从上往下做。
通常补完占位符 + 写一条失败经验就能到 90+。
