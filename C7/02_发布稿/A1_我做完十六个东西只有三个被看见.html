前几天我打开桌面，数了一下那个叫「挑战的产物」的文件夹。

16 个条目——15 个成品目录，加 1 个打包 zip。

然后我问了自己一个问题：

这些东西里，有几个是别人能点开看的？

答案让我在椅子上坐了半分钟——

三个。

一篇公众号文章，一个 GitHub 仓库，一个应用链接。

其余全部躺在我的硬盘里，格式完整、测试通过、AAR 写得挺认真，但世界上没有任何人知道它们存在。

一、我一直以为「做完」就是终点

先说说我是怎么走到这一步的。

今年我开始做一套挑战，从翻译一门斯坦福课程开始，一路做到写论文、做技能、开源仓库、上线 Web 应用。每做完一个，我都会给自己打个分，写一份 AAR，把踩过的坑一条条记下来。

评分机制让我形成了一个习惯：只要交付物齐全、测试全绿、复盘写完，这个挑战就结束了。

我甚至很擅长这件事。比如一个公众号排版技能，我把 380 行的官方 starter 改成 1419 行，写了 26 个测试、128 条断言，把 12 个缺陷一条条锁死。

再比如一个网页版的写作工具，3080 行代码、零依赖、首屏 0.94 秒，我自己跑通了 8 步流程，还录了一版 40 秒的演示。

这些数字我很得意。

但我从来没算过另一个数字：看过它们的人有几个。

⚠️ 注意　一个不太好受的对照

我把「测试通过 128 条断言」写进了复盘，却把「发布后 0 条评论」这件事，一个字都没写。

二、真正刺痛我的，是那篇文章的评论区

上个月，我把上面那个排版技能的复盘写成文章，发在了自己的公众号上。

那是我第一次把「过程」写出来发出去。发完当天我很兴奋，隔一会儿刷一下后台。

第二天，热度过去。

第三天，我打开公众号后台，想了想，关掉了。

然后我一个月没再更新。

后来我回头看，才发现问题不在阅读量——第一篇文章本来就不会有多少人看。问题在于：

  • 有人在评论区问了一个具体问题，我过了三天才回，那时候他大概已经走了；
  • 文章里我写「bug 清单放在仓库的 tests/fixtures 里，直接复制就能跑」，但我没给出仓库地址；
  • 结尾我留了互动问题，但我自己再也没回去看过那些回答。

这三件事，一件都不难。我只是没做。

因为它们不在我的「挑战清单」里。

⭐ 重点　我当时的认知

做出来 = 完成。发出去 = 顺便。

现在我知道这个认知错得有多离谱。

三、三个我自己撞出来的结论

这一节是这篇文章里我最想让你带走的部分。

结论一：没有入口的作品，等于没做

我做过一个完全离线的本地地图 Agent，跑在自己那台 8GB 内存的 MacBook Air 上，77 个离线单测全绿。

你说这件事厉害吗？可能还行。

但如果你问我「给我看看」，我只能说：「在我电脑上，我给你演示一下。」

这就是「没有入口」。

现在我给每个作品都配了一个能点开的门：

我做的事 现在的入口 之前是什么
排版技能 一篇文章 + 一套 SOP 一个文件夹
地图 Agent 公开仓库 + 版本 tag 一个 .zip
写作工具 打开就能用的网址 本地 index.html

入口不需要完美，它需要存在。

那个地图 Agent 的 README 我写得不算漂亮，但它至少让一个陌生人能在 30 秒内知道这是什么东西、怎么跑起来。

结论二：我把最值钱的东西，写给了自己看

这是我最亏的一件事。

每做完一个挑战，我都会写一份 AAR，把失败一条条列出来，还标上根因和代价。比如：

  • 把「网络不通」和「没有凭据」当成同一件事，导致一件五分钟能做完的事拖了一天；
  • 默认模型取列表第一个，结果它挂住不返回，界面永远停在「正在找角度」，不报错也不超时；
  • 录屏脚本里 recording = true 写在循环启动之后，一帧都没录到。

这些是全网最有价值的内容。 因为别人的教程里只有成功路径，而失败清单只有自己踩过才有。

但我把它们写进了只给自己看的 AAR.md。

那天我突然意识到：我不是没有内容，我是把内容锁进了保险柜，然后把钥匙扔了。

结论三：发布不是终点，是起点

我原来的流程是：写完 → 排版 → 发布 → 结束。

真实情况应该是：写完 → 排版 → 发布 → 看谁来了、谁问了什么、下一篇写什么 → 再发布。

少掉的这半段，本质上就是「发布即弃」。

🔥 踩坑　一个具体的数字

我的公众号从第一篇到第二篇，隔了将近一个月。 不是因为我没东西可写——是我桌上躺着十几个可以写的东西。

四、我决定怎么改：把作品排成一张选题表

认清问题之后，我做了一件很朴素的事：把已有的作品，排成一张可以连续更新的选题表。

不是重新创作，是把已经存在的东西，按「读者需要什么」重新切一遍。

选题 素材 读者能带走
① 我做完 16 个交付物，只有 3 个被看见过 就是这篇 自查清单
② 我把公众号写作拆成 7 步，附全部提示词 写作流程 可直接用的提示词
③ 380 行改到 1419 行：12 个坑的完整清单 排版技能 探针文档
④ 8GB 笔记本上跑本地大模型 Agent 地图 Agent 能跑的仓库
⑤ 一个人做完 31 篇论文翻译，质量怎么保证 课程翻译 翻译流水线
⑥ 不会写代码，怎么上线一个能用的网页 写作工具 从 0 到上线

六期，全部来自我已经做完的东西。素材成本是零，只有表达成本。

💡 实践　这张表怎么用

如果你也在做类似的事，可以照这个格式填一遍：左边写你做过什么，右边写「别人能从中拿走什么」。 填不满的那几行，就是你下一篇该补的功课。

五、三条给同类人的建议

如果你和我一样，习惯把东西做完就收起来，这三条可能对你有用。

⭐ 重点　建议一：给每个作品配一个 30 秒入口

不要求漂亮，要求陌生人点开就知道这是什么、怎么用。 一个 GitHub 仓库、一个能打开的网址、一篇说明文章，都算。

⭐ 重点　建议二：把你的 AAR 翻出来读一遍

那些你写给自己看的失败记录，按「别人也会踩」的标准重排一遍，就是现成的文章。 你不需要新的经历，你需要新的读者视角。

⭐ 重点　建议三：发布后 24 小时，回一次评论区

这是我给自己定的规矩。不是为了数据，是因为那个愿意打一行字问你的人，是整个互联网上最稀缺的人。

最后

写这篇文章之前，我犹豫了很久。

因为它的主题是「我做得不够好」，而不是「我做成了什么」。

但我后来想明白了：在 AI 时代，会做东西的人很多，能讲清楚的人很少。

我桌面上那十几个文件夹，每一个都花了实打实的时间。它们不该只活在我的硬盘里。

这篇文章是第一个。
